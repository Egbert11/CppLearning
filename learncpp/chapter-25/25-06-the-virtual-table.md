# 25.6 The virtual table

> 原文：https://www.learncpp.com/cpp-tutorial/the-virtual-table/

## 核心概念

- **非虚调用在编译期解析**：由于调用不是虚函数，编译器依据对象/引用的静态类型决定运行哪个函数。
- **虚调用在运行期解析**：编译器必须依赖*动态类型*，而动态类型要到程序运行时才已知，因此对派生覆写的解析只在运行期发生。
- **标准不强制实现方式**：如何实现虚函数由各实现自行决定。
- **典型实现是虚表**：各实现通常采用一种晚期绑定形式，即虚表（virtual table）。
- **虚表定义**：它是一种"用于以动态/晚期绑定方式解析函数调用的查找表"。
- **别名**：可称为 "vtable"、"virtual function table"、"virtual method table" 或 "dispatch table"。
- **动态派发（dynamic dispatch）**：C++ 中虚函数解析有时被称为动态派发。
- **Nomenclature 告示（区分三术语）**：早期绑定/静态派发是直接调用的重载解析；晚期绑定是间接调用的解析；动态派发是虚函数覆写的解析。
- **可选阅读**：了解虚表如何工作并非*使用*虚函数所必需，因此这部分内容可当作选读。
- **每个多态类都有一张表**：任何使用虚函数（或派生自这样的类）的类都有对应的虚表，它是编译器在编译期构建的静态数组。
- **每个虚函数一个表项**：表中为"该类对象可调用的每个虚函数"保留一个条目。
- **每个表项是一个函数指针**：指向该类可访问的"最派生"函数。
- **会加入一个隐藏指针成员**：编译器在基类中插入一个隐藏指针成员，记为 `*__vptr`。
- **`*__vptr` 自动设置**：创建对象时，其 `__vptr` 指向该类的虚表。
- **它是真正的指针成员（不同于 `this`）**：`this` 实际上是用于解析自引用的函数参数，而 `__vptr` 是实实在在的成员——因此每个对象都增大一个指针的大小。
- **指针的继承**：因为 `__vptr` 是基类的成员，派生类会继承它——这正是"通过基类指针/引用也能工作"的原因。
- **示例设定：三个类、三张表**：对于 `Base`、`D1`（覆写 `function1`）、`D2`（覆写 `function2`），编译器创建三张独立的虚表。
- **表中填入"最派生可调用函数"**：对 `Base` 对象只能访问 `Base` 的成员，故两个表项都指向 `Base` 的函数。
- **`D1` 的表**：`function1` 指向 `D1::function1()`（更派生），`function2` 仍指向 `Base::function2()`。
- **`D2` 的表**：恰好相反——`function1` 指向 `Base::function1()`，`function2` 指向 `D2::function2()`。
- **基类指针指向派生对象**：`Base*` 只指向 `D1` 对象的 `Base` 部分——但由于 `__vptr` 就在这部分里，指针仍能到达 `D1` 的表。
- **调用解析顺序**：程序 (a) 注意到该函数是虚函数，(b) 顺着 `dPtr->__vptr` 找到虚表，(c) 查找表项——此例中即选中 `D1::function1()`。
- **并非总是选派生版本**：若指针实际指向一个 `Base` 对象，该对象的 `__vptr` 指向 `Base` 的表，于是调用的是 `Base::function1()`。
- **该设计的好处**：借助这些表，即使只有基类指针/引用，调用也能解析到正确的覆写。
- **虚调用的性能代价**：解析需经由 `__vptr` 到达虚表再索引，大约三步操作；普通间接调用约两步，直接调用一步。原文指出这点额外开销在现代硬件上通常微不足道。
- **内存代价**：每个使用虚函数的类都带一个 `*__vptr`，故该类每个对象都大出一个指针。虚函数"强大，但确有性能代价"。
