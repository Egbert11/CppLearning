# 26.3 Function template specialization

> 原文：https://www.learncpp.com/cpp-tutorial/function-template-specialization/

## 核心概念

- **模板实例化的"拓印"**：函数模板针对某类型实例化时，编译器会生成一份把类型参数替换掉的函数副本，因此每个实例化共享完全相同的实现逻辑。
- **为什么需要不同行为**：通常希望行为统一，但有时某个特定数据类型需要略有不同的实现。
- **非模板函数的做法**：为一个类型定义一个普通（非模板）函数，重载决议就会选择它，而不去实例化模板版本。
- **签名可以灵活**：非模板函数不必与模板签名一致——例如模板收 const 引用，重载可以按值收。
- **Best practice**：一般情况下，如果有非模板函数这一选项，优先定义非模板函数。
- **显式模板特化（template specialization）**：允许为特定类型或值显式提供模板的不同实现。
- **全特化 vs 偏特化**："当所有模板参数都被特化时，称为**全特化（full specialization）**"；"当只有部分模板参数被特化时，称为**偏特化（partial specialization）**"。
- **主模板要求**：特化之前，编译器必须已经看到主模板（primary template）的声明。
- **特化语法规则**：空的模板参数声明（`template<>`）表示已没有模板参数；特化要写出类型，如 `print<double>`；特化必须与主模板签名一致（代入具体类型后），所以原本按引用传递的不能改成按值传递。
- **优先级规则**：如果同时存在匹配的非模板函数与匹配的特化，非模板函数胜出。
- **删除特化**：可以用 `= delete` 删除特化，使任何解析到它的调用都成为编译错误。
- **使用建议**：一般来说应尽量避免函数模板特化，能改用非模板函数就改用非模板函数。
- **关于成员函数**：对类模板 `Storage<T>` 的成员函数，调用会解析到 `Storage<int>::print()` 或 `Storage<double>::print()`；要为某一类型改变行为，需要特化类模板——那是"类模板特化"，不是"函数模板特化"。

## 最佳实践

- **Best practice**：一般情况下，如果有非模板函数这一选项，优先定义非模板函数。
- **Warning**："全特化不是隐式 inline 的（偏特化才是隐式 inline）。"如果把全特化放进头文件，要标记 `inline`，以免跨翻译单元违反一次定义规则（ODR）。
