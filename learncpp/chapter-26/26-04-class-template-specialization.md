# 26.4 Class template specialization

> 原文：https://www.learncpp.com/cpp-tutorial/class-template-specialization/

## 核心概念

- **不只函数能特化**：正如可以针对特定数据类型特化函数，也可以特化类。
- **动机：bool 的空间浪费**：由 `T m_array[8]` 构造的 `Storage8<bool>` 占用 8 字节。因为变量必须有地址、CPU 无法寻址到比字节更小的单位，每个 `bool` 占 1 字节——"1 位有用信息、7 位浪费"。
- **可行但别扭的替代**：可以用位运算把 8 个 bool 打包进 1 字节，但那需要一个另取名字的独立类，使用者得记住两个名字，没必要地复杂。
- **类模板特化的定义**：它让你把模板类"针对某个数据类型（或多个模板参数时针对多个类型）"加以特化；特化版本优先于通用版本。
- **特化类等同独立类**：尽管实例化方式相同，你可以改动它的一切——实现、甚至哪些函数是 public——"就像它是个独立类一样"。
- **可见性规则**：编译器必须看到特化的完整定义才会使用它；"定义类模板特化要求先定义好非特化的类"。
- **语法 `template<>`**：表示这是一个没有模板参数的模板，因为唯一的参数 `T` 已被替换成具体类型。
- **语法 `class Storage8<bool>`**：在类名后加上 `<bool>`，标志它是 bool 特化版。
- **实现要点**：特化版存一个 `std::uint8_t`（1 字节），而不是 8 个 bool 的数组（8 字节）。
- **保持一致接口**：C++ 允许在特化中增删改函数，但保持相同的公开接口，使用者就能无差别地使用两个版本。
- **成员函数特化**：为一个函数而复制整个类是冗余的；可以让编译器从 `Storage<T>` 隐式实例化 `Storage<double>`，只显式特化 `Storage<double>::print()`。
- **显式特化的 inline 规则**："显式函数特化不是隐式 inline 的"，所以放进头文件时应给显式特化的成员函数标 `inline`。
- **特化放在哪里**：通常把特化放在头文件中、紧挨非特化类的下方，一次 include 就能同时拿到两者。若只有某个翻译单元需要，可以放进该源文件——此时其它翻译单元继续用非特化版。
- **关于单独的头文件**：把特化放进它自己的头文件是不推荐的，因为那样代码行为会"随该头文件是否被包含而悄然改变"——你可能不小心用到非特化版，或因传递性包含而意外拿到特化版。

## 最佳实践

本节无严格标注为 Best practice / Warning 的方框，但有若干建议性说明：

- **关于 inline**："显式函数特化不是隐式 inline"，放进头文件时应标 `inline`。
- **关于可见性**：编译器若只看到非特化类而没看到特化定义，"就会用非特化版代替特化版"。
- **关于放置位置**：优先把特化放在同一个头文件里、紧挨非特化类的下方；只有单个翻译单元需要时才放源文件。
- **关于单独的特化头文件**：原文说这是"一个坏主意"，因为行为会随该头文件是否被包含而静默改变。
