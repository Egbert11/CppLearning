# 17.9 Pointer arithmetic and subscripting

> 原文：https://www.learncpp.com/cpp-tutorial/pointer-arithmetic-and-subscripting/

## 核心概念

- **连续存储**：数组存放在连续内存中；本节拆解下标背后的算术原理，它同样解释了范围 for 循环以及后续的迭代器。
- **指针算术（定义）**：对指针施加整数运算（加、减、自增、自减）以得到新地址。
- **向前移动**：`ptr + 1` 得到"下一个对象"的地址；对 4 字节的 `int` 即后移 4 字节，`ptr + 2` 即 8 字节。
- **向后移动**：`ptr - 1` 得到"前一个对象"的地址；对 4 字节 `int` 即前移 4 字节。
- **Key insight**：指针算术按"指针所指类型的对象"为单位移动，而不是按原始字节地址移动（是下一个/上一个**对象**，不是下一个/上一个**地址**）。
- **`++` 与 `--`**：`++ptr` 是 `ptr = ptr + 1` 的简写，会修改保存的地址；`--ptr` 同理减一个对象。
- **Warning**：对像 `x` 这样的单一变量做指针算术在技术上属于未定义行为；规则是：指针与运算结果必须处在同一数组内（或末尾后一个位置）。实现通常不会阻止。
- **下标即指针算术**：`ptr[n]` 等价于 `*((ptr) + (n))`，即"指针算术 + 一次解引用"。
- **初始化中的退化**：数组作为初始化器时会退化为指向元素 0 的指针，因此 `ptr` 保存的就是该地址。
- **数组为何从 0 开始**：因为 `*(arr + n)` 直接给出第 n 个元素，从 0 开始索引可省去编译器内部的一次减法。
- **旁注/冷知识**：由于 `ptr[n]` 会变成 `*((ptr) + (n))`，反过来写 `n[ptr]` 也能编译；但教程建议避免这种令人困惑的写法。
- **相对而非绝对**：下标是相对位置——`ptr[1]` 表示"从 `ptr` 当前所指位置的后一个对象"，所以若 `ptr` 指向元素 3，`ptr[1]` 其实是元素 4。
- **Best practice**：从元素 0 开始索引时优先用下标，使下标与元素编号对应；做相对定位时优先用指针算术。
- **负下标**：C 风格数组可以用带符号整数索引；`ptr[-1]` 等价于 `*(ptr-1)`，返回前一个对象。
- **数组遍历**：常见用法是取 `begin` 指针（首元素）与 `end` 指针（末尾后一个位置），循环条件 `begin != end`，每次解引用。
- **Tip**：指针算术只有在结果仍落在有效元素上或末尾后一个位置时才有效；越过就是未定义行为，即使不解引用。
- **重构遍历**：可以把循环搬进一个接受 `begin`/`end` 的函数，即使数组本身从不传入；`begin` 与 `end` 已携带全部信息。
- **范围 for 循环**：内部遵循标准的 `__begin`/`__end` 模式，本质上就是带 begin/end 的同一循环，只是把解引用的值赋给循环变量。
- **测验答案**：`arr[0]` 是 `*((arr) + (0))` 的简写，化简为 `*(arr + 0)`，即 `*arr`。（更多测验见 17.10。）

## 最佳实践

- **Key insight**：指针算术返回的是下一个/上一个**对象**的地址，而不是下一个/上一个地址。
- **Warning**：本节对单一变量做指针算术的示例在技术上属于未定义行为；标准规定算术仅在同一数组内或末尾后一位是良定义的，尽管实现通常不会阻止。
- **Best practice**：从元素 0 开始索引时用下标；相对某元素做偏移时用指针算术。
- **Tip**：指针算术仅在数组边界内或末尾后一位有效；越界即未定义行为，即使不解引用。
