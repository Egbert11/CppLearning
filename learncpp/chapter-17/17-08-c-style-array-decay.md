# 17.8 C-style array decay

> 原文：https://www.learncpp.com/cpp-tutorial/c-style-array-decay/

## 核心概念

- **传数组的难题**：每次函数调用都拷贝一个大数组代价高昂，而 C 语言又没有引用，无法用"按引用传递"来规避拷贝。
- **"任意长度"的诉求**：C 的设计者还希望同一个函数能被不同长度的数组调用。但 C 没有任意长度数组的语法，没有模板，也不能在不同长度的数组类型之间转换。
- **C 的巧妙解法**：把形参声明为数组类型（如 `int arr[1000]`）后，传一个更小的数组（如 7 个元素）也能通过而不发生拷贝。
- **数组退化（array decay）的定义**：在大多数表达式中，C 风格数组会隐式转换为"指向其元素类型的指针"，该指针用首元素的地址初始化。这被称为 **array decay**（退化、decay）。
- **退化出的指针是普通指针**：退化成指针后没有任何特殊之处，它就是一个保存首元素地址的普通指针。
- **const 数组退化为指向 const 的指针**：例如 `const int[5]` 退化为 `const int*`。
- **不退化的情况（Tip）**：以下情形数组**不会**退化——用于 `sizeof()` 或 `typeid()`、用 `operator&` 取地址、作为类类型成员传递、按引用传递。
- **"数组就是指针"是误解**：数组对象是一串元素，指针对象只保存一个地址，类型也不同：`int[5]` 与 `int*`。
- **长度信息丢失**：数组类型带有长度信息，退化后的指针类型不带。"decay" 一词正体现这种信息丢失。
- **下标作用于退化后的指针**：对 C 风格数组做下标时，`operator[]` 实际作用于退化后的指针；该指针本身也可以直接下标。
- **退化解决了传参问题**：虽然看起来是按值传递数组，实际上是按地址传递，因此不会发生拷贝。
- **不同长度、同一指针类型**：元素类型相同但长度不同的两个数组会退化为同一种指针类型，因而可互换使用。
- **指针形参类型**：函数形参可以是"（const）指向数组元素类型的指针"，与退化后的实参相匹配。
- **形参语法（Best practice）**：优先使用数组语法 `int arr[]` 而非指针语法 `int *arr`，更清晰；两者对编译器完全等价。方括号里不需要写长度，写了也会被忽略。
- **`sizeof()` 的差异**：对数组与退化指针调用 `sizeof()` 结果不同（4 字节 int 下为 12 与 4），因此对 C 风格数组使用它可能有危险。
- **`std::size()` 更安全**：C++17 的 `std::size()`（及 C++20 的 `std::ssize()`）传入指针时无法编译，而旧的 `sizeof(arr)/sizeof(*arr)` 写法不会报错。
- **重构困难**：对未退化数组成立的代码，换成退化数组后可能编译失败，甚至更糟——悄悄地产生错误行为。
- **没有长度检查**：失去长度信息后，函数无法校验数组是否足够长；过短的数组或指向单个值的指针在索引时会造成未定义行为。
- **遍历的困难**：没有长度就不知道数组在哪里结束，迭代变得麻烦。
- **变通方案一——同时传数组与长度**：可用，但有诸多问题：调用方配对易错、与 `std::size_t` 存在符号转换问题、只能在运行期断言（形参无法 `static_assert`）、对隐式调用不适用。
- **变通方案二——哨兵/终止元素**：用一个语义上无效的值标记结尾，从而能计算长度并遍历。C 风格字符串就用空终止符。问题：缺少终止符会越界遍历；需要特殊处理；长度不符时可能"处理"到终止符；某些数据可能不存在可用的哨兵值。
- **建议**：尽量避开 C 风格数组，优先用 `std::string_view`、`std::string`、`std::array`、`std::vector`。全局 constexpr 数组是公认的例外。
- **按引用传递（旁注）**：数组可按引用传递以避免退化，但引用要求固定长度，要多长度还得用模板——那还不如直接用 `std::array`。
- **现代 C++ 的用法**：constexpr 全局（或 constexpr static 局部）数据；以及需要直接处理非 constexpr 的 C 风格字符串实参，因为转成 `std::string_view` 反而代价高或多余。

## 最佳实践

- **Tip（数组不退化的情况）**：仅当 ① 用作 `sizeof()`/`typeid()` 的实参、② 用 `operator&` 取地址、③ 作为类类型成员传递、④ 按引用传递时，C 风格数组才不退化。
- **Key insight（长度丢失）**："退化的数组指针并不知道它所指数组有多长。" "decay" 一词正是表示长度类型信息的丢失。
- **Key insight（传参语义）**："C 风格数组是按地址传递的，即使看起来像是按值传递。"
- **Key insight（退化后可互换）**："元素类型相同、长度不同的两个 C 风格数组会退化为同一指针类型。"
- **Best practice（形参语法）**：C 风格数组形参优先用数组语法 `int arr[]`，而非指针语法 `int *arr`。
- **Key insight（哨兵值）**：C 风格字符串（本身是 C 风格数组）用空终止符，使其退化后仍能被遍历。
- **Best practice（避免 C 风格数组）**：尽量不用 C 风格数组。替代选择：
  - 只读字符串（字符串字面量符号常量、字符串形参）→ `std::string_view`；
  - 可修改字符串 → `std::string`；
  - 非全局的 constexpr 数组 → `std::array`；
  - 非 constexpr 数组 → `std::vector`。
  - 全局 constexpr 数组使用 C 风格数组是可接受的。
- **Author's note（按引用传递数组）**：数组可按引用传递以避免退化，但一致性容易丢失、固定长度限制了通用性；若再结合模板以支持多长度，不如直接用 `std::array`。
