# 17.10 C-style strings

> 原文：https://www.learncpp.com/cpp-tutorial/c-style-strings/

## 核心概念

- **C 风格数组回顾**：C 风格数组定义一串顺序排列的元素，如 `int testScore[30] {};` 得到下标 0–29。
- **字符串字面量的类型**：字符串是一串顺序字符；字面量 `"Hello, world!"` 的类型是 `const char[14]`——13 个可见字符加一个隐藏的空终止符。
- **核心定义**：C 风格字符串就是元素类型为 `char` 或 `const char` 的 C 风格数组。
- **现代地位**：字符串字面量仍然常用，但 C 风格字符串**对象**已不流行，因为它"难用又危险"；现代替代品是 `std::string` 与 `std::string_view`。老代码中仍会遇到。
- **定义字符串**：声明一个 `char`（或 `const char`/`constexpr char`）数组；需要多留一个元素放隐式的空终止符。
- **长度建议**：初始化时省略数组长度，让编译器计算，这样以后改初始化器时不必手动更新，也不会漏掉终止符的位置。
- **退化规则**：C 风格字符串字面量退化为 `const char*`；字符串数组视 const 与否退化为 `const char*` 或 `char*`。退化会丢失类型中编码的长度信息。
- **空终止符为何存在**：可以从字符串开头数到空终止符来（低效地）重新得到长度。
- **输出行为**：`std::cout` 会一直打印字符直到遇到空终止符，因此退化后的字符串仍能打印。
- **缺终止符即 UB**：打印没有空终止符的字符串是未定义行为；通常会把所有字符打印出来，再把相邻内存当作字符继续打印，直到遇到零字节。
- **输入问题**：字符串数组是固定大小，必须超量分配；我们无法预知用户会输入多少字符。
- **C++20 之前的输入危险**：`std::cin >> rolls` 会尽可能多地抽取字符，过长输入可能写穿数组，造成未定义行为。
- **缓冲区溢出（Key insight）**：当拷入的数据超过存储容量时发生；相邻内存被覆盖，产生未定义行为，恶意者可能借此改写内存以改变程序行为。
- **C++20 的变化**：`operator>>` 现在只对未退化的 C 风格字符串生效，抽取的字符数受数组长度限制，从而防止溢出——但也不能再用于已退化的字符串。
- **推荐输入方式**：用 `std::cin.getline(rolls, std::size(rolls))`；它最多读取 254 个字符（含空白）并丢弃多余的。`std::size()` 对未退化数组很容易用；对已退化的数组必须另想他法确定长度，长度给错会导致故障或安全问题。
- **更安全的替代**：读取用户文本时优先用 `std::string`，它会自动增长。
- **修改规则**：C 风格字符串遵循数组规则——可以在创建时初始化，但之后不能用赋值运算符整串赋值。
- **逐字符修改**：因为它是数组，可以用 `[]` 修改单个字符。
- **用 `std::size()` 取长度**：注意：对退化字符串无效；且返回的是**数组**长度，不是**字符串**长度。
- **用 `strlen()` 取长度**：位于 `<cstring>`，对退化数组可用，返回不含空终止符的字符串长度——但它要遍历整个数组计数，因此慢。
- **其它 `<cstring>` 函数**：`strlen()`（长度）；`strcpy()`、`strncpy()`、`strcpy_s()`（用另一串覆盖）；`strcat()`、`strncat()`（追加到末尾）；`strcmp()`、`strncmp()`（比较，相等返回 `0`）。除 `strlen()` 外一般都不推荐使用。
- **避免非 const 的 C 风格字符串**：它们难用且易越界，导致未定义行为与潜在安全问题；若需要固定缓冲区或受内存限制的设备，请用经过充分测试的第三方定长字符串库。
- **测验**：(1) 用指针与指针算术逐字符打印 C 风格字符串，用 `"Hello, world!"` 测试。(2) 同样操作但反向打印。

## 最佳实践

- **Key insight（缓冲区溢出）**："当拷入的数据超过存储容量时发生的计算机安全问题。" 超出存储部分的内存会被覆盖，造成未定义行为；攻击者可利用此类缺陷改写内存，企图改变程序行为。
- **Best practice**：避免使用非 const 的 C 风格字符串对象，优先用 `std::string`。
