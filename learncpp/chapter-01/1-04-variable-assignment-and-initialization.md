# 1.4 Variable assignment and initialization

> 原文：https://www.learncpp.com/cpp-tutorial/variable-assignment-and-initialization/

## 核心概念

- **赋值（assignment）**：变量定义之后，可以用 `=` 在单独的语句里给它一个值，这个过程叫赋值，`=` 叫**赋值运算符**。
- **拷贝赋值（copy-assignment）**：默认情况下，赋值把 `=` 右边的值拷贝进左边的变量。
- **输出值**：变量有值之后，可用 `std::cout` 和 `<<` 打印。
- **重新赋值会覆盖**：需要改变值时随时可以再赋值，旧值被覆盖（如 5 被 7 替换）。
- **一次一个值**：普通变量一次只能保存一个值。
- **初始化（initialization）**：给刚定义的对象赋值需要两条语句；可以在定义时直接给出初值，把它们合成一条。提供这个初值就叫初始化，所用语法叫**初始化器（initializer）**（初值本身也常被称作 initializer）。"Initialization 就是给变量一个初始值，联想 initial-ization。"
- **五种常见初始化形式**：默认初始化（default）、拷贝初始化（copy）、直接初始化（direct）、直接列表初始化（direct-list）、值初始化（value）。
- **C++17 起等价性**：从 C++17 开始，在多数情况下拷贝初始化、直接初始化和直接列表初始化行为相同（有一个关键差异后续再讲）。
- **默认初始化**：不提供初始化器；很多情况下不做任何初始化，留下**不确定值（indeterminate value）**，也叫"垃圾值"。
- **拷贝初始化**：初值写在等号后，源自 C。曾因复杂类型的效率问题失宠，C++17 修复了大部分问题；常见于旧代码/继承自 C 的代码。
- **直接初始化**：初值写在圆括号内。为更高效地初始化类类型对象而引入，后来让位给直接列表初始化，但由于列表初始化有些怪癖，它又部分回归。
- **列表初始化**：又叫统一初始化（uniform initialization）或花括号初始化，是现代写法，用花括号，分两种：直接列表初始化（首选）和拷贝列表初始化（很少用）。
- **列表初始化为何存在**：C++11 之前，有些类型必须拷贝初始化、有些必须直接初始化；拷贝初始化与拷贝赋值都用 `=` 难以区分，直接初始化与函数调用都用括号难以区分。列表初始化几乎处处可用、行为一致、语法无歧义。"看到花括号，就知道是在对对象做列表初始化。"
- **值列表**：列表初始化也支持用一个值列表来初始化对象。
- **禁止窄化转换（narrowing conversion）**：列表初始化不允许窄化转换，若值不能被安全保存，编译器必须给出诊断（错误或警告）；而拷贝/直接初始化会静默截断（如 4.5 变成 4），可能给警告也可能不给。
- **限制范围**：禁止窄化只作用于初始化，不作用于之后对该变量的拷贝赋值。
- **值初始化 / 零初始化（zero-initialization）**：空花括号触发值初始化，多数情况下初始化为 0（或该类型最接近 0 的值），这种置零叫零初始化。对类类型，值/默认初始化可能改用预定义的默认值（可能非 0）。
- **偏好**：一般认为列表初始化（含值初始化）最优先：适用面广、禁止窄化、支持值列表；Bjarne Stroustrup 和 Herb Sutter 也推荐。不过某些场合它的行为不符合预期，所以一些有经验的开发者主张按情况混用。
- **`{ 0 }` 还是 `{}`**：确实会用到那个值时就写 `{ 0 }`（直接列表初始化）；值只是临时、马上会被替换时就用 `{}`（值初始化）。
- **创建时即初始化**：变量应在创建时初始化；若有特定理由（如性能敏感）故意不初始化也可以。
- **实例化（instantiation）**：指变量已被创建（分配）并初始化（含默认初始化）；这样的对象叫**实例（instance）**，多用于类类型。
- **一行多个变量**：同类型变量可写在一条语句里用逗号分隔，但最佳实践是避免。一行初始化多个也可能踩坑：`int a, b = 5;` 只初始化了 `b`，`a` 仍未初始化——每个变量都要有自己的初始化器。
- **未使用变量警告**：现代编译器通常会对"初始化了却从未使用"的变量给出警告；开启"把警告当错误"后，这些警告会变成编译失败。三种处理办法：删掉/注释掉定义；真正使用它；或在两者都不可行时用 C++17 的 `[[maybe_unused]]` 属性抑制警告（编译器多半会把这类变量优化掉，没有性能损失）。`[[maybe_unused]]` 要谨慎使用，只用于确有正当理由未被使用的变量。

## 最佳实践

- **Warning**：把赋值 `=` 与相等比较 `==` 搞混，是新手最常见的错误之一；前者把值存进变量，后者判断两个操作数是否相等。
- **Best practice**：**优先使用直接列表初始化（direct-list-initialization）或值初始化（value-initialization）**来初始化变量。
- **Best practice**：**在创建变量时就初始化它**。
- 关键要点：初始化 = 给变量一个初始值（"initial-ization"）；看到花括号就是在做列表初始化。
- **Author's note**：Stroustrup 与 Sutter 也推荐列表初始化（见 C++ Core Guidelines）；但列表初始化有些怪癖，一些资深开发者主张按情况混用拷贝/直接/列表形式——等你弄懂细节后可自行判断。
