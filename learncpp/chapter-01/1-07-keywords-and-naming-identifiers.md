# 1.7 Keywords and naming identifiers

> 原文：https://www.learncpp.com/cpp-tutorial/keywords-and-naming-identifiers/

## 核心概念

- **关键字（keywords）**：C++ 把一批单词保留给语言自身使用（C++23 起共 92 个），这些词称为关键字/保留字，各有特殊含义，不能被用作标识符。
  - 它们包括类型（`int`、`bool`、`double`、`char`、`void`）、控制流（`if`、`for`、`while`、`return`、`switch`）、以单词形式出现的运算符（`and`、`or`、`not`、`xor` 及其 `_eq` 变体），以及各种转换形式（`static_cast`、`dynamic_cast` 等）。
  - C++20 新增的关键字会标注 "(since C++20)"，如 `char8_t`、`concept`、`consteval`、`constinit` 以及协程三件套 `co_await`、`co_return`、`co_yield`；若编译器不完全支持或未启用 C++20，这些可能不可用。
- **特殊标识符**：`override`、`final`、`import`、`module` 这四个名字只在特定语境下有特殊含义，其余场合并不是保留字。
- **为什么重要**：关键字加上运算符和这些特殊标识符，基本就构成了整个 C++ 语言（预处理器命令除外）。IDE 通常会给它们上色，方便识别。
- **标识符命名规则（强制，非可选）**：
  1. 不能是关键字，因为关键字是保留的；
  2. 只能包含字母（大小写）、数字、下划线，不能包含其它符号或空白；
  3. 必须以字母或下划线开头，不能以数字开头；
  4. C++ 区分大小写，所以 `nvalue`、`nValue`、`NVALUE` 是三个彼此不同的名字。
- **命名惯例（非强制，但应遵守）**：
  - 变量名一般以小写字母开头，单词或缩写整体小写；
  - 函数名通常也小写开头（此处业界有分歧，作者遵循该惯例，理由是 `main` 和标准库）；
  - 以大写字母开头的名字一般留给用户自定义类型（结构体、类、枚举）；
  - 多词名字用下划线分隔（snake_case）或首字母大写交替（camelCase）；
  - 本教程主要使用 camelCase，以避免下划线被误看成空格；标准库则对变量和函数都用下划线；
  - 不要以下划线开头——虽然合法，但这类名字一般预留给操作系统、库和编译器使用；
  - 名字应能表达其值的含义，尤其在单位不明显时；
  - 名字长度应与作用域、特异性成比例：局部、短暂使用可以短；广泛使用或含义特殊则应长（例如以毫米为单位的裤长）；用户临时输入、含义不明确的数字可以短；
  - 避免缩写，除非是 `num`、`cm`、`idx` 这类通用且明确的；
  - 当描述性名字会变得笨重时，可借注释说明意图。
- **好名字的评分参考**（原文表格）：

| 代码 | 评价 | 说明 |
|---|---|---|
| `int ccount` | 差 | c 前缀含义不明 |
| `int customerCount` | 好 | 清楚在数什么 |
| `int i` | 视情况 | 用法简单则可用，否则差 |
| `int index` | 视情况 | 索引对象明显则可用 |
| `int totalScore` | 视情况 | 只有一项计分时可用，否则太模糊 |
| `int _count` | 差 | 不要以下划线开头 |
| `int count` | 视情况 | 数的对象明显则可用 |
| `int data` | 差 | 什么数据？ |
| `int time` | 差 | 单位是秒、分还是时？ |
| `int minutesElapsed` | 视情况 | 从何时起算明显则可用 |
| `int x1, x2` | 视情况 | 用法简单则可用，否则差 |
| `int userinput1, userinput2` | 差 | 名字太长，难以区分 |
| `int numApples` | 好 | 描述性强 |
| `int monstersKilled` | 好 | 描述性强 |

## 最佳实践

- 在已有程序中，遵循该项目既有的命名惯例，即使它不符合当前最佳实践；只有在编写新程序时才应用现代最佳实践。
- 阅读代码的次数远多于编写：写代码时偷懒起的缩写名，会让每个后来的读者（包括未来的自己）多花时间。想写得更快，应依靠编辑器的自动补全，而不是起晦涩的名字。
