# 1.6 Uninitialized variables and undefined behavior

> 原文：https://www.learncpp.com/cpp-tutorial/uninitialized-variables-and-undefined-behavior/

## 核心概念

- **不会自动初始化**：与某些语言不同，C/C++ 让大多数变量保留所分配内存地址里原有的"垃圾"值。
- **未初始化变量（uninitialized variable）**：从未通过初始化或赋值获得已知值的变量。
- **术语（并非严格对立）**：初始化 = 在定义处给对象一个已知值；赋值 = 在定义之后给对象一个已知值；未初始化 = 对象尚未获得已知值。默认初始化后又赋值的变量就不再是未初始化了。
- **`int x;` 的情形**：没有初始化器即默认初始化；多数情况下它不做实际初始化，因此算未初始化。本节关注结果而非过程。
- **为何存在**：这种不初始化是从 C 继承来的性能优化——例如创建 10 万个稍后从文件填值的变量，多余地初始化会浪费开销。
- **建议**：初始化变量，因为相对于收益，代价极小；只有刻意选择时才省略初始化。
- **后果**：读取未初始化的值可能打印出任意结果，且不同运行可能不同。
- **编译器检测**：现代编译器常会对"使用未给值的变量"报警告或错误。
- **难以调试**：这是常见新手错误且难调试，因为"幸运"的垃圾值（比如 0）会让程序看起来正常。
- **未定义行为（undefined behavior, UB）**：执行了行为未被 C++ 语言良好定义的代码。使用没有已知值的变量时，没有任何规则可依。
- **UB 可能的症状**：每次运行结果不同；稳定但错误的输出；行为时对时错；现在对、以后错；现在或以后崩溃；只在某些编译器上工作；在无关改动后出问题；也可能看起来正常工作。
- **为什么代码有时"照样能用"**：要么 UB 碰巧暂时产生了想要的结果，要么编译器比较宽松——"你的编译器可能压根没遵守标准！"
- **实现定义行为（implementation-defined behavior）**：标准允许实现自行选择的行为，实现必须记录并保持一致（例如 `sizeof(int)` 返回几个字节）。
- **未指定行为（unspecified behavior）**：类似，但实现不要求记录。
- **为何两者都该避免**：程序换一个编译器或换一套项目设置可能就会出错。

## 最佳实践

- **Rule**：注意避免一切会导致未定义行为的情形，例如使用未初始化的变量。
- **Best practice**：尽可能避免实现定义与未指定行为，因为程序可能在别的实现上出错。
- **Best practice**：始终初始化你的变量。
- **Warning**：某些编译器（如 Visual Studio）在**调试**构建配置下会把内存初始化为某个预设值（因此示例 1 在调试配置下会稳定打印 `-858993460`），但**发布**构建不会。原文给出的示例警告是 `warning C4700: uninitialized local variable 'x' used`。
- **Author's note**："未定义行为就像一盒巧克力，你永远不知道会得到什么！"
