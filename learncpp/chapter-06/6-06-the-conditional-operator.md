# 6.6 The conditional operator

> 原文：https://www.learncpp.com/cpp-tutorial/the-conditional-operator/

## 核心概念

- **条件运算符（conditional operator `?:`）**：一个三元运算符（接受三个操作数），有人称之为“算术 if”。因为长久以来它是 C++ 唯一的三元运算符，也被昵称为“三元运算符（the ternary operator）”。
- **形式与含义**：写作 `c ? x : y`；条件 `c` 为真时求值 `x`，否则求值 `y`。
- **与 if-else 的关系**：它是一种特定风格 if-else 的紧凑替代。if-else 中 `else` 分支可省略；而 `?:` 中冒号与第二个表达式不可省略。
- **语法对比**：if-else 用语句，而 `?:` 用三部分：`condition ? expression1 : expression2;`
- **紧凑改写**：把“给最大值赋值”的 if-else 塌缩成一条使用条件运算符的赋值语句。
- **表达式语境**：因为它作为表达式求值，可用于任何允许表达式之处——包括 if-else 无法使用的初始化处。
- **常量表达式**：当两个操作数都是常量表达式时，整个条件表达式可用于常量表达式中。
- **if-else 的作用域问题**：在 if 或 else 块内声明的变量会在块结束处销毁，因此 if-else 无法定义一个供后续使用的变量。
- **变通方法**：可用返回该值的辅助函数达到同样效果，但要写多得多的代码。
- **优先级陷阱**：多数运算符比 `?:` 结合得更紧，故未加括号的条件表达式可能求值出与预期不同的结果——如它被解析为 `(10 - x) > y ? x : y` 而非预期的分组。
- **常见的流输出错误**：在条件运算符之前写流输出，会让 `operator<<` 先结合，含义完全改变；示例打印出 `0` 而非预期文本。
- **括号指导**：当条件运算符处于复合表达式中时，把整个条件表达式括起来；若条件含运算符，可考虑把条件也括起来；操作数本身不需要括号。
- **类型规则**：第二、第三操作数必须同类型，或可转换为公共类型；编译器的转换规则可能复杂且出人意料。
- **throw 表达式（进阶）**：作为高级替代，一个或两个操作数可以是 throw 表达式。
- **基本类型混用**：基本类型混用一般没问题，唯独有符号/无符号混用遵循算术转换规则，可能得到超范围的结果。
- **编译错误情形**：若不存在公共类型（如 int 与 C 风格字符串字面量），编译失败；可用显式转换或改用 if-else 修复。
- **constexpr 提示**：若条件是常量表达式，优先用 `if constexpr` 而非 `if`，编译器可能据此给出警告。
- **推荐用途**：最适于在两值中择一时——初始化、赋值、传参、函数返回、打印。
- **可读性警示**：复杂表达式一般应避免使用该运算符，否则易错且难读。

## 最佳实践

- 当条件运算符用于复合表达式时，把整个条件运算（含操作数）括起来。
- 若条件含任何运算符（函数调用运算符除外），考虑把条件括起来（为了可读性）。
- 条件运算符的操作数不需要加括号。
- 避免在复杂表达式中使用条件运算符。
