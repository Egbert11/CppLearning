# 6.4 Increment/decrement operators, and side effects

> 原文：https://www.learncpp.com/cpp-tutorial/increment-decrement-operators-and-side-effects/

## 核心概念

- **自增/自减的定义**：把变量加一或减一很常用，C++ 为二者各提供了专门的运算符。
- **前缀自增（`++x`）**：先把操作数加一，表达式随后返回**加一后的新值**。
- **前缀自减（`--x`）**：先把操作数减一，表达式随后返回减一后的新值。
- **后缀自增（`x++`）**：先复制一份操作数，把操作数加一，表达式返回**那份复制的旧值**。
- **后缀自减（`x--`）**：同样先复制，把操作数减一，表达式返回复制的旧值。
- **两种形式**：每种运算符都有前缀（符号在操作数前）与后缀（符号在操作数后）两种写法。
- **前缀直白**：先发生变化，表达式结果就是变化后的操作数（见 example1）。
- **后缀较微妙**：顺序是——复制、修改原值、求值那份副本（而非原值），见 example2。
- **后缀分步**：设 x 为 5，先建一份值为 5 的临时副本；真正的 x 变为 6；把副本（仍为 5）返回并存储；随后丢弃临时对象。
- **example2 的结果**：接收变量拿到的是自增前的值（5），而 x 是自增后的值（6）。
- **性能说明**：后缀形式步骤更多，可能比前缀形式性能差。
- **对比示例**：example3 打印五行，显示前缀变化在同一条输出语句中立即可见，而后缀变化要到下一行才出现。
- **两形式行为一致的情形**：若不使用表达式返回值（如单独的 `++x;` 或 `x++;`），两种形式结果相同（见 example4）。
- **选择规则**：两者都可用时选前缀——通常更快、更不容易出意外；只有当后缀明显更简洁、更清晰时才用后缀。
- **副作用（side effect）定义**：函数或表达式在返回值之外产生了可观察的后果，即具有副作用。
- **常见副作用**：修改对象、执行输入/输出、刷新用户界面（如切换按钮）。
- **副作用通常是想要的**：赋值改变存储的值，`++` 改变其操作数，`operator<<` 改变控制台状态；这些变化在语句结束后依然保留。
- **与普通运算符的对比**：赋值、前缀、后缀运算符会永久修改对象；而算术运算符只产生值，不改变操作数。
- **求值顺序问题**：C++ 不规定函数实参的求值顺序，因此一次调用中把普通操作数与带副作用的操作数混用会导致未定义行为（见 example5）。
- **标准为何留白**：不作规定可以让编译器针对特定架构选择最自然、最快的方式。
- **副作用的时序**：C++ 常常不规定运算符的副作用何时生效，故在同一条语句里复用被副作用影响的对象可能导致未定义行为。例如 x 为 1 时，`x + ++x` 在 Visual Studio 与 GCC 上得 `2 + 2`，而 Clang 上得 `1 + 2`。
- **实用安全准则**：一条语句中对某变量最多施加一次副作用，即可避开几乎所有这类问题（以及历史上该领域的编译器 bug）。
- **一个例外**：形如 `x = x + y`（等价于 `x += y`）的普通赋值是安全的。

## 最佳实践

- 优先使用前缀版本：性能更好，也更不容易带来意外。
- 当后缀版本能让代码明显比等价的前缀写法更简洁、更易理解时，才使用后缀版本。
- Key insight：赋值运算符、前缀运算符和后缀运算符都有副作用，会永久改变对象的值；其它运算符（如算术运算符）只返回值，不修改操作数。
- As an aside：C++ 标准有意不定义这些细节，以便编译器针对特定架构选择最自然（因而最高效）的做法。
- Warning（1）：C++ 不定义函数实参或运算符操作数的求值顺序。
- Warning（2）：不要在一条语句中对同一变量施加一次以上的副作用，否则结果可能是未定义行为。简单赋值（如 `x = x + y`）是例外。
