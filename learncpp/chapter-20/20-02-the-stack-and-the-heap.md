# 20.2 The stack and the heap

> 原文：https://www.learncpp.com/cpp-tutorial/the-stack-and-the-heap/

## 核心概念

- **内存分段**：程序内存被划分为若干段：
  - **代码段（text segment）**：编译后的程序所在处，通常只读。
  - **bss 段（未初始化数据段）**：存放零初始化的全局变量和静态变量。
  - **data 段（已初始化数据段）**：存放已初始化的全局变量和静态变量。
  - **堆（heap）**：动态分配变量所在处。
  - **调用栈（call stack）**：存放函数参数、局部变量及其它函数相关信息。
- **堆段**：又称"free store"，跟踪用于动态内存分配的内存。用 `new` 就在堆上分配。
  - 假设 `int` 是 4 字节，`new int` 分配 4 字节，`new int[10]` 分配 40 字节。
  - `operator new` 返回地址，可存入指针。内部如何找空闲内存不必关心，但注意：**连续的分配请求不一定得到连续的地址**。
- **删除规则**：动态分配的变量被 delete 时，内存被"归还"给堆，之后可重新分配。delete 一个指针并不会删除变量本身，只是把该地址处的内存还给操作系统。
- **堆的优缺点**：
  - 堆分配"相对较慢"。
  - 分配的内存一直保持分配状态，直到被显式释放（小心内存泄漏）或程序结束（操作系统应会清理）。
  - 动态分配的内存必须通过指针访问，解引用比直接访问变量慢。
  - 堆是一大片内存池，所以可以分配很大的数组、结构体或类。
- **调用栈**：跟踪从程序开始到当前执行点所有"已调用但尚未结束"的函数，并负责所有函数参数和局部变量的分配，以栈这种数据结构实现。
- **数据结构**：一种"为了高效使用而组织数据的编程机制"；数组和结构体是早先的例子，标准库还提供许多，包括栈。
- **盘子类比**：一叠盘子，你只能看最上面的盘子、拿走最上面的盘子、或往上面放新盘子。
- **栈的操作与 LIFO**：
  - 查看栈顶（`top()`，有时叫 `peek()`）；移除栈顶（`pop()`）；压入新项（`push()`）。
  - 栈是**后进先出（LIFO）**：最后压入的最先弹出。数组支持随机访问，栈不支持。压入则增长，弹出则收缩。
- **邮箱类比**：一排固定、钉死、初始为空的邮箱，每个只能装一项。一个标记指示最底部空邮箱：push 填充该格并把标记上移，pop 移除顶部项并把标记下移。标记以下的算"在栈上"，标记及以上的不算。
- **调用栈段**：存放调用栈所用的内存。程序启动时操作系统把 `main()` 压栈，然后开始执行。函数调用时压栈，函数结束时弹出（有时称"展开栈 unwinding the stack"），由此可以看出到达当前执行点所经过的全部函数。
- **栈帧、栈指针**：邮箱对应内存地址，被压入/弹出的"项"是**栈帧（stack frame）**，追踪一次函数调用的全部数据。那个"标记"是 CPU 寄存器，叫**栈指针（stack pointer，SP）**，追踪调用栈顶当前在哪。栈是一块固定大小的内存地址区域。
- **弹出时不做清理**：pop 只把栈指针下移；被弹出帧的内存不必清理或清零，因为它已不在栈上、不会再被访问；之后 push 到该内存会直接覆盖旧值。
- **函数被调用时的步骤**：
  1. 程序遇到函数调用。
  2. 构造并压入栈帧，包含：**返回地址**（调用之后那条指令的地址，让 CPU 知道回来时从哪继续）；所有函数实参；局部变量的内存；被调用者修改且返回时必须恢复的寄存器的副本。
  3. CPU 跳到函数起点。
  4. 函数指令开始执行。
- **函数终止时的步骤**：
  1. 从调用栈恢复寄存器。
  2. 弹出栈帧，释放所有局部变量与参数的内存。
  3. 处理返回值。
  4. CPU 从返回地址继续。
- **返回值的处理**是架构相关的：有些架构把返回值放在栈帧里，有些用 CPU 寄存器。通常不必了解调用栈的全部细节，但理解"调用压栈、返回弹栈"是理解递归和调试的基础。
- **架构差异**：有的架构调用栈朝远离地址 0 的方向增长，有的朝地址 0 增长，所以较新的栈帧地址可能更高或更低。
- **栈大小与栈溢出**：栈大小有限。原文给出"Visual Studio for Windows 默认栈大小是 1MB"，"g++/Clang 在 Unix 变体上最大可达 8MB"。栈溢出发生在栈内存被耗尽、继续分配会溢出到其它内存段时。通常由分配过多栈变量和/或过多的嵌套调用（A 调 B、B 调 C……）造成。在现代操作系统上通常触发访问违规，从而终止程序。
- **栈的优缺点**：
  - 栈分配"相对较快"。
  - 栈内存在其位于栈上时保持在作用域内，弹出时被销毁。
  - 所有栈内存都在编译期已知，因此可以通过变量直接访问。
  - 栈相对较小，避免占用大量栈空间的操作，例如分配或拷贝大数组等。
