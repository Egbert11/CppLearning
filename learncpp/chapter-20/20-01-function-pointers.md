# 20.1 Function Pointers

> 原文：https://www.learncpp.com/cpp-tutorial/function-pointers/

## 核心概念

- **函数指针**：普通指针存变量的地址，函数指针存**函数**的地址。每个函数都有自己的函数类型（返回类型 + 参数），并且函数在内存中有地址，所以函数也是左值。
- **调用即跳转**：用 `operator()` 调用函数，执行流跳转到该函数的地址。
- **裸函数名会退化为函数指针**：不加括号地写函数名，会转换成指向该函数的函数指针。
- **直接打印函数**：标准会把函数指针转换成 `bool`，非空所以符合标准的程序打印 `1`；若想打印地址，可以 `reinterpret_cast<void*>(foo)`，但这是实现定义行为，未必处处可用。
- **非 const 函数指针语法**：`int (*fcnPtr)();`，原文称之为"你见过的最丑的东西之一"。
  - 括号不可省：`int* fcnPtr()` 会被解析为"返回 `int*` 的函数的前向声明"。
  - `const` 要写在星号之后：`int (*const fcnPtr)();`；写在 `int` 前会变成"返回 `const int`"。
- **初始化与赋值**：函数指针可以用函数名初始化/赋值，写 `&foo` 也可以（和变量指针一样）。
  - 常见错误：`fcnPtr = goo();` 赋的是函数调用的返回值，而不是函数地址；不需要括号。
- **类型必须匹配**：函数指针的参数与返回类型必须与函数完全一致。
- **隐式转换**：C++ 会隐式地把函数转换成函数指针（所以 `&` 可省）；但函数指针**不会**与 `void*` 相互转换（虽然部分编译器允许）。
- **空初始化**：函数指针可以用 `nullptr` 初始化或赋值。
- **调用**：显式解引用 `(*fcnPtr)(5)`，或隐式解引用 `fcnPtr(5)`（现代编译器都支持后者）。
- **调用前检查空指针**：指针可能为空，调用前要判断或 `assert`；解引用空函数指针是未定义行为。
- **默认参数不会通过函数指针解析**（Key insight）：默认参数是编译期应用在调用处的，而通过函数指针调用发生在运行期，所以默认参数不生效。
- **消歧用途**：函数指针（或 `static_cast` 到具体函数指针类型）可以用来在因默认参数而二义的重载中指定某一个。
- **回调函数（callback）**：把函数作为参数传给另一个函数，让调用者定制算法的一部分（如排序的比较规则）。
- **泛化选择排序**：把写死的比较换成调用者提供的比较函数，同一个排序例程就能处理升序、降序甚至"奇怪"的顺序。
- **函数类型的形参**：形参声明成函数类型时会自动转换为"指向该函数的指针"；这只适用于形参，其它声明会被当成前向声明。
- **提供默认函数**：可以把标准比较函数作为默认实参，让调用者省略它。
- **类型别名**：用 `using` 让函数指针类型读起来像普通变量。
- **std::function**（`<functional>`）：可以存储可调用对象，签名写在尖括号里（先返回类型，再括号里的参数）。调用只支持隐式解引用 `fcnPtr()`，不支持 `(*fcnPtr)()`。
  - 为 `std::function` 定义类型别名时必须显式写出模板实参（没有初始化器可供推导）。
- **类型推导**：`auto` 可以推导出函数指针类型，语法干净但隐藏了参数与返回类型信息。
- **结论建议**：函数指针主要用于"存储函数"或"把函数作为参数传递"；由于原生语法又丑又容易出错，推荐使用 `std::function`——一次性使用就直接写，重复使用则定义类型别名。

## 最佳实践

本节无 Best practice / Rule / Warning 块。要点提示：

- Tip：部分编译器（如 Visual Studio）有扩展会打印函数地址（如 `0x002717f0`）；想打印地址可用 `void*` 强转。
- Tip：函数指针语法很难解析，原文给出了"螺旋法则"和"右左法则"两篇文章链接。
- Key insight：因为决议发生在运行期，所以通过函数指针调用时默认参数不会被解析。
- 结论建议：原生函数指针语法"又丑又容易出错"，优先使用 `std::function`。
