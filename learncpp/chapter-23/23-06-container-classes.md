# 23.6 Container classes

> 原文：https://www.learncpp.com/cpp-tutorial/container-classes/

## 核心概念

- **现实类比**：正如盒子、文件夹、车库收纳箱用来整理实物，容器的价值在于**整理和存放**放进去的东西。
- **容器类的定义**：它是"一个用来持有并组织另一种类型（另一个类或基础类型）的多个实例的类"。
- **数组是最常见的容器**：C++ 有内建数组，但程序员更常用 `std::array` 或 `std::vector`。
- **容器类为何优于内建数组**：它们通常支持动态改变大小、作为参数传给函数时保持大小信息、并做边界检查——更方便也更安全。
- **标准化的最小功能集**：一个设计良好的容器通常支持：创建空容器、插入对象、移除对象、报告元素个数、清空容器、访问存储的对象，以及可选的排序。
- **可能故意省略某些功能**：数组容器常省略 insert/remove，因为这些操作慢，设计者不想鼓励使用。
- **"member-of" 关系**：元素属于其容器——这里是日常意义的"成员"，而非 C++ 类成员的含义。
- **值容器（value container）**：是一种**组合**，保存被持有对象的副本，因此负责创建与销毁这些副本。
- **引用容器（reference container）**：是一种**聚合**，保存指针或引用，因此不负责被引用对象的创建与销毁。
- **单一类型规则**：C++ 中一个容器通常只持有一种数据类型；不像某些语言那样能任意混合类型——要么写多个容器，要么用模板。
- **本课示例的性质**：示例里的 IntArray 是一个**值容器**，保存元素的副本，类似 `std::vector<int>`。
- **所需数据成员**：它要记录数组数据与长度；因为要支持改变大小，动态分配意味着用指针保存数据。
- **构造函数**：添加两个——一个用于空数组，一个接收预定长度（并用断言确保长度非负）。
- **析构函数与 erase()**：析构函数释放动态内存；`erase()` 释放内存并把指针置空、长度归零，使其不再指向已释放内存。
- **元素访问与大小**：重载 `operator[]`（对下标断言）并提供 `getLength()` 访问函数。
- **reallocate()**：通过 reallocate 改变大小会**销毁**已有元素，但操作很快。
- **resize()**：通过 resize 改变大小会**保留**已有元素，但操作很慢：分配新块、拷贝较短的数组所含的元素、删除旧块。
- **拷贝构造函数**：委托给普通构造函数设置长度，然后拷贝元素。
- **拷贝赋值**：先做自赋值检查，再重新分配为源的长度，然后拷贝元素。
- **insertBefore() 与 remove()**：都模仿 resize()：分配大一个或小一个元素的块，拷贝插入/删除点前后的两段、删除旧块、调整长度。
- **便利包装**：`insertAtBeginning()` 与 `insertAtEnd()` 只是转发给 `insertBefore()`。
- **验证输出**：测试程序打印序列 `40 1 2 3 5 20 6 7 8 30`。
- **写一次，反复用**：容器类可能写起来复杂，但一旦可用，就无需再费力即可复用。
- **改进建议**：改造成支持任意可拷贝类型的模板；添加 const 重载；支持移动语义（移动构造与移动赋值）；resize/insert 时用移动而非拷贝元素。
- **异常安全改进（进阶）**：仅当元素的移动构造函数是 `noexcept` 时才移动，否则拷贝；并让 resize/插入提供强异常安全保证。
- **优先用标准库**：如果标准类满足需求就用它——例如用 `std::vector<int>` 而非手写 IntArray；只有库未覆盖的特殊需求才自写容器。

## 最佳实践

本节无显式的 Best practice / Warning 标注。最接近的是：

- **For advanced readers（异常安全）**：仅当元素的移动构造函数是 `noexcept` 时才移动元素，否则拷贝；并让 resize 或插入操作提供强异常安全保证。
- **收尾建议**：如果标准库的某个类满足需求，就用它，而不是自己写——`std::vector<int>` 被描述为"battle tested, efficient, and plays nicely with the other classes in the standard library"；但了解如何自建容器，在遇到库未覆盖的特殊需求时仍然有用。
