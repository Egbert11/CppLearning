# 23.4 Association

> 原文：https://www.learncpp.com/cpp-tutorial/association/

## 核心概念

- **背景**：前两节课讲了组合与聚合，二者都用更简单的部分搭出复杂对象。
- **关联（association）的定义**：是**不相关对象之间**较弱的关系；**不存在**隐含的整体/部分关系。
- **四条判定标准**：被关联的成员与类**无关**；可以同时属于**多个类**；其存在**不由**该类管理；它"**可能**知道、也可能不知道"对象（类）的存在。
- **与聚合对比**：与聚合一样，被关联对象可属于多个对象、且不受其管理；但不同于聚合的是，关联可以是**单向或双向**（聚合总是单向）。
- **医生/病人示例**：医生看很多病人，病人看很多医生；二者的生命周期互不依赖。
- **"uses-a" 关系**：关联用的动词，对应组合的 "part-of"、聚合的 "has-a"。
- **实现**：关联范围很广，实现方式各异；最常用**指针**，让一个对象指向被关联的对象。
- **方向性建议**："avoid bidirectional associations if a unidirectional one will do"（单向能解决就别用双向），因为双向会带来复杂度和出错风险。
- **自反关联（reflexive association）**：对象与同类型的其他对象相关联；给定例子是课程及其先修课，可形成链条。
- **间接关联**：不一定要用指针或引用；任何能把两个对象联系起来的数据都行（如按 ID 关联的 Driver/Car）。
- **按 ID 关联的取舍**：查找比指针慢，但 ID 能引用当前不在内存中的对象（文件/数据库，需要时再加载），且当唯一对象较少时可省内存。

## 最佳实践

本节无 Best practice / Warning 标注。最接近的是内联指导：**单向能解决就别用双向关联**，因为双向关联更复杂、更易出错。

## 三种关系的对照表

| 性质 | Composition（组合） | Aggregation（聚合） | Association（关联） |
|---|---|---|---|
| 关系类型 | 整体/部分 | 整体/部分 | 互不相关 |
| 成员可属于多个类 | 否 | 是 | 是 |
| 成员的存在由类管理 | 是 | 否 | 否 |
| 方向性 | 单向 | 单向 | 单向或双向 |
| 关系动词 | Part-of | Has-a | Uses-a |
