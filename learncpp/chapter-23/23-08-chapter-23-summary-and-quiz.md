# 23.x Chapter 23 summary and quiz

## 本章知识速览

- **对象组合（object composition）**：用更小的对象搭出更大的对象。它分为两个子类型：**组合（composition）**与**聚合（aggregation）**。
- **组合（composition）**：一种 "part-of" 关系，包含类**拥有并管理**其成员的生命周期。四条条件：成员是类的一部分；同一时刻只属于一个类；由该类管理其存在；成员不知道包含它的类。通常用普通成员变量实现；若类自己处理所有分配/释放，也可用指针。能满足时**优先用组合**。
- **聚合（aggregation）**：一种 "has-a" 关系，类**不**控制成员的生命周期。四条条件：成员是类的一部分；可同时属于多个类；类不管理其存在；成员不知道类存在。用**指针或引用**实现。
- **关联（association）**：更松散的关系，一个类"使用"一个**原本无关**的对象。条件：被关联对象与类无关；可同时属于多个类；类不管理其存在；它"可能或不可能"知道该类存在。用指针/引用实现，或用**间接方式**（如保存键/下标）。
- **依赖（dependency）**：一个类为完成某任务而使用另一个类。被用的类通常**不是成员**；而是在需要时被临时创建并销毁，或从外部作为函数参数传入。
- **容器类（container class）**：持有另一种类型的多个对象的类。**值容器**是一种组合，保存副本；**引用容器**是一种聚合，保存指向外部对象的指针或引用。
- **`std::initializer_list`**：可用于构造函数、赋值运算符及其他接收"列表初始化"参数的函数。定义在 `<initializer_list>` 头文件中。

## 四种关系对照表

| 性质 | Composition | Aggregation | Association | Dependency |
|---|---|---|---|---|
| 关系类型 | 整体/部分 | 整体/部分 | 互不相关 | 互不相关 |
| 成员可属于多个类 | 否 | 是 | 是 | 是 |
| 成员存在由类管理 | 是 | 否 | 否 | 否 |
| 方向性 | 单向 | 单向 | 单向或双向 | 单向 |
| 关系动词 | Part-of | Has-a | Uses-a | Depends-on |

## 测验

1. 判断下列场景各自属于哪种关系：
   - **1a)** `Animal` 类持有一种动物类型（enum）和一个名字（string）。
     - 解答：**Composition（组合）**——类型和名字离开 Animal 就没有用途。
   - **1b)** 一个文本编辑器，其 `save()` 接收一个 `File` 参数，把编辑器内容写盘。
     - 解答：**Dependency（依赖）**——编辑器借助 File 对象来完成保存。
   - **1c)** 一个 `Adventurer` 携带若干 Items（剑、魔杖、药水、法术书），这些 Item 可以被丢弃、也可以被其他 Adventurer 拾取。
     - 解答：**Association（关联）**——没有整体/部分关系，所以不是聚合；Adventurer "uses-a" Item，且不管理其存在。
   - **1d)** 一个 Player 在 Shrine（神龛）前祈祷以获得一种力量。
     - 解答：**Dependency（依赖）**——Player 依赖 Shrine，但与之没有持久联系。
   - **1e)** 一个 `Computer` 内含一个 `CPU`，该 CPU 可以被拆下来单独测试。
     - 解答：**Aggregation（聚合）**——Computer "has-a" CPU，但不控制其生命周期。
   - **1f)** 一个铁匠使用一个特定的铁砧来工作。
     - 解答：**Association（关联）**——他使用铁砧，但没有整体/部分的所有权关系。

2. 如果你可以用组合、聚合、关联、依赖中的一种来设计一个类，应该选哪一种？
   - 解答：**Composition（组合）**。它是最简单、最健壮的关系，整体负责部分的生命周期，使用者无需操心清理。
