# 4.6 Fixed-width integers and size_t

> 原文：https://www.learncpp.com/cpp-tutorial/fixed-width-integers-and-size-t/

## 核心概念

- **整数尺寸只保证最小值**：C++ 只保证整数类型满足最小尺寸；`int` 最小 16 位，但在现代机器上通常为 32 位。
- **假定 32 位 `int` 会在 16 位系统上崩溃**：把需要 32 位的值塞进 16 位 `int`，会得到溢出或未定义行为。
- **假定 16 位 `int` 会浪费空间**：把范围限制在 16 位过于受限，而且当 `int` 实际是 32 位时，有一半内存被闲置。
- **Key insight**：一个函数里创建、销毁几个 `int`，浪费 2 字节无关紧要；但当程序分配数百万个时，这点浪费会显著增加内存占用。
- **为何尺寸不固定**：可追溯到早期 C 语言，那时速度至上；语言故意不固定尺寸，让编译器作者为各架构选择性能最佳的尺寸。
- **固定宽度整数（C++11）**：一组保证在任何架构上尺寸都相同的类型，定义在 `<cstdint>` 头文件中：
  | 名称 | 固定大小 | 固定范围 |
  |---|---|---|
  | `std::int8_t` | 1 字节有符号 | −128 到 127 |
  | `std::uint8_t` | 1 字节无符号 | 0 到 255 |
  | `std::int16_t` | 2 字节有符号 | −32,768 到 32,767 |
  | `std::uint16_t` | 2 字节无符号 | 0 到 65,535 |
  | `std::int32_t` | 4 字节有符号 | −2,147,483,648 到 2,147,483,647 |
  | `std::uint32_t` | 4 字节无符号 | 0 到 4,294,967,295 |
  | `std::int64_t` | 8 字节有符号 | −9,223,372,036,854,775,808 到 9,223,372,036,854,775,807 |
  | `std::uint64_t` | 8 字节无符号 | 0 到 18,446,744,073,709,551,615 |
- **Warning（8 位类型）**：由于 C++ 规范的一个缺陷，现代编译器通常把 `std::int8_t`/`std::uint8_t`（及其 fast/least 对应类型）当作 `signed char`/`unsigned char`，即“8 位固定宽度类型常被当成 char 而非整数值”。16 位及以上类型不受影响。
- **进阶细节**：固定宽度类型并不定义新类型，而是按实现选择的现有整型的别名。通常 `std::int8_t` 是 `signed char` 的别名（因为它是唯一的 8 位有符号整型）。
- **固定宽度类型的缺点**：并非在所有架构上都保证存在（所需宽度不受支持时程序无法编译——但已标准化于 8/16/32/64 位，故很少见）；在某些 CPU 上可能比更宽的类型慢，不过内存限制往往比 CPU 速度更重要。这两点都被称为小问题。
- **快速类型（fast）**：`std::int_fast#_t` / `std::uint_fast#_t`，给出“处理最快”的、宽度至少为 # 位的有符号/无符号类型（# = 8/16/32/64）。
- **最小类型（least）**：`std::int_least#_t` / `std::uint_least#_t`，给出“至少 # 位且最小”的有符号/无符号类型。
- **它们的尺寸由实现定义**：作者的 Visual Studio 32 位控制台程序里，`std::int_least16_t` 是 16 位，而 `std::int_fast16_t` 是 32 位（因为在此处 32 位处理更快）。在只有 16 位与 64 位类型的架构上，`std::int32_t` 不存在，但 fast/least 的 32 变体会是 64 位。
- **fast/least 的缺点**：很少程序员使用（不熟悉易出错）；fast 类型可能浪费内存；最严重的是其实现定义的尺寸会跨架构改变程序行为——而这恰恰是固定宽度类型想避免的。
- **整体最佳实践**：宁可正确也不要盲目求快，宁要编译期失败也不要运行期失败；需要保证范围时用固定宽度类型而非 fast/least 类型，日后只有在遇到奇特平台时才迁移。
- **`std::size_t`**：`sizeof` 运算符返回的值类型就是 `std::size_t`。它被定义为“某个实现定义的无符号整型的别名”，由编译器选择（如 unsigned int、unsigned long 等），并“在标准库中用于表示对象的字节大小或长度”。它实际上是一个 typedef。
- **定义处**：`std::size_t` 出现在多个头文件中；推荐用 `<cstddef>`，因为它声明的其他标识符最少。仅使用 `sizeof` 本身不需要头文件。
- **它的尺寸**：`std::size_t` 保证无符号且至少 16 位；在多数系统上与应用程序的地址宽度一致（32 位程序为 32 位，64 位程序为 64 位）。
- **可选——测量自身**：可以用 `sizeof` 测 `std::size_t` 自身；作者的 32 位控制台程序打印 `4`。
- **可选——对象大小上限**：由于 `sizeof` 必须以 `std::size_t` 返回字节大小，任何对象都不能大于 `std::size_t` 的最大值。C++20 标准规定：构造对象表示字节数超过 `std::size_t` 最大值的类型是 ill-formed。4 字节 `std::size_t` 下，没有对象能超过 4,294,967,295 字节。
- **旁注（可选）**：这只是严格的数学上限；实际限制可能更低——有些编译器只允许最大值的一半，可用的连续内存也会限制。这在 8/16 位时代是真实约束，如今很少成问题。

## 最佳实践

- 需要保证范围的整型时，使用固定宽度整数类型。
- 若显式使用 `std::size_t`，请包含定义它的头文件之一，推荐 `<cstddef>`。
- 避免 fast 与 least 整型，因为它们（在其解析尺寸不同时）可能表现出不同行为。
- 选择整型时的推荐：
  - 尺寸无关时优先用 `int`（例如表示年龄、从 1 数到 10）——涵盖大多数情况。
  - 需要保证范围时用 `std::int#_t`。
  - 位操作或需要良定义回绕（加密、随机数生成）时用 `std::uint#_t`。
- 尽可能避免：`short` 与 `long`；fast 与 least 类型；用无符号类型保存数量；8 位固定宽度类型；任何编译器特定的固定宽度类型（如 Visual Studio 的 `__int8`）。
