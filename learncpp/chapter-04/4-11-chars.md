# 4.11 Chars

> 原文：https://www.learncpp.com/cpp-tutorial/chars/

## 核心概念

- **`char` 的用途**：用于存储单个字符。字符指单个字母、数字、符号或空白。
- **`char` 是整型**：它存储的值是整数，正如布尔值把 0/非 0 映射为 false/true 一样。`char` 里存的整数被解释为一个 ASCII 字符。
- **ASCII 定义**：American Standard Code for Information Interchange，把英文字母及部分符号映射为 0–127 的整数。每个映射称为一个 ASCII 码 / 码点，例如 97 对应 `'a'`。
- **字符字面量语法**：用单引号括起，如 `'g'`、`'1'`、`' '`。
- **不可打印码与可打印码**：码 0–31 和 127 是控制码（最初用于驱动打印机等外设），大多已过时；码 32–126 是可打印的字母、数字与标点。
- **超出范围的输出**：打印 ASCII 范围之外的字符，结果取决于操作系统。
- **推荐的初始化**：用字符字面量，如 `char ch2{ 'a' };`。
- **不推荐的初始化**：用普通整数初始化虽然可行，但应避免，如 `char ch1{ 97 };`。
- **不要把数字和字符混淆**：整数 `5` 与字符 `'5'` 不同（`'5'` 存为 53）。字符数字用于把数字显示为文本，不用于算术。
- **打印**：`std::cout` 按 ASCII 字符而非底层数字来显示 `char`；也可以直接输出字符字面量，如 `std::cout << 'c';`。
- **输入行为**：`char` 变量只接受一个字符，因此 `std::cin` 只提取第一个字符，剩余输入留在输入缓冲区供后续提取。
- **多字符用字符串**：要读名字、单词或句子应使用字符串（见 5.7 课）而非 `char`。
- **空白提取问题**：因为 `operator>>` 会跳过前导空白，把空格提取到 `char` 里不会如愿——它会提取后面的字符。
- **`std::cin.get()`**：该函数不跳过前导空白，是提取空白字符的简单办法。
- **大小与符号**：`char` 永远是 1 字节；默认可能是有符号或无符号，通常是有符号。若只存 ASCII，无需符号说明符。
- **小整数范围**：有符号 char 为 -128~127，无符号 char 为 0~255。只有在明确为节省空间而优化时才用 `char` 存小整数。
- **转义序列**：以反斜杠开头、后跟字母或数字的特殊字符序列，最常见的是 `'\n'`。
- **其他常见转义**：`'\t'` 水平制表符；`\'`、`\"`、`\\` 分别表示单引号、双引号、反斜杠。
- **转义序列表**：`\a`(响铃)、`\b`(退格)、`\f`(换页)、`\n`(换行)、`\r`(回车)、`\t`(水平制表)、`\v`(垂直制表)、`\'`、`\"`、`\\`、`\?`(已不再需要)、`\(数字)`(八进制)、`\x(数字)`(十六进制)。
- **单引号与双引号**：单引号产生表示一个字符的 `char` 字面量；双引号产生可含多个字符的 C 风格字符串字面量。
- **多字符字面量**：`'56'` 这类字面量编译器可能为向后兼容而接受，但其值是实现定义的，应当避免。
- **其他字符类型**：`char16_t`、`char32_t`（C++11）分别支持 16、32 位 Unicode 字符；`char8_t`（C++20）支持 UTF-8，表示方式等同 `unsigned char`。Unicode 码点超过 144000 个，需要直接用 UTF-32，或使用 UTF-16/UTF-8 编码。
- **实用建议**：处理字符和字符串时只使用 ASCII 字符；其他字符集可能显示异常。除与 Windows API 交互外应避免 `wchar_t`，因为它的大小是实现定义的。

## 最佳实践

- **Best practice**：单个字符通常用单引号而非双引号（例如用 `'t'` 或 `'\n'`，而不是 `"t"` 或 `"\n"`）。例外是输出时，为保持一致可以全部用双引号。
- **Best practice**：避免多字符字面量（如 `'56'`）。
- **Warning**：注意不要把字符数字与整数数字混淆，`char ch{5};` 与 `char ch{'5'};` 并不相同。
- **Warning**：转义序列以反斜杠开头，而不是正斜杠。用正斜杠“可能仍能编译，但不会得到期望结果”。
- **Warning**：确保换行使用转义序列 `'\n'`，而不是多字符字面量 `'/n'`。
- **Key insight**：若把 `"/n"` 用双引号书写，程序本会打印 `3/n`——仍然错误，但远没那么令人困惑。
