## 核心概念

- **复合语句 / 块**：编译器当作单条语句处理的一组（零条或多条）语句。块以 `{` 开始、`}` 结束，末尾不需要分号，可出现在任何允许单条语句之处，常与 `if` 搭配。
- **用户自定义命名空间**：你为自己的声明创建的命名空间。C++ 自身的（全局命名空间）或库的（`std`）不算"用户自定义"。
- **作用域解析运算符（`::`）**：用来访问命名空间中的声明；右操作数在左操作数的作用域中查找。左侧为空时默认是全局命名空间。
- **局部变量**：在函数内定义（含形参）。具有**块作用域**（从定义点到块末尾可用）与**自动存储持久期**（定义时创建、块末销毁）。
- **遮蔽 / 名称隐藏（shadowing / name hiding）**：嵌套块中的名字可隐藏外层同名变量，应避免。
- **全局变量**：在任何函数外定义。具有**文件作用域**（从声明点到文件末尾可见）与**静态持久期**（程序启动时创建、结束时销毁）。应尽量避免静态变量的动态初始化。
- **链接性（linkage）**：决定一个名字的其它声明是否指向同一对象。局部变量无链接；**内部链接**表示仅本文件可用；**外部链接**表示在定义文件及（经前向声明后）其它文件中可用。
- **全局变量指导**：应尽量避免非 const 全局变量；const 全局变量一般可接受。在支持 C++17 的编译器上，全局常量使用**内联变量**。
- **静态局部变量**：用 `static` 关键字可让局部变量获得静态持久期。
- **限定名与非限定名**：限定名带作用域（如 `std::string`）；非限定名不带（如 `string`）。
- **using 语句**：**using 声明**把某个限定名作为无限定使用的别名；**using 指令**把某命名空间的所有标识符引入当前作用域。两者一般都应避免。
- **内联展开（inline expansion）**：调用被替换为被调函数的定义代码；标了 `inline` 的函数即**内联函数**。
- **内联函数/变量的两个要求**：① 使用它的每个翻译单元都必须看到完整定义（仅有前向声明不够；若有前向声明，定义可出现在使用点之后）；② 所有定义必须完全相同，否则行为未定义。
- **inline 的现代含义**：现在表示"允许多个定义"。C++17 增加了**内联变量**，即允许在多个文件中定义的变量。
- **仅头文件库（header-only library）**：由一个或多个头文件实现某功能、不含配套 `.cpp` 的库；内联函数/变量在此特别有用。
- **匿名与内联命名空间**：匿名命名空间使其内容隐式获得内部链接；内联命名空间提供一种朴素的命名空间版本管理。

## 本章知识速览

- **块/复合语句**：把多条语句当作一条；`{ }` 包裹，无末尾分号。
- **命名空间与 `::`**：命名空间把名字分组；`::` 访问其中声明，左侧为空表示全局命名空间。
- **作用域 / 持久期 / 链接性**：作用域决定"哪里能访问"，持久期决定"何时创建销毁"，链接性决定"不同作用域的同名声明是否指向同一实体"（见 7.12 总表）。
- **局部变量**：块作用域 + 自动持久期 + 无链接。
- **全局变量**：文件作用域 + 静态持久期；const 全局为内部链接，非 const 全局为外部链接；非 const 全局一般应避免。
- **静态局部变量**：块作用域但静态持久期，跨调用保留值；初始化器只执行一次；非 const 的静态局部变量一般应避免。
- **链接性**：内部链接（`static` 全局/函数、const 全局、匿名命名空间）；外部链接（非静态函数、非 const 全局、`extern`/`inline` const 全局、命名空间）。
- **前向声明**：变量前向声明必须不初始化；不允许 `extern constexpr`；constexpr 变量经 const 前向声明后只被当作 const。
- **存储类说明符**：`extern`、`static`、`thread_local`、`mutable`（`auto`、`register` 已弃用）。
- **inline**：现代含义为"允许多个定义，但定义须处处可见且完全相同"；适合仅头文件库。`constexpr` 函数隐式内联，`constexpr` 变量不隐式内联。
- **共享全局常量**（C++17）：优先在头文件中用 `inline constexpr` 定义。
- **using 语句**：优先显式限定名；using 声明可在 `.cpp` 中 `#include` 之后使用；避免 using 指令（`using namespace std::literals` 例外）；不要放进头文件。
- **匿名 / 内联命名空间**：匿名命名空间的内容为内部链接（勿用于头文件）；内联命名空间用于版本管理，不改变链接性。

## 测验

- **Q1**：下面的程序为什么不能正确工作？修复它。
  - 参考：[7-15-quiz1.cpp](7-15-quiz1.cpp)。缺陷在于 `num = -num;` 那条语句位于 `if` 之外，因此总会执行。修法是给 `if (num < 0)` 补上 `{ }`，让"打印提示"与"取负"两条语句都受条件控制。
- **Q2**：编写一个 `constants.h`，使得下面给出的 `main.cpp` 能编译并运行，且 `Constants::maxClassSize` 等于 `35`。若编译器支持 C++17 用 `inline constexpr`，否则用普通 `constexpr`。
  - 参考：[7-15-quiz2/constants.h](7-15-quiz2/constants.h) 与 [7-15-quiz2/main.cpp](7-15-quiz2/main.cpp)。头文件用 include guard，并定义 `namespace Constants { inline constexpr int maxClassSize{ 35 }; }`。`main.cpp` 原样保留，提示输入班级人数并与 `Constants::maxClassSize` 比较，输出 "There are too many students in this class" 或 "This class isn't too large"。
- **Q3**：编写函数 `int accumulate(int x)`，返回截至当前所有传入值的累计和。提示：用静态局部变量保存和。
  - 参考：[7-15-quiz3.cpp](7-15-quiz3.cpp)。用 `static int sum{ 0 };` 然后 `sum += x; return sum;`，依次调用 `accumulate(4)`、`(3)`、`(2)`、`(1)` 输出 4、7、9、10（每行一个）。
- **Q3b（附加题）**：上面的 `accumulate()` 有两个缺点。
  1. 没有常规办法在不重启程序的情况下**重置**累计。
  2. 没有常规办法**同时运行多个**累加器。
  - 对进阶读者：这两个缺点都可改用仿函数（重载括号运算符）而非静态局部变量来解决。
