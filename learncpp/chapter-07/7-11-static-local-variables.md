# 7.11 Static local variables

> 原文：https://www.learncpp.com/cpp-tutorial/static-local-variables/

## 核心概念

- **`static` 的含义随语境而变**：它出现在不同位置有不同含义，这正是它常令人困惑的原因。
- **全局变量具有静态持久期**：程序启动时创建、结束时销毁。
- **对全局标识符加 `static` → 内部链接**：该标识符只能在定义它的文件内使用。
- **局部变量默认为自动持久期**：在定义点创建，离开所在块时销毁。
- **对局部变量加 `static` → 自动持久期改为静态持久期**：变量在程序启动时创建、程序结束时销毁，因此离开作用域后仍保留其值。
- **初始化时机**：被零初始化或具有 constexpr 初始化器的静态局部变量，可在程序启动时初始化。
- **无初始化器或非 constexpr 初始化器**：这类静态局部变量在程序启动时被零初始化；非 constexpr 初始化器会在首次执行到该定义时运行一次，之后再次到达该定义会跳过，不再重新初始化。未初始化的静态局部变量默认零初始化。
- **ID 生成器用例**：静态局部变量常用于唯一 ID 生成器，使大量对象各得一个不同标识，便于调试。
- **作用域与生命期**：静态局部变量具有块作用域（像普通局部变量），但生命期延续到程序结束（像全局变量）。
- **静态局部常量**：静态局部变量可以是 `const` 或 `constexpr`；常见用法是把创建代价高的值（如从数据库读取）只构建一次、跨调用复用。
- **避免用静态局部变量改变控制流**：函数带有隐藏内部状态、在后续调用中行为不同，会让读者困惑并妨碍复用；教程的 `getInteger()` 就是例子。
- **复用问题**：`getInteger()` 持有外部无法重置的状态（`s_isFirstCall`），因此不可复用——加上"减法"路径后提示语就错乱了。
- **首选修法**：把标志（更好是把提示文本）作为参数传入，让调用者控制行为。

## 最佳实践

- **Best practice**：初始化你的静态局部变量——它们只在代码首次执行时初始化一次，之后不再初始化。
- **Best practice**：**const 静态局部变量一般可以放心使用**；非 const 的静态局部变量一般应避免；若确实使用，必须永不需重置、且不得用来驱动程序流程。
- **Tip**：如同全局变量常加 `g_` 前缀，静态（静态持久期）局部变量习惯加 `s_` 前缀。
- **Tip**：更可复用的做法是接受一个 `std::string_view` 形参，由调用者提供提示文本。
- **对进阶读者**：当需要多个彼此独立、各自保留值的实例（如多个 ID 生成器）时，仿函数（functor）是更好的方案。
- **关键要点**：静态局部变量在"局部变量必须跨函数调用记住其值"时使用；它具有块作用域而生命期像全局变量延伸到程序结束；最擅长避免每次调用都重复进行代价高昂的初始化。
