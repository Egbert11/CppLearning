# 14.7 Member functions returning references to data members

> 原文：https://www.learncpp.com/cpp-tutorial/member-functions-returning-references-to-data-members/

## 核心概念

- **返回引用的回顾**：函数返回的引用必须在函数返回后仍然有效；返回局部变量的引用会悬垂，不安全。
- **可安全返回引用的对象**：引用参数以及具有静态存储期（静态局部变量或全局变量）的对象通常安全，因为函数退出时它们不会被销毁。
- **成员函数适用同样的规则**，但多出一种情形：成员函数返回自身某个数据成员的引用。
- **按值返回数据成员虽安全但昂贵**：每次调用都会拷贝一份成员，而访问函数往往被频繁调用，因此通常不是最好的选择。
- **按 (const) 左值引用返回数据成员通常安全**：数据成员与所属对象同生命周期，而成员函数总是作用于调用者作用域中存在的对象上，因此返回的引用在该作用域内保持有效。
- **Key insight**：返回对数据成员的 const 左值引用是没问题的，因为隐式对象在函数返回后仍存在于调用者作用域中，返回的引用因此持续有效。
- **返回类型应与数据成员类型一致**：返回不同类型（如对 `std::string` 成员返回 `std::string_view`）会在每次调用时创建并返回一个临时对象，低效；需要时可由调用者自行转换。
- **用 `auto` 推导返回类型**：让编译器从成员推导可确保不发生转换，但对文档读者隐藏了真实类型，因此一般仍偏好显式写出返回类型。
- **右值隐式对象**：当隐式对象是右值时（例如函数按值返回的对象），它在创建它的完整表达式结束时被销毁；此后对其成员的引用悬垂，使用它们是未定义行为。
- **对右值成员引用的安全用法**：只能在创建该右值对象的同一个完整表达式内使用。
- **Key insight（完整表达式）**：完整表达式的求值在其作为初始化器的使用处结束，这正是允许用同类型右值初始化对象的原因。
- **需长期保存返回的引用时**：用返回的引用初始化一个**非引用**局部变量，这样会拷贝该成员，局部变量即独立于（可能已被销毁的）右值。
- **约定**：尽管存在右值风险，getter 惯例上对拷贝昂贵的类型仍按 const 引用返回，而不是按值返回。
- **安全用法三原则**：优先立即使用返回的引用（左值和右值对象都适用）；除非确定隐式对象是左值，否则不要"保存"返回的引用以备后用；若必须保存且不确定，则拷贝到非引用局部变量。
- **不要返回私有数据成员的非 const 引用**：引用等同于被引用对象，交回非 const 引用会让调用者直接改写成员，从而绕过访问控制系统。
- **const 成员函数不能返回成员的非 const 引用**：const 成员函数不得修改状态，也不得让他人得以修改，交回非 const 引用会违背这一意图。

## 最佳实践

- **Key insight**：返回数据成员的 (const) 左值引用是可以的，因为隐式对象在函数返回后仍存在于调用者作用域中。
- **Best practice**：返回引用的成员函数，其返回类型应与被返回的数据成员的类型相同，以避免不必要的转换。
- **Warning**：右值对象在其创建所在的完整表达式结束时被销毁，对其成员的引用会悬垂；此类引用只能在同一完整表达式内安全使用。
- **Key insight**：完整表达式的求值在其作为初始化器的使用处结束，因此可以用同类型右值初始化对象。
- **Best practice**：优先立即使用返回引用的成员函数的返回值，这样当隐式对象为右值时也不会出现悬垂引用问题。
- **Tip**：关于"完整表达式"的定义见 1.10 — Introduction to expressions。
- **注意**：不要返回私有数据成员的非 const 引用（见原 Example 6），否则调用者可直接改写成员、绕过访问控制。
