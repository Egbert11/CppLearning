# 14.3 Member functions

> 原文：https://www.learncpp.com/cpp-tutorial/member-functions/

## 核心概念

- **struct 可以存放成员变量**：`struct Date` 里放三个 `int`（`year/month/day`），另有一个非成员函数 `print()` 接收 `const Date&` 把它们打印出来。
- **现实对象的属性与行为不可分割**：现实对象有可观察的属性，也有作用于它或由它发出的行为；在代码里属性对应变量、行为对应函数。
- **朴素做法把它们拆开了**：第一个例子里 `Date` 的属性和 `print()` 这个行为分隔两地，读者只能从 `const Date&` 形参去推断两者的关系。
- **命名空间只是部分补救，却让代码更啰嗦**：把 `Date` 与 `print()` 装进命名空间会多出不少名字与前缀。
- **定义——成员函数（member function）**：属于某个类类型的函数；类类型包括 struct、class、union。
- **旁注——"方法（methods）"**：其它面向对象语言（Java、C#）用"方法"一词，C++ 不使用该术语，但新手可能仍会这么叫。
- **定义——非成员函数（non-member / free function）**：任何不是成员函数的函数，例如原来的 `print()`。
- **声明/定义规则**：成员函数必须在类类型定义内部**声明**，可以在类内或类外**定义**；定义同时也是声明，所以在类内定义即等于声明。
- **隐式内联**：在类定义内部定义的成员函数是隐式 inline 的，因此把该定义放进多个文件也不会违反单一定义规则（ODR）。
- **调用语法**：成员函数用成员选择运算符选取，与访问成员变量一致（`today.day = 16;`、`today.print();`）。
- **所有非静态成员函数都需要对象**：它们必须通过该类型的某个对象来调用。
- **定义——隐式对象（implicit object）**：成员函数被调用时作用其上的那个对象，它是隐式传入而非显式实参。
- **成员函数内部如何访问成员**：任何不带成员选择运算符的成员标识符都关联到隐式对象；带前缀的（如 `person.name`）则指向那个具名对象。
- **Key insight（非成员 vs 成员）**：非成员函数需要显式传入对象并通过它访问成员；成员函数则隐式传入对象并隐式访问其成员。
- **可读性收益**：写成 `kisses(joe, kate)` 不如成员形式 `joe.kisses(kate)` 易读，后者能看出哪个对象发起行为、哪个对象作为受动方。
- **类内顺序无关**：不同于非成员（必须先声明后使用），类内的成员可以相互"先用后声明"，数据成员与成员函数可任意排列。
- **Warning——初始化顺序**：数据成员按**声明顺序**初始化。用稍后声明的成员（直接或经由函数）去初始化某个成员会导致未定义行为；不要在默认成员初始化器里使用其它成员。
- **进阶读者细节**：编译器会隐式前置声明在类内定义的成员函数，并把这些定义挪到类定义之后，这样编译函数体时整个类已经可知。
- **重载**：成员函数可以重载，只要能互相区分，例如 `print()` 与 `print(std::string_view prefix)`。
- **struct 与成员函数**：C 的 struct 只有数据成员；Bjarne Stroustrup 决定 C++ 的 struct 也应有成员函数，最终统一了 struct 与 class 的规则（用法差别只来自约定而非规则）。
- **聚合体注意**：struct 应避免定义构造函数，因为带构造函数的类类型不再是聚合体。
- **没有数据成员的类类型**：只有成员函数的类类型是可行的，但更推荐用"含非成员函数的命名空间"——它表明这里不管理数据、也不需要对象。

## 最佳实践

- **Best practice**：成员函数既可以用于 struct 也可以用于 class。但 struct 不应定义构造函数（一旦定义就不再是聚合体）。
- **Best practice**：如果你的类类型没有数据成员，优先使用命名空间。
- **Warning**：数据成员按声明顺序初始化；在默认成员初始化器里使用尚未初始化的后续成员会导致未定义行为，务必避免。
- **Author's note**：本节用 struct 演示成员函数，但这些内容同样适用于 class；带成员函数的 class 会在 14.5 出现。
