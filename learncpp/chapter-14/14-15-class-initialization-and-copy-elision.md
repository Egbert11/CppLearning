# 14.15 Class initialization and copy elision

> 原文：https://www.learncpp.com/cpp-tutorial/class-initialization-and-copy-elision/

## 核心概念

- **六种初始化形式**：对基础类型有默认、拷贝、直接、直接列表、拷贝列表、值初始化六种。本节指出这些形式对类类型同样有效。
- **现代 C++ 的相似性**：拷贝、直接、列表初始化"本质上做同一件事——初始化一个对象"。
- **类类型的构造函数选择**：编译器查看类的构造函数，用重载决议选出最佳匹配，其间可能涉及隐式实参转换。
- **非类类型的匹配**：由隐式转换规则决定是否存在可用的转换。
- **三种关键差异**（Key insight）：列表初始化不允许窄化转换；拷贝初始化只考虑非 explicit 的构造函数/转换函数；列表初始化优先选择列表构造函数。
- **上下文限制**：某些初始化形式在某些上下文中被禁止；例如构造函数成员初始化列表只能用直接形式，不能用拷贝初始化。
- **不必要的拷贝**：`Something s { Something { 5 } };` 通常会先构造一个临时对象，再拷贝构造 `s`；而 `Something s { 5 };` 只调用 `Something(int)`，得到相同结果。
- **拷贝消除（copy elision）的定义**："拷贝消除是一种编译器优化技术，允许编译器移除对象不必要的拷贝。"当拷贝构造调用被移除时，称该构造函数被消除（elided）。
- **不适用 as-if 规则**：拷贝消除即使对带有副作用的拷贝构造函数也会消除其拷贝，因此拷贝构造函数不应有除拷贝之外的副作用。
- **按值传参与按值返回**：这些上下文中的拷贝可能被消除。在 C++14 或更早、关闭消除时，示例会调用拷贝构造函数 4 次；Visual Studio 2022 消除其中 3 次，GCC 消除全部 4 次。
- **实用建议**：不要死记消除何时发生；如果预期的拷贝构造调用没有出现，很可能就是拷贝消除。
- **C++17 的强制消除**：C++17 之前拷贝消除是可选的；C++17 起在部分情形变为强制，即使告诉编译器不要执行。
- **可选 vs 强制的要求**：可选消除即使调用被消除，仍要求拷贝构造函数可访问；强制消除即使在拷贝构造函数被删除时也能进行。
- **进阶说明**：如果可选的拷贝消除没有执行，移动语义可能允许"移动"而非"拷贝"。

> **Key insight**：三种初始化形式的差异在于——列表初始化禁止窄化转换；拷贝初始化只考虑非 explicit 的构造函数/转换函数；列表初始化优先考虑列表构造函数。
