# 14.14 Introduction to the copy constructor

> 原文：https://www.learncpp.com/cpp-tutorial/introduction-to-the-copy-constructor/

## 核心概念

- **拷贝构造函数（copy constructor）的定义**："一个用于以一个同类型已有对象来初始化某对象的构造函数。"
- **拷贝的结果**：拷贝构造函数运行后，新对象应当是被初始化对象的副本。
- **隐式拷贝构造函数**："如果你不为自己的类提供拷贝构造函数，C++ 会为你创建一个公开的隐式拷贝构造函数。"
- **逐成员初始化（memberwise initialization）**："默认情况下，隐式拷贝构造函数执行逐成员初始化。"每个成员都从源对象的对应成员初始化。
- **自定义拷贝构造函数**：可以自己定义，形如接受同类型 `const` 引用的构造函数。
- **访问控制提醒**："访问控制按类生效（而非按对象生效）。"成员函数可以访问同类任意对象的私有成员。
- **只做拷贝**："拷贝构造函数除了拷贝对象不应做别的事。"编译器可能把拷贝构造调用优化掉。
- **优化警告**："如果你依赖拷贝构造函数实现拷贝以外的某种行为，该行为可能发生也可能不发生。"
- **参数规则**："拷贝构造函数的参数必须是左值引用或 const 左值引用。"
- **优先 const**："因为拷贝构造函数不应修改参数，所以优先使用 const 左值引用。"
- **按值传参**："当对象按值传递时，实参被拷贝进形参。""当实参与形参为同一类类型时，拷贝通过隐式调用拷贝构造函数完成。"
- **按值返回**：按值返回会创建临时对象；"该临时对象通过隐式调用拷贝构造函数来初始化"。
- **拷贝消除（copy elision）**：编译器可能消除某些拷贝构造调用；这项优化称为拷贝消除，被消除的调用称为"被 elide"。
- **`= default`**：显式请求编译器生成默认拷贝构造函数。
- **`= delete`**：把拷贝构造函数标记为删除，禁止拷贝；尝试拷贝会导致编译错误。
- **私有拷贝构造函数**：可阻止公开拷贝，但类成员仍能使用它。
- **三法则 / 五法则（Rule of three / five）**：若一个类需要自定义拷贝构造函数、析构函数或拷贝赋值运算符中的任何一个，很可能三个都需要。C++11 把这条规则扩展为"五法则"：再加上移动构造函数与移动赋值运算符。
- **测验答案**：拷贝构造函数的参数不能按值传递，因为那样拷贝构造函数将需要调用自身来拷贝实参，导致无限递归——"这会形成对拷贝构造函数的无限调用链。"

## 最佳实践

- **Best practice**："拷贝构造函数除了拷贝不应产生其他副作用。"
- **Best practice**："除非有特定理由要自己写，否则优先使用隐式拷贝构造函数。"
- **Best practice**："如果你自己写拷贝构造函数，参数应当是 const 左值引用。"
- **As an aside**：把拷贝构造函数设为私有可以阻止公开拷贝，但私有成员函数仍可使用它。
- **For advanced readers**：三法则 / 五法则的讨论；不遵守它们可能导致代码运行故障。
