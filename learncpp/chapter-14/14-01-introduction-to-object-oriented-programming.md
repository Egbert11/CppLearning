# 14.1 Introduction to object-oriented programming

> 原文：https://www.learncpp.com/cpp-tutorial/introduction-to-object-oriented-programming/

## 核心概念

- **对象与变量回顾**：对象是"一块可以存储值的内存"；当它有了名字，就叫变量。此前的程序都是一步一步的指令，先定义数据、再定义对数据的操作。
- **过程式编程（procedural programming）**：重心在"过程"——C++ 里叫函数——它们承载程序逻辑。数据被交给这些函数，函数作用于数据并可能返回结果。
- **数据与函数分离的问题**：这种风格下函数与它们操作的数据是两样东西，程序员必须手动把它们组合起来，写出 `eat(you, apple);` 这样的调用。
- **为什么它不能很好地对现实建模**：现实中的对象都同时具有属性（重量、颜色、大小……）与行为（被打开、加热东西……），二者不可分割。属性对应对象、行为对应函数，过程式写法就把本该在一起的东西拆开了。
- **面向对象编程（OOP）**：重心变成定义程序自定义的数据类型，这种类型同时持有属性（properties）与一组定义好的行为（behaviours）；此语境下的"对象"指的是由这些类型实例化出的实例。
- **调用风格的改变**：不再是把所有东西都当参数传进去，而是写成 `you.eat(apple);`，明确地表达出主语、被调用的行为以及附属对象。
- **把属性与行为打包的好处**：对象更容易模块化，程序更易编写与理解，复用性提高，对象自身以及对象之间的交互都可以被显式定义。
- **扩充代码——过程式版本**：新增一个 `snake` 需要改动 `AnimalType` 枚举、`numLegs()`、`animalName()`，在大代码库里还要动其它所有使用 `AnimalType` 的函数——极易出错（breakage）。
- **扩充代码——OOP 版本**：每种动物都是自己的类型、拥有一切相关信息，加一条蛇只是新增一个类型，几乎不改动既有代码。
- **重复问题的提醒**：每只动物一个 struct 的做法会重复相同的成员，因此也可以用一个共享的 `Animal` struct 来实例化；但"一种动物一个类型"的模型允许某个成员只属于某一种动物（原文的例子是 `Chicken` 上的 `wormsPerDay`）。
- **真实项目中的模块化**：学校作业产出正确输出就算完成，但放进代码仓库或交付给用户的应用还必须经受操作系统/软件变化、用户发现的逻辑错误、新的业务需求，以及由其他开发者扩展等的考验，而且要求花的时间、痛苦和破坏都尽可能小。
- **另外四个 OOP 工具**：保持代码模块化、不冗余还得益于继承（inheritance）、封装（encapsulation）、抽象（abstraction）、多态（polymorphism），这些将在后续章节介绍。
- **OOP 是补充而非替代**：它是一套处理复杂度的额外工具，并不取代过程式编程。
- **"对象"一词的重载**：传统含义只是一块存值的内存区域；OOP 含义则在此之上加了打包好的属性与行为。本系列教程沿用传统含义，说到 OOP 含义时会写"类对象（class object）"。

> 原文另有两条纯示意的一行伪代码：过程式为 `eat(you, apple);`，OOP 为 `you.eat(apple);`。它们依赖未定义的实体、无法编译，因此未单独生成源码文件。

## 最佳实践

- 本节无 Best practice / Rule / Warning 条目。原文唯一的方框是 **Author's note**：调侃语言设计者的"能用大词就不用小词"哲学（"Also why is the word abbreviation so long?"），并说明四个 OOP 概念将在后续章节讲解；一旦理解 OOP，多半就不再想回到纯过程式编程——但它并非替代，只是给管理复杂度多加了一套工具。
