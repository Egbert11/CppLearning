# 14.11 Default constructors and default arguments

> 原文：https://www.learncpp.com/cpp-tutorial/default-constructors-and-default-arguments/

## 核心概念

- **默认构造函数（default constructor）**：不接受任何实参的构造函数，通常以空形参列表定义。
- **类类型的值初始化 vs 默认初始化**：若类有默认构造函数，`Foo foo{}` 与 `Foo foo2;` 都会调用它；对这类类而言两种写法等价。
- **更安全的选择**：值初始化对聚合体更安全，而聚合体与非聚合体一眼难以区分，因此统一使用值初始化。
- **带默认实参的构造函数**：与普通函数一样，构造函数最右侧的形参可以带默认实参。
- **全部形参都有默认值 ⇒ 默认构造函数**：若每个形参都有默认值，该构造函数也算默认构造函数，因为它可被无实参调用。
- **重载构造函数**：构造函数也是函数，一个类可定义多个以支持不同的构造方式。
- **只能有一个默认构造函数**：由重载规则可推出——若有两个默认构造函数，编译器无法选择，会报调用有歧义的错误。
- **隐式默认构造函数**：非聚合类若没有任何用户声明的构造函数，编译器会生成一个 public 的默认构造函数，使对象可被值初始化或默认初始化。
- **隐式版本的样子**：等价于一个无参、无成员初始化列表、函数体为空的构造函数。
- **隐式版本何时有用**：主要对有数据成员的类没什么用——这类类通常需要用户提供数值；它主要用于没有数据成员的类。
- **`= default`**：即"显式默认化的默认构造函数"，即使类中已有其它用户声明的构造函数，也要求编译器生成一个默认构造函数。
- **差异一：零初始化**：若默认构造函数是**用户提供**的，值初始化只会默认初始化对象；若是隐式定义或 `= default` 的（非用户提供），值初始化会先零初始化再默认初始化。
- **差异二：聚合体（C++20 前）**：C++20 之前，用户定义的默认构造函数会让类成为非聚合体，而 `= default` 不会；C++20 起两者都使类成为非聚合体。
- **聚合体/性能提示**：对没有用户提供默认构造函数的类，默认初始化可能比值初始化快，但不够安全；空函数体的构造函数能避免零初始化，却可能挡住其它优化。
- **只在合理时才定义默认构造函数**：默认构造函数让对象可无需用户提供数值即被创建，因此只有当"全默认"的对象在语义上有效时才应提供它。

## 最佳实践

- **Best practice**：对所有类类型，优先使用值初始化而非默认初始化。
- **Best practice**：优先使用显式默认化的默认构造函数（`= default`），而非空函数体的默认构造函数。
- **Tip（性能 vs 安全）**：对没有用户提供默认构造函数的类，值初始化会零初始化，而默认初始化可能更快；只有在创建大量此类对象时，才值得考虑改用默认初始化或空函数体构造函数。
- **Related content**：默认实参见 11.5 — Default arguments。
