# 27.3 Exceptions, functions, and stack unwinding

> 原文：https://www.learncpp.com/cpp-tutorial/exceptions-functions-and-stack-unwinding/

## 核心概念

- **从被调用函数抛出更有价值**：在同一函数里抛并捕获意义不大；真正有用的是"在 try 块中调用函数，而该函数抛出异常"的情况。
- **try 块能探测被调用函数的异常**：throw 语句不必直接位于 try 块内部。
- **Key insight（try 块的作用范围）**："Try 块不仅能捕获块内语句抛出的异常，也能捕获在 try 块内被调用函数所抛出的异常。"
- **捕获时执行流跳转**：以这种方式捕获时，"执行会从异常抛出处跳到处理它的 catch 块"。
- **模块化的好处**：异常处理可以更模块化——平方根示例被改写为使用独立函数。
- **责任下放**：`mySqrt()` 可以抛出异常而不自行处理，把处理责任交给调用者（类似于返回错误码）。
- **为什么让错误向外传**：不同应用对错误的处理方式可能不同（控制台消息 vs 对话框、致命 vs 非致命），因此让函数保持模块化、把错误处理留在不那么模块化的代码里更合适。
- **展开（unwinding）规则——查找顺序**：程序先看当前函数能否处理（是否在本地 try 内抛出且存在匹配 catch）；若不能，则检查调用者，再检查调用者的调用者，依此类推沿调用栈向上。
- **上层能处理的前提**：要让某个调用者处理异常，对当前函数的调用必须位于带匹配 catch 的 try 块中；否则就继续检查再上一层。
- **查找的终止**：如此进行，直到找到处理器，或检查完栈上所有函数都没有处理器。
- **找到处理器时**：执行跳到匹配 catch 块的顶部，同时展开（移除）调用栈上的函数，直到处理它的函数位于栈顶。
- **找不到处理器时**：调用栈"可能展开，也可能不展开"，将在 27.4 讨论。
- **展开期间的清理**：当某个函数从调用栈上被移除时，"其所有局部变量都会照常销毁，但不会返回值"。
- **Key insight（栈展开与析构函数）**："展开调用栈会销毁被展开函数中的局部变量（这很好，因为它确保这些变量的析构函数得以执行）。"
- **长示例引出的四条原则**：
  1. 抛出函数的直接调用者不必处理异常——可以向上委派（C() 没有处理 D() 抛出的异常）。
  2. 若 try 块没有类型匹配的 catch，展开就像根本没有该 try 一样继续（B() 只写 double 处理器）。
  3. 若调用没有发生在关联的 try 块内，即便有匹配的 catch 也会被忽略（B() 的空 try 配 int 处理器）。
  4. 匹配的 catch 执行完后，控制从最后一个 catch 之后的第一条语句继续；其上层调用者甚至不知道曾发生过异常。
- **整体收益**：一个不想处理异常的函数据此无需处理——异常沿调用栈"向上传播，直到找到愿意处理它的人"，让调用栈中最合适的位置去处理错误。

## 最佳实践

本节无 Best practice / Rule / Warning / Tip 标注，但有两个 **Key insight**：

- **Key insight**：Try 块不仅能捕获块内语句抛出的异常，也能捕获在 try 块内被调用函数所抛出的异常。
- **Key insight**：展开调用栈会销毁被展开函数中的局部变量，从而确保它们的析构函数被执行。
