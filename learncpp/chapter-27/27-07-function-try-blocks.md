# 27.7 Function try blocks

> 原文：https://www.learncpp.com/cpp-tutorial/function-try-blocks/

## 核心概念

1. **动机**：派生类构造函数的成员初始化列表会先构造基类，而这发生在派生类构造函数体之前，因此普通的 `try` 块无法包住成员初始化列表里的这次调用。
2. **函数 try 块（定义）**：一种经过改造的 `try` 块，可以"为**整个函数体**建立异常处理器，而不是只为一小段代码块"。
3. **语法要点**：`try` 关键字放在成员初始化列表**之前**，从该位置到函数体结束都被视为 try 块的一部分。
4. **catch 的位置**：关联的 `catch` 块与函数本身同级缩进（写在函数体外），而不是嵌在函数体内；`try` 关键字到函数体结束之间抛出的异常都能被它捕获。
5. **传播流程示例**：构造 `b` 会调用 `B` 的构造函数（含函数 try），`B` 又调用 `A` 的构造函数，`A` 抛异常 → 异常向上到 `B` 的函数级 `catch`，打印信息并重抛 → 最终由 `main` 的 `catch` 处理。
6. **构造函数推荐用法**：需要构造函数处理"成员初始化列表里抛出的异常"时，使用函数 try 块。
7. **普通 catch 块的三种选择**：抛出全新异常、重抛当前异常，或"解决"异常（通过 `return`，或让控制流到达 catch 块末尾）。
8. **构造函数级 catch 的限制**：必须抛出全新异常或重抛现有异常，**不能解决异常**；不允许 `return`；控制流到达 catch 块末尾会隐式重抛。
9. **析构函数级 catch**：可以抛出、重抛，或通过 `return` 解决异常；到达末尾会隐式重抛。
10. **其他（普通）函数**：可以抛出、重抛，或通过 `return` 解决异常；到达末尾时，对无返回值的函数会隐式"解决"异常，对**有返回值的函数则是未定义行为**。
11. **行为汇总表**：

    | 函数类型 | 能否用 return 解决 | catch 末尾的行为 |
    |---|---|---|
    | 构造函数 | 否，必须抛出或重抛 | 隐式重抛 |
    | 析构函数 | 可以 | 隐式重抛 |
    | 无返回值函数 | 可以 | 解决异常 |
    | 有返回值函数 | 可以 | 未定义行为 |

12. **隐式重抛说明**：前面示例中，若在构造函数的函数级 catch 里不显式重抛，控制流到达末尾也会触发隐式重抛，结果相同。
13. **适用场景**：函数 try 块也能用于非成员函数，但极少需要——它们"几乎只用于构造函数"。
14. **同时捕获基类与当前类的异常**：`B` 上的函数 try 块既能捕获 `A` 构造函数抛出的异常，也能捕获 `B` 自身构造函数抛出的异常。
15. **不要用它清理资源**：对象构造失败时该类的析构函数不会被调用；由于对象在 catch 执行前就已"死亡"，引用其成员属未定义行为。要清理失败的对象请遵循 27.5 的常规规则。
16. **主要用途**：在把异常向上传递前记录失败信息，或把异常转换为另一种类型。

## 最佳实践

- **Best practice**：当需要构造函数处理"成员初始化列表里抛出的异常"时，使用函数 try 块。
- **Best practice**：避免让控制流到达函数级 catch 块的末尾；应显式地 `throw`、重抛或 `return`。
- 相关建议：由于 catch 末尾的行为随函数类型剧烈变化（对有返回值函数甚至未定义行为），建议永不依赖该行为。
- 资源清理注意：不要用函数 try 块来清理构造失败的类，参见 27.5 的"When constructors fail"。
