# 15.7 Static member functions

> 原文：https://www.learncpp.com/cpp-tutorial/static-member-functions/

## 核心概念

- **静态成员变量属于类、不属于对象**：一个 public 静态成员可以用"类名 + `::`"访问；而 private 静态成员不能这样在类外直接访问。
- **访问私有静态成员通常要借助对象**：用普通 public 成员函数能读到它，但为了读一个"班级别"的值被迫实例化对象，很不方便。
- **成员函数也可以是 static**：把访问函数写成 `static int getValue() { return s_value; }` 后，就能用 `Something::getValue()` 调用，无需创建任何对象。
- **静态成员函数不依附于对象**：它可以用"类名 + 作用域运算符"调用；通过对象调用虽然也能编译，但不推荐。
- **没有 `this` 指针**：由于它不对任何对象操作，自然没有可供 `this` 指向的目标。
- **只能访问其他静态成员**：非静态成员需要一个类对象才能访问，而静态成员函数没有这样的对象。
- **可以在类外定义**：类外定义时不写 `static` 关键字（只保留返回类型、类名限定与参数）。
- **全静态的类无需实例化**：数据与函数都可以是类级别的，因此可直接使用其功能。
- **inline / ODR 规则**：定义在类内的函数隐式 inline；定义在类外的不是，但可标 `inline`。放在头文件中的静态成员函数应标为 `inline`，否则被多个翻译单元包含时会违反单一定义规则（ODR）。
- **纯静态类（monostate）的缺点**：所有静态成员只存在一份，无法拥有多份彼此独立的副本（例如两个各自计数的 ID 生成器）；又因为类声明通常具有全局作用域，这类类本质上就是"全局可达的全局函数与全局变量"，有同样的风险。
- **更可取的替代方案**：写一个普通类，再创建一个它的全局实例——这样既有全局实例可用，又保留了创建局部实例的能力。
- **静态类 vs 命名空间**：二者都能容纳静态存储期的变量与函数；区别在于类有访问控制、命名空间没有。需要静态数据成员和/或访问控制时用静态类，否则优先用命名空间。
- **C++ 没有静态构造函数**：与一些现代语言不同，C++ 不能通过构造函数来初始化静态成员。
- **能直接初始化就直接初始化**：如果静态成员可以直接初始化，就在定义处初始化（即便它是 private 也允许）。
- **需要执行代码才能初始化时**：用"一个构造、填充并返回对象的函数"来完成，把返回结果拷贝进静态成员；lambda 也能起到同样作用。

## 最佳实践

- **Key insight**：静态成员函数可以在没有对象的情况下调用；但它们**没有 `this` 指针**，因此不能访问非静态数据成员。
- **Warning（关于"全静态成员类"的警告）**：纯静态类有两大缺点——(1) 无法拥有多份副本，例如两个各自独立编号的 ID 生成器；(2) 其行为等价于全局可达的函数与全局变量，因而带有全局变量的一系列风险。
- **Author's note（相关内容）**：lambda 也可以用来执行初始化静态成员所需的代码；第 8.15 节（全局随机数）给出了一个实用示例（那里用的是命名空间，写法相同）。
- **inline / ODR 提示**：放在头文件中的静态成员函数应标为 `inline`，以免被多个翻译单元包含时违反 ODR。
