# 15.10 Ref qualifiers

> 原文：https://www.learncpp.com/cpp-tutorial/ref-qualifiers/

**说明**：本节为**可选（optional）**小节。作者建议"轻松通读、熟悉材料即可，无需完全掌握就能继续"学习后续内容。

## 核心概念

- **悬垂引用的风险回顾**：访问函数若返回数据成员的引用，当隐式对象是右值（临时对象）时就很危险——临时对象在引用初始化后立即销毁，引用随即悬垂。
- **两难（conundrum）**：按值返回对"右值隐式对象"安全，但在隐式对象是左值时"造成昂贵且不必要的拷贝"；按 const 引用返回高效，但"在隐式对象是右值时可能被误用（导致未定义行为）"。
- **惯例做法**：由于成员函数通常在左值对象上调用，通常的解决办法就是"按 const 引用返回，并约定不要在右值隐式对象上误用返回的引用"。
- **ref-qualifier 的定义**：C++11 引入的"ref-qualifier"是一种"鲜为人知"的特性，允许你根据隐式对象是左值还是右值来重载成员函数。
- **限定符语法规则**：给只匹配左值隐式对象的重载加 `&`，给只匹配右值隐式对象的重载加 `&&`。
- **两个重载可有不同返回类型**：因为它们是相互区分的重载，各自可以声明自己的返回类型；左值版本按 const 引用返回，右值版本按值返回。
- **好处**："当隐式对象是左值时做高效的事，是右值时做安全的事。"
- **进阶读者注**：对"非 const 临时对象"，右值重载仍可能不是最优，因为该对象在表达式结束时反正要销毁；用 `std::move` 把成员移出可以避免一次昂贵拷贝。
- **并存规则**：对同一个函数，带 ref-qualifier 与不带 ref-qualifier 的两个重载不能同时存在，只能二选一。
- **const 左值绑定的规则**：正如 const 左值引用可以绑定到右值，若只有"const 左值限定"的版本存在，它也能同时接受左值与右值的隐式对象。
- **删除规则**：任一限定版本都可以用 `= delete` 显式删除，从而**阻止**对它的调用（例如删除右值限定版本，就禁止了对右值隐式对象的调用）。
- **为什么不推荐**：给每个返回引用的 getter 都加右值重载会增添杂乱，而这个场景又罕见且可避免；右值重载按值返回即使在本可安全返回引用处也会产生一次拷贝/移动；许多开发者不了解该特性；标准库一般也不用它。
- **最终建议**：与其用 ref-qualifier，不如**始终立即使用**访问函数的返回值，而不要保存它返回的引用。

## 最佳实践

- **Best practice 结论**：不推荐使用 ref-qualifier 来解决上述问题；应优先"立即使用访问函数的结果、不要保存其返回的引用"。
