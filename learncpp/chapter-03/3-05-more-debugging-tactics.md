# 3.5 More debugging tactics

> 原文：https://www.learncpp.com/cpp-tutorial/more-debugging-tactics/

## 核心概念

- **调试打印语句的问题**：上一节指出四条缺点——它们会"弄乱你的代码"、弄乱程序输出、需要改代码来添加和删除（有引入新 bug 的风险）、且事后必须删掉，因此**不可复用**。
- **把调试代码条件化（conditionalizing）**：用预处理指令把调试语句包起来，例如定义一个宏 `ENABLE_DEBUG`，配合 `#ifdef` / `#endif`，这样只要注释或取消注释一行，就能开关调试输出。
- **多文件传播**：在多文件程序里，`#define` 应写进一个被所有代码文件包含的头文件里，这样改一处就能在全局范围内启用/禁用调试。
- **条件编译的缺点**：它用"删不干净的风险"换来了"更多的代码杂乱"；宏名打错、或漏包含头文件，都可能悄无声息地让部分甚至全部调试输出失效。
- **日志（log）/ 记录（logging）/ 日志文件（log file）**：
  - log 是"对已发生事件的顺序记录，通常带时间戳"；
  - logging 是产生这种记录的行为；
  - 日志通常写入磁盘上的日志文件，供日后查阅。大多数应用程序和操作系统都会生成此类文件来帮助诊断问题。
- **日志文件的优点**：把调试信息与程序输出分离开，避免互相干扰；而且日志文件可以很方便地发给别人，帮助定位问题出在哪里。
- **`std::clog`**：C++ 提供了用于记录日志的输出流，但它默认写到标准错误流（与 `std::cerr` 相同）。它可以被重定向到文件，但一般来说，使用第三方日志库会更好。
- **plog 日志库**：这里仅作演示。它是 header-only 的，因此随处包含都很方便，而且轻量。使用分三步：包含日志头文件、初始化、然后像写控制台那样写日志。
- **日志行的样子**：宏 `PLOGD`（由 plog 定义）产生的条目带有时间戳、级别、线程 id 和源码位置（见示例输出）。
- **不需要条件指令**：日志库通常都提供了减少或关闭输出的办法，从而免去 `#ifdef` 块的杂乱。以 plog 为例，只要改一下初始化语句就能基本关闭输出。
- **安装（旁注）**：从 plog 仓库下载 zip 并解压，把 `plog-master\include\` 目录设为每个工程的头文件包含目录；日志文件通常创建在你的可执行文件旁边。
- **性能提示**：对于更大或对性能敏感的项目，可以考虑更快、功能更丰富的日志库，例如 spdlog。

## 最佳实践

本节原文没有 Best practice / Author's note / Warning 标注，但包含以下 Tip 与旁注：

- **Tip**："在更大或对性能敏感的项目中，可能更倾向于使用更快、功能更丰富的日志库，例如 spdlog。"
- **旁注**：编译 plog 示例或在自己项目里使用 plog 的步骤——从 plog 仓库获取最新发布（绿色 Code 按钮 → Download zip），解压，然后为每个工程设置包含目录。
- **行内说明**：plog 不会在任何后续课程中使用，因此没有学它的必要。
