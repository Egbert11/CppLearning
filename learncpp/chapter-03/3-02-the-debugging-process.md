# 3.2 The debugging process

> 原文：https://www.learncpp.com/cpp-tutorial/the-debugging-process/

## 核心概念

- **场景**：程序能干净编译，但运行结果不对——那么问题一定出在某处语义错误上，需要把它找出来。
- **错误可能在哪**：如果你一边写一边做小步测试，可能已经有怀疑的位置；否则可能毫无头绪。
- **一切 bug 的共同前提**：每个 bug 归根结底都源于一个"你以为是对的、其实并不对"的信念——"Something that you thought was correct, isn't."
- **难点在于定位**：找出这个错误信念才是调试中最难的部分；本节给出的是一套通用的调试流程。
- **示例是刻意简化的**：本章程序都很基础，这些技巧看起来可能"杀鸡用牛刀"，但它们真正发挥作用的场合是"更大、更复杂的程序"。
- **调试六步法**：
  1. **找到根本原因（root cause）**：定位出问题的那一行，通常就是没能正常工作的那段代码（具体策略见下一节）。
  2. **理解问题**：确认自己明白问题为什么会发生。
  3. **确定修复方案**：决定用什么方法解决它。
  4. **实施修复**：真正把修改落实下去。
  5. **重新测试是否修好**：确认原来的问题已经消失。
  6. **重新测试是否引入回归**：确认没有产生新的问题。
- **制冰机类比**：听到制冰机在运转却没有冰，冰盒是空的——"没冰"只是症状，真正的根本原因是"制冰模块坏了"；理解问题后，修复选项可以是买冰、继续诊断、更换制冰模块或换一台冰箱（本例选择更换制冰模块），装好后过夜再看，出冰了且没引入新问题，即完成整个流程。
- **套用到示例程序**：第 10 行打印出了错误的答案，这就是调查的起点。
  - 找根本原因：输入是字面量 5 和 3，不可能有错，所以只能是 `add` 返回了错误的值；而函数里唯一的 `return` 语句就是罪魁祸首。
  - 理解/修复：用错了运算符；把 `operator-` 换成 `operator+` 并重新编译。
  - 重新测试：再跑一遍得到正确的 8；对这种小程序而言，这就足够了。
- **要点**：这个例子虽小，却完整演示了诊断任何程序时所用的基本流程。
