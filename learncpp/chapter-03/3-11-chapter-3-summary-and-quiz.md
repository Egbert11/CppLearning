## 核心概念

以下是本章（Chapter 3 调试 C++ 程序）总结页给出的核心术语与定义：

- **语法错误（syntax error）**：写出了违反 C++ 语法规则的语句，编译器会捕获这类错误。
- **语义错误（semantic error）**：语句在语法上合法，但没有完成作者想让它做的事。
- **调试（debugging）**：定位并消除程序中错误的整个活动。
- **五步调试流程**：找到根因 → 理解问题 → 决定修复方案 → 应用修复 → 重新测试。
- **定位错误**：通常是调试工作中最困难的部分。
- **静态分析工具（static analysis tools）**：扫描代码、找出可能问题的语义瑕疵的工具。
- **可靠复现**：让问题能按需复现，被描述为调试中第一个、也是最关键的一步。
- **发现问题的战术**：用注释禁用代码、加入输出语句以追踪控制流、打印值。
- **打印调试的偏好**：应使用 `std::cerr` 而不是 `std::cout`；理想情况下最好根本不用打印式调试。
- **日志文件 / 日志（log file / logging）**：记录程序事件的文件；写入这类信息就叫 logging。
- **重构（refactoring）**：在不改变行为的前提下重组代码，通常为了组织、模块化或性能。
- **单元测试（unit testing）**：测试源码中小的、独立的片段是否正确。
- **防御性编程（defensive programming）**：预想软件被误用的各种方式，以便捕获并减少这些误用。
- **程序状态（program state）**：运行时被记录的全部信息——变量值、执行过哪些函数、当前执行点。
- **调试器 / 集成调试器（debugger / integrated debugger）**：控制执行并检查状态的工具；集成调试器位于代码编辑器内部。
- **单步（stepping）**：一组相关调试功能，用于一条语句一条语句地前进。
- **Step Into（步入）**：执行下一条语句；若它含函数调用，则跳到该函数顶部。
- **Step Over（步过）**：执行下一条语句；若它含函数调用，则先完整执行该函数再交还控制权。
- **Step Out（步出）**：跑完当前函数剩余部分，函数退出后交还控制权。
- **Run to cursor（运行到光标）**：执行直到抵达光标所在的语句。
- **Continue / Start（继续 / 开始）**：运行直到程序结束或遇到断点；*Start* 与之相同，但从程序开头开始。
- **断点（breakpoint）**：一个标记，指示调试器在到达该点时暂停。
- **Set next statement（设置下一条语句）**：把执行点移到别处（俗称"跳转"），向前可跳过代码，向后可重跑。
- **监视变量 / 监视窗口（watching a variable / watch window）**：在调试时检查变量值；监视窗口显示变量或表达式。
- **调用栈 / 调用栈窗口（call stack / call stack window）**：通往当前执行点的活跃函数列表；调用栈窗口用于显示它。

## 本章知识速览

Chapter 3（调试 C++ 程序）全章要点清单：

- **3.1 语法与语义错误**：语法错误违反语法规则、由编译器捕获；语义错误语法合法但行为不符合意图。
- **3.2 调试流程**：五步法——找根因、理解问题、决定修复、应用修复、重新测试；定位错误通常最难。
- **3.3 调试策略**：先设法让问题**可靠复现**（最关键的一步）；然后缩小范围、逐层定位。
- **3.4 基本调试手法**：注释掉代码、验证代码流程（用 `std::cerr` 打印函数名）、打印值；临时调试语句宜不缩进以便清除。
- **3.5 更多调试手法**：明确假设并验证、用代码流程追踪、打印的是"值"而不是"执行路径"、条件化调试（`#ifdef DEBUG`）、用日志（logging）留下可复查的记录。
- **3.6 单步调试**：程序状态、调试器、集成调试器；Step Into / Step Over / Step Out 的语义与快捷键；必须用 debug 构建；`std::unitbuf` 强制刷新。
- **3.7 运行与断点**：Run to cursor、Continue、Start、Breakpoint、Set next statement；断点每次命中都交还控制且会保留；跳转只改执行点、不改状态，且不要跨函数跳。
- **3.8 监视变量**：悬停、QuickWatch、Watch 窗口、Locals 窗口；在变量上设断点（值改变即停）；监视窗口可求简单表达式（标识符取当前值）。
- **3.9 调用栈**：调用栈是通往当前点的活跃函数列表；压栈/弹栈规则；用调用栈窗口查看栈帧及各函数的"下一条将执行语句"。
- **3.10 把问题消灭在萌芽**：语义错误会潜伏、越拖越难查；预防清单；重构（不改行为的结构调整）；函数宜短（<10 行，最好 <5 行）；防御性编程；尽早测试、单元测试、基于约束（`assert`/`static_assert`）；静态分析工具（含编译器自身的警告）。

## 测验

### 第 1 题

下面这个"两数相加"的程序行为不正确。请用集成调试器单步执行、同时监视 `x`，找出并修复问题。见 [3-11-quiz1.cpp](3-11-quiz1.cpp)。

**参考解答**：`main` 中的 `readNumber(x);` 这一句丢弃了返回值；且 `readNumber` 不该接受参数，应无参并用局部变量 `x`。修正后见 [3-11-quiz1-solution.cpp](3-11-quiz1-solution.cpp)。

### 第 2 题

下面这个"两数相除"的程序行为不正确。请单步执行，输入 8 和 4，然后修复它。见 [3-11-quiz2.cpp](3-11-quiz2.cpp)。

**参考解答**：第二次读入误写成了 `x = readNumber();`（应为 `y = readNumber();`），于是 `y` 仍为 0，导致 `x/y` 除零、产生未定义行为。需把第二次赋值改为给 `y`；修正后见 [3-11-quiz2-solution.cpp](3-11-quiz2-solution.cpp)。

### 第 3 题

对下面这个多函数程序，当执行点位于 `d()` 中被标注 `// here` 的那一行时，调用栈中包含哪些函数？（只需给出函数名，无需返回行号。）见 [3-11-quiz3.cpp](3-11-quiz3.cpp)。

**参考解答**：`d`、`b`、`a`、`main`（自栈顶到底部）。

### 第 4 题（附加题）

下面是另一个有问题的"两数相加"程序。用输入 8 和 4 单步执行并修复它。见 [3-11-quiz4.cpp](3-11-quiz4.cpp)。

**参考解答**：`readNumber()` 内部把变量声明成了 `char x{};`，于是输入被按字符编码存储（输入 8 得到 56、输入 4 得到 52），导致结果错误。把该行由 `char` 改为 `int` 即可。
