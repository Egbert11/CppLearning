# 3.9 Using an integrated debugger: The call stack

> 原文：https://www.learncpp.com/cpp-tutorial/using-an-integrated-debugger-the-call-stack/

## 核心概念

> 本节原文以 **Visual Studio** 的界面为主要示例（同时给出 Code::Blocks 与 VS Code 的对应操作）。

### 为什么需要调用栈

- 调用栈窗口能帮助我们追踪执行"是如何到达当前这一点"的；它也回答了"程序在函数调用后如何知道该返回到哪里"。

### 定义与规则

- **调用栈（call stack）**：到达当前执行点时，所有"已被调用且仍然活跃"的函数的列表。列表中的每一项记录一个被调用的函数，以及执行将返回到的行。
- **压栈/弹栈规则**：函数被调用时被压到栈顶；函数返回时从栈顶移除，控制权交给它下面的那一项。

### 调用栈窗口的位置

- **调用栈窗口（call stack window）**：显示当前调用栈的调试器面板；若被隐藏，需要让 IDE 显示它。
  - **Visual Studio**：*Debug menu > Windows > Call Stack*——需处于调试会话中才能用。
  - **Code::Blocks**：*Debug menu > Debugging windows > Call stack*。
  - **VS Code**：调试模式下出现在左侧。

### 示例演练

- 示例程序：`a()` 和 `b()` 各打印一条消息；`b()` 先打印再调用 `a()`；`main()` 先调用 `a()`，再调用 `b()`。
- 在第 5 行和第 10 行设断点，开始调试。**先命中第 5 行**，因为 `a()` 先被调用。
- 可能的 IDE 差异（都无关紧要）：函数/行的格式可能不同、行号可能差 1、可能显示 "[External Code]" 或其它名字奇怪的函数。
- 读第一个栈：最底部的项显示 `main` 先被调用，然后是 `a`。`a` 旁边的行号标记**当前执行点**；`main` 那一项上的行号表示**控制权将返回到的位置**。
- **Tip**：函数名后面的行号显示各函数中**下一条将执行的语句**。对栈顶项来说，这是马上要运行的下一行；对偏低的项来说，这是该函数恢复后要执行的下一条语句。
- Continue 到下一个断点（第 10 行）：`b` 成为栈顶项；`a` 消失了，因为它在返回时被移除了。
- 再 Continue：由于 `b()` 调用了 `a()`，第 5 行断点再次命中；此时栈中有三帧，自下而上依次是 `main`、`b`、`a`。
- 实用价值：调用栈与断点配合很好——断点命中时，它能显示为到达该点调用了哪些函数。

### 结论

- 单步、断点、监视、调用栈这四样提供了调试几乎所有问题的基础；技能要靠练习与试错来增长。
