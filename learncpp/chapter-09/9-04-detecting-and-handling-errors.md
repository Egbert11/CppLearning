# 9.4 Detecting and handling errors

> 原文：https://www.learncpp.com/cpp-tutorial/detecting-and-handling-errors/

## 核心概念

- **语义错误 vs. 假设错误（assumption error）**：误用语言特性或逻辑失误可以直接改正；但大多数 bug 源于"程序员做出的错误假设"，以及缺少错误检测与处理。
- **假设会在三处出错**：(a) 函数返回之后（假设它成功了）；(b) 从用户或文件传入输入时（假设格式/内容正确）；(c) 调用函数时（假设参数有效）。
- **要测试"悲伤路径"，不只是"快乐路径"**：新手往往只测试 happy path（无错误的情形），但为失败情形做规划才是重点。
- **防御式编程（defensive programming）**：第 3.10 节定义为——预料最终用户或开发者可能误用软件的所有方式，并加以处理。
- **四种通用的错误处理策略**：在函数内部处理错误；把错误传回给调用者；终止程序；抛出异常。**没有唯一最佳方案**，取决于具体问题。
- **在函数内部处理**：当错误可以被隔离时首选。两种做法：重试直到成功（例如重新提示输入，或循环中重试连接），或取消/忽略该操作。
- **静默取消的缺点**：如果忽略错误，调用者或用户无从得知出了差错；打印错误信息会有帮助。当调用者期待返回值或副作用时，忽略就不是选项。
- **把错误传回给调用者**：对于 `void` 函数，可把返回类型改为 `bool` 来表示成功/失败，供调用者检查。
- **哨兵值（sentinel value）**：在函数语境中具有特殊含义的值。如果某个值永远不会被合法地产生（例如求倒数时的 `0.0`），就返回它表示失败；返回一个带名字的常量可提升可读性。
- **哨兵值的注意事项**：如果函数的值域范围都可能是合法结果，哨兵就无法区分合法值与错误——此时应改用 `std::optional` 或 `std::expected`（12.15 节）。
- **致命（不可恢复）错误**：程序无法继续时，终止它：若在 `main()` 中就从 `main()` 返回非零状态码，否则使用 `std::exit()` 之类的 halt 语句。
- **异常（exception）**：C++ 的独立机制——出错时"抛出"异常；调用者有机会"捕获"它，否则它会沿调用栈向上传播，直到被处理，或直到 `main()` 失败、程序终止。详见第 27 章。
- **何时用 `std::cout` vs `std::cerr` vs 日志**：二者默认都打印到控制台；操作系统的流重定向可捕获输出。
  - *交互式应用*：启动后用户与之交互（游戏、音乐应用）。
  - *非交互式应用*：无需用户交互；输出可能喂给另一个程序。
    - *工具（tools）*：产生即时结果后终止（例如 Unix 的 `grep`）。
    - *服务（services）*：在后台安静运行（例如病毒扫描器）。
- **输出的经验规则**：
  - 用 `std::cout` 输出"所有常规的、面向用户的文本"。
  - 交互式程序中：`std::cout` 用于面向用户的正常错误信息；`std::cerr` 或日志文件用于状态/诊断信息——技术性警告与错误、状态更新、完成百分比等。
  - 非交互式程序（工具或服务）中：`std::cerr` "只用于错误输出"，以便把错误与正常输出分开解析。
  - 事务型应用（浏览器、Web 服务器）：用日志文件记录事件以便日后查阅（处理的文件、进度、各阶段时间戳、警告/错误）。

## 最佳实践

本节无 Best practice / Rule / Warning 提示框。唯一的提示框是 **Related content**：当返回值的完整范围都可能被合法产生时，返回 `std::optional`（见 12.15 节）或 `std::expected` 会是更好的选择。

## 代码示例

- [9-04-example1.cpp](9-04-example1.cpp)：静默失败——`void` 除法函数在 `y == 0` 时直接不打印，调用者毫不知情。
- [9-04-example2.cpp](9-04-example2.cpp)：同样的函数，但 `else` 分支打印 `"Error: Could not divide by zero\n"`——取消操作并告知用户原因。
- [9-04-example3.cpp](9-04-example3.cpp)：`int doIntDivision(int x, int y)`，函数体是 `return x / y;`——有返回值的函数无法简单跳过其逻辑（除零是真实风险）。
- [9-04-example4.cpp](9-04-example4.cpp)：`bool printIntDivision(int x, int y)`——`y == 0` 时打印错误并返回 `false`，否则打印 `x / y` 并返回 `true`；演示用返回值向调用者报告成功/失败。
- [9-04-example5.cpp](9-04-example5.cpp)：`double reciprocal(double x)`，函数体 `return 1.0 / x;`——即使出错也必须返回一个 `double`；`reciprocal(0.0)` 会崩溃。
- [9-04-example6.cpp](9-04-example6.cpp)：使用哨兵值的 `reciprocal()`——定义 `constexpr double error_no_reciprocal { 0.0 };`，`x == 0.0` 时返回它，否则返回 `1.0 / x`。
- [9-04-example7.cpp](9-04-example7.cpp)：`double doIntDivision(int x, int y)` 在出错时终止——`y == 0` 打印错误后调用 `std::exit(1)`，否则返回 `x / y`；演示用 halt 语句处理致命错误。
