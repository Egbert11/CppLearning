# 5.1 Constant variables (named constants)

> 原文：https://www.learncpp.com/cpp-tutorial/constant-variables-named-constants/

## 核心概念

- **常量（constant）**：程序运行期间不能被改变的值。
- **常量的两类**：命名常量（named / symbolic constant，与标识符绑定）与字面量常量（literal constant，不绑定标识符）。命名常量有三种定义方式——常量变量、带替换文本的对象式宏、枚举常量，其中常量变量最常用。
- **常量变量（constant variable）**：一种刻意的“矛盾修辞”——变量一旦初始化，其值便固定不变。
- **声明方式**：在类型旁加上 `const` 限定符；`const` 可写在类型前，也可写在类型后，但写在类型前更常见（如同说“绿球”而不是“球绿”）。
- **限定符是类型的一部分**（Key insight）：在 `const double gravity { 9.8 };` 中，`gravity` 的类型是 `const double`。
- **必须初始化**：const 变量一定要在定义处初始化，之后不能再对它赋值。
- **初始化式可以是非常量**（Key insight）：const 变量的初始化式可以是普通变量或其他运行期值，例如从 `std::cin` 读入的值。
- **命名建议**：C 程序员常用全大写加下划线（如 `MAX_STUDENTS`），C++ 程序员常用带 `k` 前缀的驼峰式（如 `kMaxStudents`）。因为常量变量的行为与普通变量一致，本节更推荐沿用普通变量的命名约定。
- **const 函数形参**：形参可声明为 const，且无需写初始化式——调用时的实参本身就是初始化式。
- **现代实践**：按值传参的形参只是函数结束时即销毁的副本，给它加 const 只增加杂乱而没有收益。
- **const 返回值**：语法允许，但对基本类型而言该限定符会被忽略（可能产生编译器警告）；对其他类型通常也无意义，因为返回值是临时副本，且 const 还会妨碍移动语义优化。
- **为什么要用 const**：① 降低出错概率；② 给编译器更多优化机会（程序更小更快）；③ 最重要的是降低程序复杂度，因为 const 变量的值不会变化。
- **关于复杂度的洞见**（Key insight）：系统里每一个“活动部件”都会增加复杂度和失效风险；非常量变量是活动部件，常量变量不是。
- **带替换文本的对象式宏**：预处理器把宏名替换为替换文本；宏名是标识符、替换文本是常量，所以它也算命名常量。
- **宏的三个问题**：① 忽略 C++ 作用域——名称一旦定义，就在文件余下部分被替换，常导致难以理解的编译错误；② 更难调试——编译器和调试器只看到替换后的文本；③ 其替换行为与语言中其他机制都不同，容易出错。常量变量可以避免这三个问题。
- **跨文件使用**：多个文件都要用的常量应集中声明一次而非各文件重复定义，以便一处修改。细节见 7.10（用 inline 变量共享全局常量）。
- **类型限定符（type qualifier）**：作用于类型、改变类型行为的关键字；用于常量变量的 `const` 就是 const 限定符。截至 C++23 只有两个类型限定符：`const` 与 `volatile`。
- **延伸阅读**：`volatile` 表示值可能随时变化，会禁用某些优化；`const` 与 `volatile` 合称 cv-qualifiers。相关术语：cv-unqualified（无限定符）、cv-qualified（有一个及以上限定符）、possibly cv-qualified（可能有限定符）。这些只作参考，无需背诵。

## 最佳实践

- 把 `const` 写在类型之前（因为这样更符合惯例）。
- 不要对按值传参的形参使用 `const`。
- 不要对按值返回的值使用 `const`。
- 尽可能把变量设为常量。例外包括按值传参的形参和按值返回的类型，它们一般不应设为常量。
- 优先使用常量变量，而不是带替换文本的对象式宏。
