## 核心概念

- **常量（constant）**：在程序执行期间不可被修改的值。C++ 有两类：命名常量与字面量。
- **命名常量（named constant）**：绑定到标识符的常量。**字面量常量（literal constant）** 则没有标识符。
- **常量变量（constant variable）**：值不可更改的变量，用 `const` 关键字创建。此类变量必须初始化；在按值传递或按值返回时，不建议使用 `const`。
- **类型限定符（type qualifier）**：作用于类型、改变其行为的关键字。截至 C++23，只有 `const` 与 `volatile` 担此角色。
- **常量表达式（constant expression）**：可在编译期求值的表达式；其反面是**运行期表达式（runtime expression）**。
- **编译期常量（compile-time constant）**：值在编译期已知的常量。**运行期常量（runtime constant）** 的值到程序运行时才确定。
- **constexpr 变量**：必须是编译期常量，且由常量表达式初始化。函数形参不允许声明为 constexpr。
- **字面量（literals）**：直接写在源码中的值。它们有各自的类型，字面量后缀可以覆盖默认类型。
- **魔术数字（magic number）**：含义不清、或将来可能需要修改的字面量（通常指数字）。规则是：不要使用它们，改用符号常量。
- **数制（numeral systems）**：日常计数用**十进制**（10 个数字），计算机用**二进制**（2 个数字）；C++ 额外支持**八进制**（基 8）与**十六进制**（基 16）。这些都是用数字/符号集合表示数字的系统。
- **字符串（string）**：表示文本的字符序列。字符串字面量一律用双引号括起；C++ 的字符串字面量是类型有点别扭的 C 风格字符串。
- **std::string**：处理文本的简单、安全的方式，位于 `<string>`。它的初始化、赋值与拷贝代价都较高。
- **std::string_view**：对已存在字符串（C 风格字面量、`std::string` 或字符数组）的只读访问，不拷贝。底层字符串已消失的视图称为**悬垂（dangling）** 视图。修改 `std::string` 会使所有指向它的视图**失效（invalidate）**；使用已失效的视图（除用于重新使其有效外）会导致未定义行为。
- 由于 C 风格字符串字面量贯穿整个程序，把 `std::string_view` 指向它是可以的，甚至可以从函数返回这样的视图。
- **子串（substring）**：已存在字符串中一段连续的字符。

## 最佳实践

- 优先用 `const` / `constexpr` 声明符号常量，而不是 `#define`：宏定义在调试器中不可见，且更容易引发命名冲突。
- 不使用魔术数字，改用符号常量。
- 避免在按值传递的形参和按值返回的值上使用 `const`（无实际意义）。

## 本章知识速览

- **常量与字面量**：常量分命名常量与字面量；字面量有类型，可用后缀改变默认类型。
- **const 与 constexpr**：`const` 表示值不可改，初始化器可编译期或运行期确定；`constexpr` 表示可用于常量表达式，初始化器必须编译期已知。常量变量的初始化器是常量表达式时用 `constexpr`，否则用 `const`。`constexpr` 变量隐式是 `const`。
- **类型限定符**：截至 C++23 只有 `const` 与 `volatile`。
- **常量表达式 / 编译期常量 / 运行期常量**：能编译期求值的表达式是常量表达式；值编译期已知的是编译期常量，否则是运行期常量。
- **魔术数字**：含义不清或易变的字面量，应替换为符号常量；符号常量优先用 `const`/`constexpr` 而非 `#define`。
- **数制**：十进制、二进制（C++14 起有二进制字面量 `0b...`）、八进制（前缀 `0`）、十六进制（前缀 `0x`）。C++14 起数字分隔符 `'` 提升可读性。
- **字符串**：字符串是字符序列；字符串字面量是 C 风格字符串（`const char[]`），类型别扭且不灵活。
- **std::string**：可修改，位于 `<string>`；初始化、赋值、拷贝代价高，不要按值传递。用 `std::getline(std::cin >> std::ws, s)` 读取整行。
- **std::string_view**：位于 `<string_view>`，对已有字符串的只读视图，不拷贝；适合做只读形参。拥有完整 `constexpr` 支持。
- **悬垂与失效**：视图依赖于被查看对象；对象销毁则视图悬垂，`std::string` 被修改则视图很可能失效。指向 C 风格字面量的视图始终安全，甚至可从函数返回。
- **子串**：字符串中连续的字符段。
- **返回值**：返回 `std::string` 多数情况可接受（局部变量、按值返回的表达式、临时对象）；返回字面量时优先返回 `std::string_view`。

## 测验

- **Q1a**：命名常量（符号常量）相对于字面量常量有哪些优点？
  - 参考：字面量（魔术数字）使代码更难理解、更难修改；符号常量能记录含义，改一处声明即可更新所有使用处。
- **Q1b**：用 `const` / `constexpr` 相对 `#define` 声明常量有哪些优点？
  - 参考：`#define` 创建的对象在调试器中不可见，且更容易产生命名冲突。
- **Q2**：下面程序有三个问题（参见 [5-10-quiz2.cpp](5-10-quiz2.cpp)），找出并修复它们。
  - 参考：
    1. `std::uint8_t` 实际是字符类型，读入 "18" 只会提取 `'1'`（ASCII 49），把用户当成 49 岁。应改用普通 `int` 并去掉 `<cstdint>`。
    2. 魔术数字 `16` 应改为 `constexpr` 变量。
    3. `'.\n'` 是多字符字面量，打印结果不正确；应改为双引号的 `".\n"`。
- **Q3**：`std::string` 与 `std::string_view` 有什么区别？各自适合什么场景？后者的主要风险是什么？
  - 参考：`std::string` 可修改，但初始化与拷贝代价高；`std::string_view` 是对别处某字符串的廉价只读视图。其风险是底层字符串先被销毁，导致悬垂视图。
- **Q4**：编写一个要求用户输入两个人的姓名与年龄、并打印较年长者姓名与年龄的程序（要求用 `std::string` 存储、`std::string_view` 作只读形参）。参见 [5-10-quiz4.cpp](5-10-quiz4.cpp)。
  - 提示（原文）：用 `std::getline()` 输入姓名。
  - 参考示例输出：`David Jenkins (age 44) is older than John Bacon (age 37).`
- **Q5**：在上题中，为什么 `age1` 不能声明为 `constexpr`？
  - 参考：`constexpr` 变量需要常量表达式作初始化器，而调用 `getAge()` 不允许出现在常量表达式中，所以只能用 `const`。
