# 5.9 std::string_view (part 2)

> 原文：https://www.learncpp.com/cpp-tutorial/stdstring_view-part-2/

## 核心概念

- **拥有者 vs 查看者的类比**：拥有一个对象（自己买车）要花钱，还要负责获取、维护与销毁；查看别人的对象很便宜，但对它没有控制权。
- **`std::string` 是唯一拥有者**：构造时会把初始化器拷贝进自己预留的内存，因此之后不再依赖初始化器。
- **关键要点：初始化后的控制权**："一个已初始化的对象，无法控制初始化完成后初始化值会怎样。" 临时初始化器会立即销毁；若初始化器是变量，则调用方后续可以修改或销毁它。
- **"拥有者"的定义**：称一个对象为拥有者，通常意味着它是**唯一**拥有者，因此对数据的责任归属是明确的。
- **何时不需要拷贝——三条判据**：问原字符串是否可能在形参仍在使用时被销毁、是否可能被修改、函数是否会意外修改该字符串。若三者皆为"否"，则查看是安全的。
- **`std::string_view` 是查看者**：它创建对已有字符串的廉价视图而非拷贝，不能修改被查看对象，销毁视图也不影响被查看对象。
- **视图的生命周期依赖被查看对象**："视图依赖于被查看的对象。" 在视图使用期间修改或销毁被查看的字符串，会导致意外或未定义行为。
- **悬垂视图（dangling）**：查看着一个已被销毁的字符串的 `std::string_view`，称为**悬垂**。
- **最佳用途：只读函数形参**：`std::string_view` 形参可接受 C 风格字符串、`std::string` 或 `std::string_view`，且不拷贝。形参在调用期间创建、调用结束销毁，因此实参不可能在使用中途失效。
- **优先 `std::string_view` 而非 `const std::string&`**：作者建议在多数情况下用 `std::string_view`（见 12.6）。
- **悬垂的场景**：(a) 在嵌套块内把视图指向块内的 `std::string`，块结束后字符串销毁；(b) 用返回 `std::string` 的函数的返回值初始化视图；(c) 用 `"Alex"s` 这样的 `std::string` 字面量初始化视图。
- **修改会使视图失效**：修改 `std::string` 有很大可能使所有指向它的视图失效。若发生内存重分配，视图悬垂；若未重分配，视图可能看到长度错误的数据（"某个子串……或者……超串"）。
- **重新使视图有效**：给已失效的视图赋一个有效字符串，把它恢复到已知良好的状态。
- **返回 `std::string_view` 有风险**：返回局部变量的视图会让返回值悬垂；编译器可能不会给出警告。
- **两种安全的返回情形**：返回 C 风格字符串字面量的视图（它贯穿整个程序）；返回 `std::string_view` 函数形参的视图（其底层实参活得比这次调用长）。
- **临时实参的微妙之处**：若实参是一个临时对象，返回的视图必须在**同一个完整表达式**内使用；之后它便悬垂。
- **视图的修改函数**：`remove_prefix()` 从视图左端裁掉字符，`remove_suffix()` 从右端裁掉；两者都不改动被查看的字符串，且一旦调用，只有重新赋值才能复位视图。
- **子串（substring）定义**：较大字符串中一段**连续**的字符（如 "snowball" 中的 "now"；"owl" 则不是）。
- **不保证以空字符结尾**：C 风格字符串字面量和 `std::string` 总是以空字符结尾；而 `std::string_view` **可能**不是。它自己记录长度，所以这一点通常无所谓。
- **使用指南**：变量层面——需要可修改/接收用户输入/存放返回的字符串用 `std::string`；查看已存在的长生命周期字符串、C 字符串符号常量，或安全延续查看某个返回值时用 `std::string_view`。函数形参层面——要修改副本用 `std::string`；只读或可能不以空字符结尾用 `std::string_view`；C++17 之前或 API 需要时用 `const std::string&`；输出形参用 `std::string&`。返回类型规则类似。
- **总结要点**：`std::string` 初始化/拷贝昂贵，避免按值传递、避免短生命周期字符串，修改会使视图失效；`std::string_view` 主要面向形参和字面量，指向 C 风格字面量永远安全，绝不能在字符串销毁后继续使用。

## 最佳实践

本节没有显式的 Best practice 框；最接近的是"多数情况下优先使用 `std::string_view`"这一建议。其余要点：

- **Warning**：视图依赖于被查看的对象。在使用视图期间修改或销毁被查看对象，会导致意外或未定义行为。
- **Warning**：不要用 `std::string` 字面量（`s` 后缀）初始化 `std::string_view`——它会悬垂。用 C 风格字面量、`std::string_view` 字面量，或活得更久的对象则没问题。
- **Warning**：若实参是在完整表达式结束时销毁的临时对象，返回的 `std::string_view` 必须立即使用。
- **Warning**：不要写出假设 `std::string_view` 以空字符结尾的代码。
- **关键要点**：修改 `std::string` 很可能使所有指向它的视图失效。
- **关键要点**：C 风格字符串字面量与 `std::string` 总是以空字符结尾；`std::string_view` 可能不是。
- **Tip**：若需要从非空字符结尾的 `std::string_view` 得到以空字符结尾的字符串，可把它转换成 `std::string`。
- **For advanced readers**：修改时若发生重分配，视图悬垂；若未重分配，视图可能静默看到子串或超串（含新结尾之后的垃圾数据）。
