# 5.4 The as-if rule and compile-time optimization

> 原文：https://www.learncpp.com/cpp-tutorial/the-as-if-rule-and-compile-time-optimization/

## 核心概念

- **优化（optimization）**：修改软件使其更高效（跑得更快、占用资源更少）的做法，对程序整体性能影响很大。
- **性能分析器（profiler）**：显示程序各部分耗时的工具，能指出拖慢性能的部分。手工调优很慢，因此开发者通常瞄准高层收益（更好的算法、数据布局、更少的资源占用、并行化）。
- **优化器（optimizer）**：一个用来优化另一个程序的程序。优化器通常在低层工作，重写、重排或删除语句与表达式。
- **低层重写示例**：`i = i * 2;` 可能被改写为 `i *= 2;`、`i += i;` 或 `i <<= 1;`。对整数而言它们结果相同，但哪个最快取决于具体架构，而针对特定系统的优化器比人更清楚。
- **累积效应**：单个低层优化带来的收益可能很小，但综合起来能带来显著的总体提升。
- **优化型编译器**：现代 C++ 编译器在编译期间自动进行优化，而且与预处理器一样，绝不修改你的源文件，改动是在编译过程中透明完成的。
- **优化级别**：编译器提供多个级别，用于控制是否优化、优化力度，以及优化类型（例如侧重速度还是体积），因为优化涉及取舍。
- **默认行为**：多数编译器默认不优化。命令行用户要手动开启；IDE 通常在 release 构建中开启、在 debug 构建中关闭。
- **as-if 规则**：只要不改变程序的“可观察行为”，编译器就可以随意修改程序以生成更好的代码。
- **规则的例外**：不需要的拷贝/移动构造函数调用，即使这些构造函数具有可观察行为，也可能被省略（见 14.15 类的初始化与拷贝省略）。
- **编译期求值（compile-time evaluation）**：在编译期而非运行期完整或部分地求值表达式。它让可执行文件更快更小，代价是编译略慢。
- **常量折叠（constant folding）**：编译期求值的一种早期形式，编译器把操作数都是字面量的表达式替换为该表达式的结果，例如把 `3 + 4` 变成 `7`。它也适用于那些仍须在运行期执行的表达式内部的子表达式。
- **常量传播（constant propagation）**：把已知其值的变量替换成那个值。这能消除内存访问，并能创造新的常量折叠机会。
- **死代码消除（dead code elimination）**：删除可能执行、但对程序行为没有影响的代码。因此被去掉的变量称为被“优化掉”（optimized out / optimized away）。
- **const 变量更易优化**：把变量标为 const 就是给编译器一个“该值不会改变”的保证，使常量传播——乃至完全删除该变量——更可能发生（Key insight）。
- **优化会干扰调试**：被优化过的变量、表达式、语句和调用可能被重排、修改、替换或删除，于是编译出的代码与源码对应关系很差。观察被优化掉的变量会失败，步入被优化掉的函数会被跳过。编译期调试也很难，因为“可见性和工具都很少”。因此调试构建通常关闭优化。
- **命名：编译期常量（compile-time constant）**：值在编译期就已知的常量，例如字面量，或由编译期常量初始化的常量对象。
- **命名：运行期常量（runtime constant）**：值在运行期上下文中确定的常量，例如常量函数形参，或由非常量/运行期常量初始化的常量对象。
- **为何不推荐这两个术语**：某些运行期常量（甚至非常量）在 as-if 规则下可能被编译期求值；而某些编译期常量（如 `const double d { 1.2 };`）却不能用于编译期语言特性。本节建议避免这些术语，后继小节会给出更好的命名。

## 最佳实践

本节没有 Best practice / Warning 条目。相关提示：

- **Key insight**：优化型编译器让程序员可以专注写出可读、可维护的代码，而不必牺牲性能。
- **Key insight**：编译期求值让编译器在编译期完成本应在运行期做的工作，结果是更快、更小的可执行文件，代价是编译略慢。
- **Key insight**：使用 const 变量能帮助编译器更有效地优化。
- **Author's note**：编译期调试是“发展不足的领域”（截至 C++23，像 P2758R1 这样正在考虑的提案若获批，未来标准可能加入有帮助的能力）。编译期/运行期常量这两个术语正在从今后的文章中被淘汰。
- 对 gcc/Clang 用户：开启优化的方法见 0.9（配置编译器的构建配置）。
