# 16.2 Introduction to std::vector and list constructors

> 原文：https://www.learncpp.com/cpp-tutorial/introduction-to-stdvector-and-list-constructors/

## 核心概念

- **`std::vector` 是什么**：实现数组的容器类，声明在 `<vector>` 中，是一个类模板，其类型参数决定元素类型。
- **实例化 vector**：`std::vector<int> empty{}` 进行值初始化，因此开始时含 0 个元素。
- **列表初始化**：在大括号里给出你想要的值，初始值个数即元素个数（列表长度）。
- **CTAD（C++17）**：省略元素类型时，编译器可从初始化列表推导元素类型（例如由字符推导出 char 的 vector）。
- **列表构造函数（list constructor）**：一种特殊构造函数，"允许我们用初始化列表构造容器实例"。
- **列表构造函数做什么**：预留足够存储、把容器长度设为初始值个数，并按顺序初始化各元素。
- **下标运算符 `operator[]`**：常用的元素访问方式；方括号内的整数值（下标/索引）用于选取元素。
- **返回引用**：下标运算符返回元素引用而非副本，因此既可赋值也可输出。
- **从 0 开始索引**：C++ 数组从 0 开始计数，作者指出这可能令人困惑，因为人们习惯从 1 数起。
- **索引是偏移量**：索引衡量的是"距第一个元素的距离（偏移）"，索引 0 即起点，索引 1 是下一个元素。
- **有效下标范围**：长度为 N 的数组，下标从 0 到 N−1；不存在下标为 N 的元素。
- **不做越界检查**：`operator[]` 不检查下标有效性，非法下标将导致未定义行为。
- **编译器的调试帮助**：某些编译器（如 Visual Studio）在 debug 构建中插入运行时断言检查下标有效性；断言在 release 构建中消失，因此没有性能开销。
- **连续性**：数组元素"在内存中连续分配"，元素之间没有空隙，也没有逐元素额外开销。
- **快速地址计算**：因为元素相邻，编译器可快速算出任意元素地址（例如 `int` 的地址相差 4 字节）。
- **随机访问**：数组可直接访问任意元素，不同于顺序访问；这种高效性是数组常被优先选用的主要原因。
- **构造指定长度的 vector**：`std::vector<T>(std::size_t)` 构造函数创建 N 个值初始化的元素（`int` 即 0）。
- **必须用直接初始化**：这个长度构造函数必须用圆括号调用，不能用大括号。
- **为什么大括号不同**：对 `{ 10 }` 存在两个候选构造函数，而 C++ 让非空初始化列表优先匹配列表构造函数。
- **歧义规则的例外**：通常多个匹配构造函数会导致编译错误，但"列表构造函数优先"这条特殊规则化解了它。
- **各种初始化形式对比**：`v1 = 10` 拷贝初始化失败（构造函数是 explicit、且非列表值）；`v2(10)` 直接初始化选中单参构造函数；`v3{ 10 }` 与 `v4 = { 10 }` 列表初始化选中列表构造函数；`v5({ 10 })` 是拷贝列表初始化（并非直接初始化）；空括号 `{}` 选中默认构造函数。
- **行为取决于是否存在列表构造函数**：`{ 10 }` 究竟匹配列表构造函数还是单参构造函数，取决于该类是否有列表构造函数；容器一般可认为都有。
- **成员默认初始化器**：成员默认初始化器里不允许用圆括号（直接）初始化，也不允许 CTAD，因此要把构造好的 vector 包进大括号拷贝/列表初始化。
- **`const` vector**：const vector 必须初始化且不可修改；其元素表现为 const，但不允许 `std::vector<const int>` 这类 const 元素类型。
- **const 性的来源**："容器的 const 性来自把容器本身设为 const，而不是把元素设为 const。"
- **不能用 `constexpr`**：`std::vector` 不能是 `constexpr`；需要 constexpr 数组时用 `std::array`。
- **命名历史**：Stepanov 指出 vector 这个名字来自 Scheme 和 Common Lisp，与数学中的用法不一致；这个结构严格说应叫数组。

## 最佳实践

- **Best practice #1**：用带值初始化列表的列表初始化来构造"元素就是这些值"的容器。
- **Best practice #2**：当用"并非元素值"的初始值构造容器（或任何有列表构造函数的类型）时，使用直接初始化。
- **Key insight #1**：索引是距第一个元素的距离：移动 0 个元素仍停在第一个元素上，所以索引 0 是第一个元素。
- **Key insight #2**：若初始化列表为空，默认构造函数优先于列表构造函数。
- **Key insight #3**：若初始化列表非空，匹配的列表构造函数优先于其他匹配的构造函数。
- **Key insight #4（const）**：容器在设计时并未考虑 const 元素：const 性来自让容器本身为 const，而非让元素为 const。
- **Tip #1**：对 N 个元素，下标是 0 到 N−1；不存在下标为 N 的元素，使用 N 会导致未定义行为。
- **Tip #2**：某些编译器（如 Visual Studio）会添加运行时下标断言，在 debug 模式触发、release 模式移除。
- **Tip #3**：对类类型成员，使用拷贝或列表初始化（直接或拷贝皆可），且不允许 CTAD，所以要显式写出元素类型。
- **Warning**：如果某类原本没有列表构造函数、之后才加上，那么用非空初始化列表初始化的对象所调用的构造函数会随之改变。
