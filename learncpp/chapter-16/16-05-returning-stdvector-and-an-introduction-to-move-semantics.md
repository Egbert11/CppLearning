# 16.5 Returning std::vector, and an introduction to move semantics

> 原文：https://www.learncpp.com/cpp-tutorial/returning-stdvector-and-an-introduction-to-move-semantics/

## 核心概念

- **传参与返回的差异**：把 `std::vector` 传给函数时按（const）引用传递，以免昂贵地拷贝底层数组数据；但出人意料的是，按值返回 vector 却没问题。
- **拷贝语义（copy semantics）**：指"决定对象副本如何被制造出来的规则"。若一个类型的对象可拷贝是因为存在这些规则，就说它支持拷贝语义；触发拷贝语义意味着你做了会产生副本的操作。
- **类类型如何实现拷贝语义**：通常通过拷贝构造函数（及拷贝赋值运算符），逐个拷贝数据成员。因此 `std::vector arr2 { arr1 };` 调用拷贝构造函数，产生一个独立但内容等价的 `arr2`。
- **拷贝语义何时不最优**：如果初始化来源是函数返回的临时对象（rvalue），该临时对象在初始化表达式结束时就消亡，之后不再需要其数据。先拷贝再销毁原对象很浪费，因为两份数据从不需要同时存在。
- **移动的思路**：与其拷贝，不如让 `arr2` "窃取"临时对象的数据并成为新所有者；这种数据转移称为被"移动（moved）"。代价极小——"通常只是两三次指针赋值"——被掏空的临时对象销毁时也几乎没有成本。
- **移动语义（move semantics）的定义**："决定一个对象的数据如何被移动到另一个对象的规则。"可移动的数据成员被移动，不可移动的被拷贝。因此移动语义可能比拷贝语义更高效。
- **移动语义何时生效**：通常从同类型对象初始化/赋值用拷贝语义（除被省略外）。只有当三个条件同时成立才用移动语义：该类型支持移动；源是同类型的 rvalue（临时对象）；且移动未被省略。
- **移动支持并不普及**：支持移动语义的类型不多，但 `std::vector` 与 `std::string` 都支持。细节留到第 22 章。
- **按值返回可移动类型**：因为按值返回会产生 rvalue，可移动类型的返回值会被移动而非拷贝进目标，使按值返回非常廉价。这类类型仍应按 const 引用传递。
- **传参-返回的四步流程（可选讨论）**：1) 构造要传的值；2) 把它传给函数；3) 构造要返回的值；4) 把返回值传回调用者。
- **无移动能力时的代价**：示例程序共产生四次拷贝：初始化实参 vector、把实参拷贝进形参、构造返回值、把返回值拷贝回调用者。
- **第 1、3 次拷贝无法优化**：必须存在一个 vector 才能传参，也必须存在一个才能返回；又因为 vector 拥有其数据，它必然要拷贝其初始化来源。只有第 2、4 次拷贝可优化。
- **第 2 次拷贝（调用者→函数）的选项**：按引用/地址传递可行（实参存活期长于调用）；省略不可行（没有多余的拷贝/移动）；输出参数不可行（没有要返回的东西）；移动不可行（实参是 lvalue，从 `v1` 移动会掏空它，导致之后打印 `v1[0]` 是 UB）。因此最佳是 const 引用——避免拷贝、避免空指针问题，且同时接受 lvalue 与 rvalue。
- **第 4 次拷贝（函数→调用者）的选项**：按引用/地址返回不可行（返回时局部对象被销毁，留下悬垂指针/引用）；省略可能可行（按 as-if 规则编译器可以把 `v3` 构造在调用者作用域，但不保证）；输出参数可行但调用语义难看、对不可赋值类型不兼容、难以同时支持 lvalue 与 rvalue；移动可行（`v3` 反正要被销毁，可把其数据移出而非拷贝）。
- **偏好**：省略最佳但不由程序员掌控；对可移动类型而言次佳是移动语义，编译器会在按值返回时自动采用。
- **总结规则**：对可移动类型，优先按 const 引用传递、按值返回。

## 最佳实践

- **Key insight #1**："移动语义是一种优化，允许我们在某些情况下，把某些数据成员的所有权从一对象廉价地转移到另一对象（而非做更昂贵的拷贝）。"无法移动的数据成员会被拷贝。
- **Key insight #2**：像 `std::vector` 和 `std::string` 这样的可移动类型可以按值返回，它们会廉价地移动其值而非做昂贵拷贝；但这类类型仍应按 const 引用传递。
