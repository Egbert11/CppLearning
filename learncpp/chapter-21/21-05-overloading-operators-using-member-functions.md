# 21.5 Overloading operators using member functions

> 原文：https://www.learncpp.com/cpp-tutorial/overloading-operators-using-member-functions/

## 核心概念

- **此前已有两种方式**：运算符可重载为普通（自由）函数，也可重载为友元函数；本节讲第三种——成员函数方式。
- **成员重载与友元重载很像**：机制几乎一样，区别只在放置位置与参数表。
- **规则——作用域**：重载的运算符必须作为**左操作数**所属类的成员。
- **规则——左操作数变成 `*this`**：左操作数不再是参数，而成为隐式的 `*this` 对象。
- **规则——其余操作数变为参数**：其余操作数作为普通函数参数传入。
- **友元转成员的三个步骤**：把它定义为成员而非友元；删掉左参数；去掉函数体中对左参数的引用（`cents.m_cents` 变为 `m_cents`，即隐式引用 `*this`）。
- **调用语法不变**：用户仍写相同的表达式（如 `cents1 + 2`），只是底层定义不同。
- **求值方式的差异**：友元版中 `cents1 + 2` 变成两参数调用 `operator+(cents1, 2)`；成员版中变成 `cents1.operator+(2)`，对象前缀被隐式当作隐藏的最左 `*this` 参数（`operator+(&cents1, 2)`），与友元版几乎相同。
- **并非什么都能写成友元**：赋值 `=`、下标 `[]`、函数调用 `()`、成员选择 `->` **必须**重载为成员函数，这是语言的要求。
- **并非什么都能写成成员**：当左操作数是 `std::ostream` 时，`operator<<` 不能写成成员——因为无法修改标准库类。同理 `operator+(int, Cents)` 不能写成成员，因为 `int` 不是类。
- **一般规则**：当左操作数不是类类型、或是你不能修改的类时，通常无法用成员重载。
- **不修改左操作数的二元运算符**（如 `operator+`）：通常更适合普通/友元版，因为它们适用于任意参数类型，还具有"对称性"（所有操作数都是显式参数）。
- **修改左操作数的二元运算符**（如 `operator+=`）：通常更适合成员版，因为被修改的对象自然就是 `*this`，右操作数是唯一显式参数，减少歧义。
- **一元运算符**：通常重载为成员，因为成员版不带参数。
- **五条实用准则**：`=`/`[]`/`()`/`->` 用成员；一元运算符用成员；不修改左操作数的二元运算符用普通（优先）/友元；修改左操作数但无法给其类加成员的（如 `operator<<`，左操作数是 `ostream`）用普通（优先）/友元；修改左操作数且能改其类定义的（如 `operator+=`）用成员。
