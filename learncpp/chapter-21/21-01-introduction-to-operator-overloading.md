# 21.1 Introduction to operator overloading

> 原文：https://www.learncpp.com/cpp-tutorial/introduction-to-operator-overloading/

## 核心概念

- **回顾函数重载**：函数重载允许同名函数存在多个版本，只要每个版本的函数原型不同；这样可以针对不同数据类型提供同名变体，而不必为每种变体另起名字。
- **运算符重载的定义**：在 C++ 中运算符就是函数，因此对运算符函数做"函数重载"，为不同数据类型（含你自己写的类）定义运算符的专属版本，就叫**运算符重载**。
- **运算符即函数**：表达式 `x + y` 在心智上可翻译为函数调用 `operator+(x, y)`，其中 `operator+` 是函数名。
- **内置版本**：编译器为 int、double 等基础类型内置了 `+` 的版本；写 `w + z`（两个 double）时，重载解析会选择 double 版本而不是 int 版本。
- **程序自定义类型需要自己重载**：对类类型 `Mystring` 使用 `+`，编译器没有可用的内置版本，会报错；想让它像字符串拼接那样工作，必须自己写重载函数告诉编译器 `+` 该如何处理两个 `Mystring` 操作数。
- **编译器如何解析运算符**：
  - 若所有操作数都是基础类型，则调用内置版本（若存在），否则报错。
  - 若任一操作数是程序自定义类型（类或枚举），则走函数重载解析算法，寻找无歧义的最佳匹配。这可能涉及对操作数做隐式转换，或经重载的类型转换把自定义类型隐式转为基础类型以匹配内置运算符；若找不到匹配或匹配有歧义，则报错。
- **哪些运算符可以重载**：几乎所有已有运算符都能重载。例外是：条件运算符 `?:`、`sizeof`、作用域 `::`、成员选择 `.`、成员指针选择 `.*`、`typeid` 以及各种转换运算符（casting operators）。
- **不能发明新运算符**：只能重载已存在的运算符，不能创建或重命名运算符（例如自定义 `operator**` 做幂运算是不允许的）。
- **至少一个操作数须是用户定义类型**：`operator+(int, Mystring)` 合法，`operator+(int, double)` 不合法。
- **标准库类也算用户定义类型**：因此 `operator+(double, std::string)` 技术上可定义，但不是好主意——未来的语言标准可能定义同样的重载，从而破坏依赖你这份重载的程序。只对"至少一个程序自定义类型"重载可避免此风险。
- **操作数个数固定**：不能改变运算符支持的操作数个数。
- **优先级与结合性固定**：无论用于什么类型，运算符都保持默认的优先级和结合性，且无法更改。
- **`^` 的优先级陷阱**：有新手把异或 `^` 重载成幂运算。`^` 的优先级低于算术运算符——数学上 `4 + 3 ^ 2` 应解析为 `13`，而 C++ 里会解析为 `(4 + 3) ^ 2 => 49`。这样每次用都要显式加括号，既反直觉又易错。
- **名称不具描述性**：运算符没有描述性名字，意图未必清晰。例如 `operator+` 做字符串拼接尚算合理，但 `operator-` 对字符串该做什么就不明确了。
- **返回值约定**：不修改操作数的运算符（如算术运算符）通常按值返回结果；修改最左操作数的运算符（如前自增、各赋值运算符）通常按引用返回该最左操作数。
- **收益**：重载让你能以更直观的方式使用自己的类——用 `+` 拼接、用 `<<` 打印、用 `==` 比较。

## 最佳实践

- **Best practice**：重载的运算符应当至少作用于一个程序自定义类型（作为函数参数，或作为隐式对象）。
- **Best practice**：重载运算符时，最好让运算符的功能尽可能贴近它原本的意图。
- **Best practice**：如果某个重载运算符的含义不清晰、不直观，就改用有名字的函数。
- **Best practice**：不修改操作数的运算符（如算术运算符）一般应**按值**返回结果；修改最左操作数的运算符（如前自增、各赋值运算符）一般应**按引用**返回最左操作数。
