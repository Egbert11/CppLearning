# 21.4 Overloading the I/O operators

> 原文：https://www.learncpp.com/cpp-tutorial/overloading-the-io-operators/

## 核心概念

- **打印之痛**：成员变量多的类，逐个打印很繁琐——否则要为一串 `<<` 逐个调用 getter。
- **可复用的 `print()` 成员**：把输出封装进成员函数更好，但它返回 `void`，"无法在一条输出语句中间被调用"。
- **重载 `operator<<` 的目标**：让 `std::cout << "My point is: " << point << ...` 这种自然语法成为可能，无需把输出拆成多条语句。
- **重载方式类似 `operator+`**：两者都是二元运算符，但操作数类型不同——流在左、你的类在右。
- **左操作数类型规则**：`std::cout` 是 `std::ostream` 类型的对象，因此重载的第一个参数是 `std::ostream&`。
- **标准签名**：`friend std::ostream& operator<< (std::ostream& out, const Point& point);`
- **返回类型规则**：要**按引用**返回流；`std::ostream` "明确禁止被拷贝"，按值返回会导致编译错误。
- **链式调用**：返回 `out` 才能让 `std::cout << point << '\n'` 工作，因为它按 `(std::cout << point) << '\n'` 求值。
- **为何 `void` 不行**：若返回 `void`，表达式会变成 `void << '\n';`，"毫无意义！"
- **按引用返回的安全性**：按引用返回左操作数是安全的——它是调用方传进来的，生命周期长于本次函数调用。
- **通用的可链式规则**：凡是希望可链式的二元运算符，都应**按引用返回左操作数**。
- **友元与否**：`operator<<` 只在需要直接访问成员时才是友元；若 getter 够用，也可写成非友元。
- **`operator>>` 与之类似**：`std::cin` 是 `std::istream` 类型；对象参数必须是**非 const**，才能被修改。
- **部分抽取问题**：直接把数据抽取到成员里，可能留下"新值、零值、旧值混杂"的怪状态。
- **部分抽取的成因**：一次成功抽取之后若某次抽取失败，流进入失败态，后续抽取被跳过，于是先前的成员值保持不变。
- **为何要重视**：这种状况绝不可取且可能危险（例如分母变成 `0`，引发除零风险）。
- **事务式操作（定义）**："事务式操作必须要么完全成功、要么完全失败"——没有部分结果；失败时必须撤销先前的改动。
- **银行转账类比**：扣款失败则都不变；入账失败则撤销扣款；两步都成功则两个余额都变。
- **事务式的实现**：先抽取到临时变量，再检查是否成功并一次性赋给所有成员；否则一个成员也不改。
- **条件抽取的 Tip**：`if (in >> x >> y >> z)` 等价于先抽取再判断 `if (in)`。
- **三种事务式策略**：*成功后再改*（先存结果，全部成功才应用）、*失败即恢复*（先拷贝备份，失败时回退）、*失败即回滚*（逐个反向撤销，数据库常用）。
- **一致性注意事项**：抽取失败到基础类型上时会赋 `0`，所以你可能更倾向于把对象重置为默认状态。
- **Author's note**：失败即重置在严格意义上已不再是事务式的；对于"保证无部分结果"的操作，或许可叫"不可分操作"（indivisible operation）。
- **语义无效的输入**：能抽取但非法的值（如分母为 `0`）不会自动触发失败态；需手动 `in.setstate(std::ios_base::failbit);`。
- **结论**：重载 `<<` 和 `>>` 能让你的类方便地做控制台输出与输入。
- **测验要求**：给 `Fraction` 加上 `<<` 和 `>>`；避免部分抽取，分母为 0 时报失败，且失败时不要把对象重置为默认值。

## 最佳实践

本节无正式标注的 Best practice / Warning。原文明示的要点以 Callout 形式给出：

- **Key insight**（事务）：现实生活里事务无处不在。比如从账户 A 转钱到账户 B：先扣 A、再入账 B。执行时只有三种可能——扣款失败（整笔失败，两个余额都不变）、入账失败（撤销扣款）、两步都成功（两个余额都改变）。
- **Tip**：`if (in >> x >> y >> z)` 等价于 `in >> x >> y >> z; if (in)`。每次抽取都返回 `in`，可链式连写。
- **Tip**（三种事务式策略）：*成功后再改*、*失败即恢复*、*失败即回滚*。
- **Author's note**：失败即把对象重置为默认值，技术上已不再是事务式操作（因为失败并非"什么都不做"）；这类"保证无部分结果"的操作没有通用名称，或许可叫"不可分操作"。
