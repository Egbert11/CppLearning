# 11.10 Using function templates in multiple files

> 原文：https://www.learncpp.com/cpp-tutorial/using-function-templates-in-multiple-files/

## 核心概念

- **非模板函数可跨文件协作**：对普通函数，编译器可以依赖某个文件里的前置声明，链接器再把调用接到另一个文件中的定义。
- **模板打破这种分工**：当只可见前置声明时，编译器无法实例化 `addOne<int>` 或 `addOne<double>`，于是假设它们存在于别处；链接器随后报未解析的外部符号错误。
- **定义所在的 .cpp 也不会实例化**：编译存放定义的 .cpp 时不产生任何实例化，因为该文件里没有对模板的使用——因此符号从未被生成。
- **强制实例化很脆弱**：原文指出，如果定义文件实例化了这些函数就能正常工作，但警告这种做法很脆弱：后续修改若不再实例化它们，或别处用到新类型 `addOne<float>`，链接失败就会重现。
- **常规做法——头文件**：模板代码通常放在头文件（.h）中；任何需要它的文件 `#include` 该头文件，预处理器把定义复制进来，编译器便能按需实例化。
- **为什么这不会破坏 ODR**：单定义规则允许类型、模板、inline 函数与 inline 变量在不同文件中有完全相同的定义，因此模板定义的相同副本是允许的。
- **实例化出的函数隐式 inline**：由函数模板隐式实例化出的函数是隐式 inline 的，而 inline 函数只要每个定义相同，就可以在多个文件中定义。
- **模板本身不是 inline**：inline 概念只适用于变量和函数。

## 最佳实践

- **Best practice**：需要在多个文件中使用的模板应定义在头文件中，然后在需要处 `#include`。这样编译器能看到完整模板定义并在需要时实例化模板。
- **Key insight**：模板定义获得 ODR 豁免，因此同一模板定义可被包含进多个源文件；由函数模板隐式实例化出的函数是隐式 inline 的，只要每个定义相同即可在多个文件中定义。
- 相关内容：ODR 与前置声明/定义见 2.7 节。
