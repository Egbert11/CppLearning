# 11.7 Function template instantiation

> 原文：https://www.learncpp.com/cpp-tutorial/function-template-instantiation/

## 核心概念

- **模板不是函数**：模板代码本身不会被编译或运行，它唯一的任务是"生成函数"，生成出来的函数才会被编译和执行。
- **带模板实参的调用语法**：`max<actual_type>(arg1, arg2)`，看起来和普通调用一样，只是多了尖括号里的类型，用于指定替换 `T` 的实际类型。
- **隐式实例化（implicit instantiation）**：当编译器看到 `max<int>(1, 2)` 这样的调用、而对应定义还不存在时，它会自动用模板生成一个。
- **术语**：由模板为具体类型创建函数的过程叫"函数模板实例化"；由调用触发的实例化叫"隐式实例化"。生成出来的函数在技术上是"特化（specialization）"，通常叫"函数实例（function instance）"，所源自的模板叫"主模板（primary template）"。实例与普通函数在各方面行为一致。
- **命名注意**：通常说的 "specialization" 指"显式特化"（刻意定义一个特化版本），在 26.3 节才会讲解。
- **实例化的工作方式**：编译器本质上克隆主模板，把模板类型替换成指定的实际类型。
- **每个翻译单元只实例化一次**：模板在每个翻译单元中只在第一次调用时实例化，之后的调用复用该实例。
- **没有调用就没有实例**：如果某个翻译单元从不调用该模板，它就不会在该单元中被实例化。
- **实参转换**：实例化 `max<double>` 会得到 `double` 形参，因此 `int` 实参会被隐式转换。
- **模板实参推导（template argument deduction）**：当实参类型已经匹配目标类型时，可以省略显式类型，写 `max<>(1, 2)` 或 `max(1, 2)`。
- **重载决议差异**：写空尖括号 `<>` 时只考虑模板重载；完全不加尖括号时，模板实例化和非模板函数都是候选项。
- **非模板优先**：在普通调用语法下，如果模板实例化和非模板函数同样可行，非模板函数胜出。
- **推荐的调用风格**：最常使用普通函数调用形式，因为它简洁；非模板/模板同名配对很少见，而且通常想要的就是非模板版本。
- **为什么通用版与专用版实现会不同**：模板必须适用于多种类型（因此更通用）；非模板只处理一种类型组合，可以针对它做更优化。
- **带非模板参数的模板**：模板可以混合类型模板参数和固定类型的普通参数，返回类型也可以是任意类型。
- **实例可能编译失败**：只有当替换后的代码语法非法时（例如对 `std::string` 使用 `x + 1`）实例才会失败。
- **实例可能语义无意义**：编译器只检查语法，不检查含义。例如给字符串字面量加整数，通过指针算术在语法上是允许的。
- **禁用某实例（进阶）**：把"函数模板特化"与 `= delete` 结合，可以让某个实参类型的使用变成编译错误。
- **非模板参数的默认实参**：模板的非模板参数可以有默认实参，所有实例共享同一个默认值。
- **模板中的 static 局部变量**：每个实例化出的函数拥有自己独立的 static 局部变量副本，这在变量被修改时常常出人意料。
- **泛型编程（generic programming）**：模板类型叫"泛型类型"，用模板编程叫"泛型编程"，让你专注于算法逻辑与数据结构设计，而不是类型细节。
- **结论：优点与缺点**：模板减少维护成本和错误，但可能膨胀出大量代码（代码膨胀 code bloat、编译变慢），并产生难读的错误信息。推荐做法：先写普通函数，在需要针对不同类型重载时再改写成模板。

## 最佳实践

- **Key insight**：正常函数调用语法会优先选择非模板函数，而不是由模板实例化出的同等可行的函数。
- **Best practice**：在调用由函数模板实例化出的函数时，优先使用普通函数调用语法（除非你需要让函数模板版本优先于匹配的非模板函数）。
- **Warning**：只要语法合法，编译器就会实例化并编译语义上不合理的函数模板。确保用合理的实参调用这些模板是你的责任。
- **Best practice（收尾）**：当你有需要处理多种类型时，用函数模板来编写可处理多种类型的泛型代码。
- 进阶读者：可用函数模板特化加 `= delete` 禁止用某些实参实例化；函数模板特化见 26.3 节。
