# 19.1 Dynamic memory allocation with new and delete

> 原文：https://www.learncpp.com/cpp-tutorial/dynamic-memory-allocation-with-new-and-delete/

## 核心概念

- **三种内存分配**：C++ 使用静态分配、自动分配和动态分配；本节讲第三种。
- **静态分配（static allocation）**：用于 static 与全局变量，内存在程序启动时一次性划好，持续整个运行期。
- **自动分配（automatic allocation）**：用于函数参数和局部变量，进入代码块时出现、离开时消失，可随调用反复进出。
- **静态/自动分配的共同限制**：变量或数组的大小必须在编译期已知；分配与释放全自动，无需程序员干预。
- **固定大小的四个问题**（当变量大小依赖外部输入时）：
  1. **浪费内存**：按平均情况预留会留下大量未用空间（名字平均 12 字符却定 25 个）。
  2. **难以追踪用量**：定长数组没有现成办法判断某元素是"还活着 / 已初始化 / 已释放"，需要额外簿记。
  3. **栈很有限**：普通变量与定长数组位于**栈**上，栈很小（Visual Studio 缺省 1MB），超出即栈溢出，程序多半被终止。
  4. **人为上限与溢出**：固定容量会导致报错或截断输入，未检查时还会越界溢出。
- **动态内存分配（dynamic memory allocation）**：运行中的程序按需向操作系统申请内存，取自大得多的内存池——**堆（heap）**，现代机器上可达数 GB。
- **分配单个变量**：`new` 的标量形式申请内存、在其中构造对象，并返回指向该地址的**指针**。
- **必须保存返回值**：把 `new` 的结果存进指针变量，之后才能通过解引用访问这块内存；不保存就再也找不到它。
- **堆比栈慢**：堆访问一般要通过指针，需要"先取地址、再取值"两次内存访问；而栈上变量的地址编译器直接知道。
- **分配过程**：操作系统把程序载入内存（大部分闲置）；程序请求时划出一块并返回地址，之后由程序交还。
- **谁负责**：与静态/自动内存不同，动态内存必须由程序自己申请、自己释放。
  - **Key insight**：栈对象的分配与释放是自动完成的；而堆对象需要一个无歧义的方式来引用，即内存地址——这正是 `new` 返回指针的原因。
- **分配时初始化**：可用直接初始化 `new int (5)` 或统一初始化 `new int { 6 }`。
- **释放单个变量**：`delete` 的标量形式把内存还给操作系统，之后通常把指针置为 `nullptr`。
- **delete 的实质**：并没有"擦除"任何东西，只是把内存交还，操作系统可能重新分配它；指针变量本身仍留在作用域内、可被重新赋值。
- **释放非动态内存**：对不是动态分配的指针 `delete`，"may cause bad things to happen"。
- **悬垂指针（dangling pointer）**：C++ 不保证已释放内存的内容，也不保证指针的值；指向已释放内存的指针即悬垂指针，解引用或再次 `delete` 它是**未定义行为**。
- **多个悬垂指针**：多个指针可指向同一块已释放内存，只把一个置空并不能让其他指针停止悬垂。
- **new 失败**：缺省抛出 `std::bad_alloc`，未捕获则程序因未处理异常而崩溃。
- **nothrow 备选**：在 `new` 与类型之间写 `std::nothrow`，失败时返回空指针而不是抛出。
- **检查结果**：解引用空指针是未定义行为，所以申请后应先检查；因为失败很少见，这个检查常被忘记。
- **空指针的语义**：空指针表示"当前不指向任何内存"，可用于条件式分配。
- **删除空指针是安全的**：`delete` 空指针什么也不做，无需用 `if` 包起来。
- **内存泄漏（memory leak）**：动态内存在显式释放或程序结束前一直存在，但指向它的指针遵循普通局部作用域；最后一个地址丢失后，这块内存再也无法释放。
- **泄漏的后果**：泄漏的内存在程序运行期间对己对人都不可用，严重时会拖慢甚至拖垮机器；操作系统只在进程结束后回收。
- **其他泄漏来源**：把持有动态地址的指针重新赋值；或对同一指针连续两次 `new`——都会丢掉旧地址。
- **小结**：`new`/`delete` 用于动态分配**单个**变量，这类内存具有动态存储期；不要解引用悬垂或空指针；数组见下一节。

## 最佳实践

- **Best practice**：除非指针马上要离开作用域，否则把已 `delete` 的指针置为 `nullptr`。
- **Best practice**：删除空指针是合法的，且什么也不做。
- **原文强调**：避免多个指针指向同一块动态内存；若无法避免，明确指定哪个指针**拥有**（负责 delete）该内存、哪些只是**访问**；申请内存后应先检查结果再使用。
- **提示**：释放不是动态分配的内存"可能引发糟糕的后果"；解引用空指针 / 悬垂指针是未定义行为，通常会崩溃。
