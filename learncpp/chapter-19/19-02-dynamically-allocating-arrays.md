# 19.2 Dynamically allocating arrays

> 原文：https://www.learncpp.com/cpp-tutorial/dynamically-allocating-arrays/

## 核心概念

- **运行期长度**：与长度必须在编译期确定的定长数组不同，动态分配的数组长度可在程序运行时决定——它"does not need to be constexpr"。
- **Author's note（该分配哪种数组）**：本节讲的是动态分配的 **C 风格数组**，这是最常见的形式；动态分配 `std::array` 虽可行，但通常不如直接用（非动态分配的）`std::vector`。
- **分配 / 释放语法**：数组用 `new` 的数组形式分配、`delete` 的数组形式释放，写作 `new[]` 与 `delete[]`。
- **自动选择数组形式**：因为分配的是数组，编译器会自动选用数组版 `new`（即使方括号不紧贴关键字）。
- **长度的类型**：动态数组长度类型是 `std::size_t`；用非 constexpr 的 `int` 需要 `static_cast` 到 `std::size_t`，否则会被视为窄化转换而告警。
- **内存来源与上限**：动态内存来自与定长数组不同的区域，因此可以非常大——大致能分配 1,000,000 乃至 100,000,000 个元素；需要大量内存的程序通常因此选择动态分配。
- **释放数组**：动态数组必须用 `delete[]` 释放，它告诉 CPU 要清理的是多个变量而非一个。
- **误用标量 delete**：对数组用标量 `delete` 是**未定义行为**，可能导致数据损坏、内存泄漏或崩溃。
- **`delete[]` 如何知道长度**：数组 `new[]` 会记录分配了多少内存，`delete[]` 据此释放正确大小；但这个长度对程序员不可见。
- **动态数组 vs 定长数组**：定长数组持有首元素地址、可退化为指向首元素的指针，从而丢失长度（以及 `sizeof()`）；动态数组同样从"指向首元素的指针"开始，也有这些局限，额外的责任是要用 `delete[]` 手动释放。
- **零初始化**：把动态数组初始化为 0 的简洁写法是 `int* array{ new int[length]{} };`。
- **C++11 之前的非零初始化**：当时没有方便的办法把动态数组初始化为非零值（初始化列表只适用于定长数组），只能循环逐个赋值——"Super annoying!"。
- **C++11 初始化列表**：自 C++11 起可用初始化列表初始化动态数组（与定长数组写法对应）；语法上"长度与初始化列表之间没有 `operator=`"；可用 `auto` 省去重复类型。
- **定长数组的统一初始化**：定长数组也能用统一初始化，且可省略长度。
- **调整大小**：C++ 没有内建的重设大小方式。变通做法是分配新数组、拷贝元素、删掉旧的，但这容易出错——对具有特殊创建规则的类类型元素尤其如此。原文建议避免这样做，改用 `std::vector`。

## 最佳实践

- **Author's note**：本节使用动态分配的 C 风格数组，这是最常见的形式；若要"动态数组"，`std::vector` 通常比动态分配的 `std::array` 更好。
- **Warning**：对动态数组误用标量 `delete`（而不是 `delete[]`）是初学者常见错误，会导致未定义行为——内存损坏、泄漏或崩溃。
- **提醒（输入）**：`std::getline()` 可以读入含空格的名字。
- **提醒（排序）**：通过指向数组的指针排序时，需自行计算区间：`std::sort(array, array + arrayLength);`。
