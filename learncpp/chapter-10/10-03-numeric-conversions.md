# 10.3 Numeric conversions

> 原文：https://www.learncpp.com/cpp-tutorial/numeric-conversions/

## 核心概念

- **提升回顾**：上一节讲了较窄数值类型到较宽类型（通常 `int` 或 `double`）的转换，它们能被 CPU 高效处理。
- **数值转换（numeric conversion）**：另一类转换，涵盖基础类型之间除提升之外的其他转换。
- **Key insight**：如果某个转换已被提升规则覆盖，它就算**提升**，不算**转换**。
- **数值转换的五种基本情形**：
  1. 整型 → 整型（不含提升）；
  2. 浮点 → 浮点（不含提升）；
  3. 浮点 → 整型；
  4. 整型 → 浮点；
  5. 整型或浮点 → `bool`。
- **本节为何用拷贝初始化**：花括号初始化会禁止某些数值转换，为了让示例简单，本节故意使用拷贝初始化（`=`）。
- **安全 vs 不安全**：提升总是保值的；许多转换则不保值。**不安全转换**指源类型至少有一个取值无法在目标类型中表示为相等的值。
- **三个安全类别**：
  - **保值（value-preserving，安全）**：目标类型能精确表示源的每个取值。
  - **重解释（reinterpretive，不安全但不丢数据）**：如符号/无符号互换，转换后的值可能不同，但没有信息丢失。
  - **有损（lossy，不安全）**：可能丢失数据。
- **保值转换**：目标类型能精确表示源的所有值（如 `int` → `long`、`short` → `double`）。编译器通常不警告，往返转换能取回原值。
- **重解释转换**：符号/无符号之间的转换；转换值可能不同但不丢数据。`5` 转成 `5`，而 `-5` 会按模回绕成一个超出有符号范围的大值。
- **重解释的往返**：再转回去总能复现原值，即使第一次转换产生了越界结果。
- **有损转换**：可能丢数据，如 `double` → `int`（丢小数）、`double` → `float`（丢精度）。转回去会得到不同的值。编译器通常会对隐式运行期有损转换报警告，有时报错。
- **平台相关性**：安全性可能随平台变化。`int` → `double` 通常安全，但在两者都是 8 字节的架构上就变成有损。
- **何时可接受不安全转换**：当取值可被约束时（已知非负的 `int` 转 `unsigned int`），或当丢失的数据无所谓时（把 `int` → `bool` 用作"是否为零"判断）。
- **越界转换**：几乎总会给出意外结果。溢出对无符号值有定义，对有符号值是未定义行为。
- **同族窄化**：大 → 小在取值装得下时没问题；浮点即使装得下也可能因精度损失而被舍入。
- **整数 ↔ 浮点**：整数 → 浮点在取值落于浮点类型的范围时可行；浮点 → 整数会丢掉小数部分。
- **结论**：编译器一般会对危险的转换发出警告，但部分符号/无符号情形除外。

## 最佳实践

本节无 Best practice 条目。相关提示框有：

- **Key insight**：已被提升规则覆盖的转换"称为数值提升，而不是数值转换"。
- **As an aside**：花括号初始化会拒绝某些转换，所以本课故意用拷贝初始化来简化示例。
- **Related content**：越界的符号/无符号转换在 4.12《Introduction to type conversion and static_cast》中讲解。
- **Warning（符号/无符号）**：多数编译器默认关闭隐式的符号/无符号转换警告，因为这类转换往往难以避免且通常无害，开启后会淹没真正的警告。若保持关闭，要自己留意意外的反号转换，尤其是函数实参。
- **For advanced readers**：C++20 之前，越界的无符号转有符号在技术上是实现定义的（因为有符号整数可能用别的二进制表示）；C++20 要求补码，使该情形有确定的模回绕定义——但有符号算术溢出仍是未定义行为。
- **Warning（平台相关）**：有些转换会因平台而改变类别。`int` → `double` 通常安全（4 字节 `int`、8 字节 `double`），但两者都是 8 字节时就变成有损。
