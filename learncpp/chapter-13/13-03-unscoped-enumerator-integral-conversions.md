# 13.3 Unscoped enumerator integral conversions

> 原文：https://www.learncpp.com/cpp-tutorial/unscoped-enumerator-integral-conversions/

## 核心概念

- **枚举量是带整数值的符号常量**：就像 `char` 实际存储的是一个 1 字节的整数值一样，枚举量持有的也是某个整数类型的值。
- **默认取值规则**：第一个枚举量得 0，之后每个枚举量取"前一个 + 1"。
- **允许显式赋值**：可以显式给枚举量赋正数或负数，值也可以重复；未赋值的枚举量仍取"前一个 + 1"。
- **重复值使枚举量"不再可区分"**：两个枚举量共享同一个值时彼此可互换，C++ 允许但不推荐。
- **Best practice**：除非有充分理由，避免给枚举量显式赋值。
- **枚举的零初始化**：对枚举做值初始化会得到整数值 0，即使没有任何枚举量等于 0。
- **推论 A**：如果确有枚举量值为 0，值初始化就默认取它——所以让值为 0 的枚举量承载最合适的默认含义是个好主意。
- **推论 B**：若没有 0 值枚举量，值初始化很容易产生语义上无效的枚举；建议加一个值为 0 的 "invalid"/"unknown" 枚举量，让该状态有文档可依、可被显式处理。
- **Best practice**：让代表 0 的枚举量承载最合适的默认含义；否则加一个值为 0 的 "invalid"/"unknown" 枚举量。
- **无作用域枚举隐式转换为整数，但本身不是整数类型**：它是复合类型；这个转换是 constexpr 转换。
- **重载解析顺序**：编译器先尝试匹配枚举类型本身的重载；若不存在，再尝试枚举可转换到的整数类型。
- **底层类型（base / underlying type）**：真正存放枚举量值的那个整数类型。无作用域枚举的底层类型标准留给实现定义，大多数编译器用 `int`（除非需要更大类型）。也可以显式指定，且必须是整数类型。
- **Best practice**：只在必要时指定底层类型。
- **Warning**：由于 `std::int8_t`/`std::uint8_t` 通常是字符类型的别名，用它们当底层类型很可能导致枚举量按字符而不是整数打印。
- **整数不会隐式转换为无作用域枚举**：编译器默认不会把整数转成无作用域枚举。
- **绕法一：`static_cast`**：把"某个枚举量所表示的整数值"以及"底层类型范围内的任意值"转成枚举是安全的；超出该范围则是未定义行为。
- **Advanced：安全范围**：显式指定底层类型时，安全范围等于该类型的范围；未指定时，只有能装下所有枚举量值的最小位宽范围内的值才安全。
- **绕法二（C++17）**：若无作用域枚举显式指定了底层类型，则允许用整数做列表（花括号）初始化；直接初始化、拷贝初始化和赋值仍会报错。
- **测验要点**：枚举量可以赋整数值、不赋值、负值、重复值、或引用前一个枚举量的值；但不能是浮点值或非 constexpr 值，因为枚举量本身就是 constexpr。

## 最佳实践

- **Best practice**：除非有充分理由，避免给枚举量显式赋值。
- **Best practice**：让代表 0 的枚举量承载最合适的默认含义；若没有合适的默认值，就加一个值为 0 的 "invalid"/"unknown" 枚举量，以便记录并显式处理该状态。
- **Best practice**：只在必要时指定枚举的底层类型。
- **Warning**：因为 `std::int8_t` 和 `std::uint8_t` 通常是字符类型的别名，用它们作枚举底层类型很可能让枚举量按字符而非整数打印。
- **Related content**：枚举与字符串互转见 13.4；让 `std::cout` 能打印枚举量见 13.5。
