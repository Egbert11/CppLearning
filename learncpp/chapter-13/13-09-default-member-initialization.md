# 13.9 Default member initialization

> 原文：https://www.learncpp.com/cpp-tutorial/default-member-initialization/

## 核心概念

- **默认成员初始化（default member initialization）**：在定义 struct/class 时，直接为每个成员写一个默认值；对非静态成员而言，这称为**非静态成员初始化（non-static member initialization）**，写在成员后面的 `{}` 或 `{ 2 }` 就是**默认成员初始化器（default member initializer）**。
- **默认值何时生效**：当创建对象时用户**没有显式提供**初始化器时，才使用默认成员初始化值。
- **无初始化列表**：有形如 `{ 2 }` 这类默认值（或空 `{}`）的成员使用默认值；完全没有默认值的成员保持未初始化。
- **Key insight**：借助默认成员初始化器，"即使没有提供显式初始化器，struct 和 class 也能自我初始化！"
- **显式优先于默认**：显式初始化列表中的值总是**覆盖**默认成员初始化值；如果每个成员都显式给了值，则根本不使用默认值。
- **缺省时的回退**：通常缺省的成员会被**值初始化**；但若该成员存在默认成员初始化器，则改用该默认值。
- **规则速记（带初始化列表的聚合）**：显式给了值 → 用显式值；缺省且有默认值 → 用默认值；缺省且无默认值 → 值初始化。
- **规则速记（不带初始化列表的聚合）**：有默认值 → 用默认值；无默认值 → 成员保持未初始化。
- **初始化顺序**：**成员永远按声明顺序初始化**。
- **危险情形**：在不带花括号定义的对象里，没有默认初始化器的成员会保持未初始化——教程称之为坏做法。
- **建议**：给**每个成员**都提供默认值（显式值或空 `{}`），这样无论是否使用初始化列表，成员都会被初始化。
- **默认初始化 vs 值初始化（聚合）**：当所有成员都有默认值时，两者结果相同；但值初始化（空花括号 `{}`）更安全，因为它会对任何"意外漏掉默认值"的成员执行值初始化。
- **一致性**：偏好值初始化也与其它类型对象的初始化方式一致，可减少错误。
- **保留意见**：出于历史原因（值初始化 C++11 才加入）以及非聚合类型中默认初始化可能更高效，教程推荐但不强制使用值初始化。
- **相关**：静态成员及静态成员初始化见 15.6；CTAD 不能用于非静态成员初始化。

## 最佳实践

- **Best practice**：**为所有成员提供默认值。** 这能确保即使变量定义中不含初始化列表，成员也会被初始化。
- **Best practice**：**对聚合类型，优先使用值初始化（空花括号初始化器）而非默认初始化（无花括号）。**
- **Key insight**：使用默认成员初始化器（或后续介绍的其它机制），struct 和 class 可以在没有显式初始化器时自我初始化。
- **For advanced readers**：CTAD（见 13.14）不能用于非静态成员初始化。
- **Related content**：静态成员及静态成员初始化见 15.6。
