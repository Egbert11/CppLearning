# 13.2 Unscoped enumerations

> 原文：https://www.learncpp.com/cpp-tutorial/unscoped-enumerations/

## 核心概念

- **枚举的动机**：基本类型和复合类型有时无法表达"取值范围很有限的一组相关值"（例如苹果只能是红、黄、绿之一）。
- **魔法数字做法**：把颜色存成 `int`（0 表示红）并不直观，全靠注释和魔力数字。
- **符号常量做法**：给值起名（`red`、`green`、`blue`）可读性更好，但并没有强制变量只能取这些值。
- **类型别名捷径**：`using Color = int;` 给了一个可搜索的名字，但仍不提供任何使用约束。
- **没有真正的类型安全**：因为 `Color` 就是 `int`，像 8 这种越界值是"语法上合法、语义上毫无意义"；调试器里也只会显示整数。
- **`bool` 是灵感来源**：`bool` 只有两个定义好的值，且编译器把它与其他类型区分开，因此可以重载。
- **枚举的定义**：枚举（enumerated type / enum）是一种复合数据类型，取值被限制为一组命名的符号常量，这些常量叫做枚举量（enumerator）。
- **C++ 有两种枚举**：无作用域枚举（本节）和有作用域枚举（13.6 节）。
- **属于程序自定义类型**：每个枚举都必须先完整定义后使用，前置声明不行。
- **语法规则**：`enum` 关键字引入无作用域枚举；枚举量在花括号里、用逗号分隔（不是分号）；末尾逗号"可选但推荐"；定义以分号结尾。
- **初始化受限**：枚举类型的变量只能用该类型的枚举量来初始化，用别的会编译错误。
- **隐式 constexpr**：枚举量隐式地是 `constexpr`。
- **术语辨析**：枚举/枚举类型指类型本身（如 `Color`）；枚举量是其中某个具名值（如 `red`）。
- **命名约定**：枚举类型名按惯例首字母大写；现代 C++ 中应避免匿名枚举。
- **枚举量命名**：枚举量必须有名字，且没有唯一的通用命名约定。
- **彼此不同的类型**：每个枚举都是独立的类型（不同于 typedef/别名），所以枚举量不能跨枚举混用。
- **典型用途**：对象一次只取一个值的小型相关常量集合：星期、方位、花色、状态码、物品/怪物/地形类型、函数选择参数等。
- **状态码**：枚举可以把"描述性但晦涩"的魔法返回值（-1/-2/-3）替换成可读的枚举量。
- **布尔值**：在 C++ 里 `true`/`false` 是关键字而非枚举量，尽管布尔在概念上就是两值枚举。
- **拷贝成本**：枚举很小、拷贝很便宜，按值传递和返回都没有问题。
- **位标志**：枚举可以定义位标志位置供 `std::bitset` 使用；无作用域枚举量会隐式转换为整数值（13.3 节详述）。
- **作用域规则**：无作用域枚举把枚举量放进与枚举本身相同的作用域，而不是新建作用域区域，因此会污染外层作用域、提高重名风险。
- **冲突后果**：同一作用域内两个无作用域枚举不能重用同名枚举量。
- **仍可加限定名访问**：无作用域枚举本身仍是一个具名作用域区域，所以 `Color::red` 也合法，只是通常不写作用域解析运算符。
- **避免冲突之一：加前缀**：给枚举量加前缀（如 `color_red`）仍会污染命名空间，但降低冲突概率。
- **避免冲突之二：命名空间**：把枚举放进命名空间（或类）里就得到独立作用域，需要 `Feeling::blue` 这样的限定名。
- **函数内定义枚举**：若某枚举只在一个函数内使用，就定义在那里；它的枚举量会遮蔽同名的全局枚举量。
- **比较**：相等运算符 `==`、`!=` 可用来判断枚举当前持有哪个枚举量。

## 最佳实践

- **Best practice（命名）**：枚举类型名以大写字母开头；枚举量名以小写字母开头。
- **Best practice（作用域）**：优先把枚举放进具名作用域区域（如命名空间或类），以免枚举量污染全局命名空间。
- **Warning**：枚举不一定要有名字，但现代 C++ 中应避免匿名枚举。
- **Reminder（术语）**：区分"枚举/枚举类型"（类型本身，如 `Color`）与"枚举量"（具名值，如 `red`）。
- **Advanced readers**：类也提供作用域区域，与某个类相关的枚举类型常被嵌套在类里（见 15.3 嵌套/成员类型）；有作用域枚举是另一种选择（13.6 节）。
