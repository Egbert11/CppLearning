# 13.1 Introduction to program-defined (user-defined) types

> 原文：https://www.learncpp.com/cpp-tutorial/introduction-to-program-defined-user-defined-types/

## 核心概念

- **基本类型无需定义**：基本类型是 C++ 核心语言的一部分，因此可以直接声明 `int`、`double` 变量。
- **简单复合类型也无需定义**：函数、指针、引用、数组都由已知的类型名或符号拼成，不需要导入或定义。
- **类型别名必须先定义**：`using Length = int;` 引入一个新标识符，编译器必须先看到定义才能使用它；但这条定义本身不创建任何对象。
- **为什么要程序自定义类型**：C++ 无法预先想到每一种有用的类型（比如"分数"），所以允许程序员创建全新的自定义类型。
- **术语偏好**：这类自定义类型通常叫"用户自定义类型（user-defined type）"，本节更偏好"程序自定义类型（program-defined type）"这一说法。
- **两类复合类型**：用作程序自定义类型的是枚举类型（无作用域/有作用域枚举）与类类型（struct、class、union）。
- **先定义后使用**：和类型别名一样，程序自定义类型必须先有名字并先给出定义才能使用；这个定义称为**类型定义（type definition）**。
- **Key insight**：程序自定义类型必须先有名字、先有定义才能使用；其他复合类型两者都不需要。
- **函数被排除在外**：函数也需要名字和定义，但被命名的是函数本身而不是它的类型，因此这类东西叫用户自定义*函数*。
- **分号规则**：类型定义必须以分号结尾，这是常见错误，而且"很难调试，因为编译器可能会在类型定义的*下一行*报错"。
- **命名约定**：程序自定义类型的名字以大写字母开头且不加后缀（写 `Fraction`，而不是 `fraction` 或 `fraction_t`）。
- **类型名与变量名不冲突**：大写类型名后跟小写变量名不会冲突，因为 C++ 区分大小写。
- **多文件要求**：每个使用某程序自定义类型的文件都必须看到完整定义；前置声明不够，因为编译器需要知道分配多少内存。
- **头文件约定**：把共享的类型定义放进以该类型命名的头文件（如 `Fraction.h`），在使用处 `#include` 它。
- **ODR 的部分豁免**：与函数、全局变量不同，一个类型可以定义在多个代码文件中（例如两个文件都 include 了 `<iostream>`）。
- **豁免的两个前提**：每个代码文件里该类型只能有一份定义（头文件保护通常已处理）；且同一类型的所有定义必须完全一致，否则是未定义行为。
- **术语辨析（user-defined vs. program-defined）**：日常语境里"用户自定义类型"= 你自己定义的类型；但语言标准里它还包括标准库和实现定义的类型，所以 `std::string` 也算 user-defined。C++20 把"程序自定义类型"定义为：非标准库、非实现、非核心语言定义的类类型与枚举类型。
- **分类小结**：基本类型（核心语言，如 `int`、`std::nullptr_t`）；复合类型（由其他类型定义，如 `int&`、`double*`、`std::string`、`Fraction`）；用户自定义类型（类或枚举类型，含库/实现的）；程序自定义类型（类或枚举类型，不含库/实现的，如 `Fraction`）。

## 最佳实践

- **Best practice（命名）**：程序自定义类型的名字以大写字母开头，且不要加后缀。
- **Best practice（放置位置）**：只在单个代码文件中使用的程序自定义类型，应定义在该文件中靠近其首次使用处；在多个文件中使用的类型应放进以该类型命名的头文件，并在每个需要它的文件中 `#include`。
- **Warning**：别忘记给类型定义结尾加上分号。
- **Key insight**：程序自定义类型必须先有名字和定义才能使用；其他复合类型两者都不需要。
