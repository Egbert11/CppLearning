# 13.8 Struct aggregate initialization

> 原文：https://www.learncpp.com/cpp-tutorial/struct-aggregate-initialization/

## 核心概念

- **成员默认不初始化**：和普通变量一样，数据成员不会得到默认初始化；在赋值之前读取某个成员是未定义行为。
- **聚合体（一般含义）**：任何持有多个数据成员的类型——struct 可以混合类型，数组不行。
- **聚合体（C++ 含义）**：更窄：C 风格数组，或满足以下条件的 class/struct/union——没有用户声明的构造函数、没有 private/protected 的非静态数据成员、没有虚函数。`std::array` 也符合。只含数据成员的 struct 就是聚合体。
- **聚合初始化**：聚合体通过初始化列表来初始化——一个逗号分隔的花括号列表，按顺序直接作用于各成员。
- **两种主要形式**：拷贝列表初始化（`= { ... }`）和列表初始化（`{ ... }`）；后者更受推荐。
- **逐成员初始化**：值按成员声明顺序映射。
- **C++20 带括号形式**：可以用带括号的值列表初始化某些聚合体，但遇到花括号省略（尤其是 `std::array`）会失败，因此不推荐。
- **初始化器太少时**：未列出的成员若有默认成员初始化器就用它；否则从空列表拷贝初始化，通常也就是值初始化为 0。
- **空列表技巧**：空初始化列表会把所有成员值初始化。
- **打印 struct**：为 struct 重载 `operator<<` 是常见便利做法，格式由你决定。
- **const struct**：struct 类型变量可以是 `const`/`constexpr`，和以往一样必须初始化。
- **指定初始化器（C++20）**：可以点明每个值对应哪个成员；必须按声明顺序给出，否则会警告/报错；未被指定的成员会被值初始化。
- **顺序的脆弱性**：在 struct 中间插入一个成员会悄悄改变其后所有初始化器的含义，而编译器可能不会报错。
- **用初始化列表赋值**：`joe = { ... }` 做逐成员赋值；不需要改动的成员也要填一个占位值。
- **指定赋值（C++20）**：`joe = { .id = ..., ... }`；未被指定的成员得到其值初始化后的值。
- **从同类型拷贝**：聚合体可以用同类型的另一个对象初始化（走的是拷贝/直接/直接列表初始化，而非聚合初始化）——从函数返回值初始化时很常见。

## 最佳实践

- **Author's note**：本系列在说 "aggregate" 或 "non-aggregate" 时，都采用 C++ 的含义。
- **For advanced readers**：C++ 中聚合体是 C 风格数组，或没有用户声明构造函数、没有非 public 的非静态数据成员、没有虚函数的类类型。
- **Best practice**：初始化聚合体时优先使用（非拷贝的）花括号列表形式。
- **Best practice**：新增成员时，把它"放在定义列表的底部，以免其它成员的初始化器发生位移"。
- **Tip**：空初始化列表可以"值初始化 struct 的所有成员"。
- **For Clang users**：用花括号做指定初始化时，Clang 可能误报 "braces around scalar initializer" 警告。
- **Note（指定初始化器）**：有助于自文档化，但也让列表变臃肿，因此本节暂不把它推荐为最佳实践。
