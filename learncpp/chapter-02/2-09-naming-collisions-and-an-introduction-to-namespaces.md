# 2.9 Naming collisions and an introduction to namespaces

> 原文：https://www.learncpp.com/cpp-tutorial/naming-collisions-and-an-introduction-to-namespaces/

## 核心概念

- **命名冲突（naming collision / naming conflict）**：当两个同名标识符以编译器或链接器无法区分的方式进入同一程序时，就会报错。
- **报错位置**：同一文件里的冲突产生**编译错误**；同一程序不同文件之间的冲突产生**链接错误**。最常见的情形是——不同文件里同名的函数或全局变量（链接错误）、同一文件里同名的函数或全局变量（编译错误）。程序越大、标识符越多，冲突概率越高。
- **作用域区域（scope region）**：一段源代码区域，其中声明的标识符与其它作用域里的同名标识符被视为不同。同名标识符可以存在于不同作用域区域，但在同一区域里所有标识符必须唯一。函数体就是一个作用域区域（两个同名标识符可分别定义在两个函数里，但不能在同一个函数里）。
- **命名空间（namespace / namespace scope）**：一种作用域区域，用来消除名字歧义，其中的名字与其它作用域隔离。命名空间里**只能放声明和定义**（变量、函数），不允许出现可执行语句（除非它是某个定义的一部分）。常用做法是把一组相关标识符放进一个命名空间（例如把数学函数放进 `math`）。
- **全局命名空间（global namespace / global scope）**：任何没有定义在类、函数或命名空间内部的名字，都属于隐式定义的全局命名空间。全局作用域里声明的标识符从其声明点起、到文件末尾都可见。在全局命名空间里定义变量能编过，但一般应避免。
- **`std` 命名空间**：早期标准库标识符都放在全局命名空间，容易与用户代码及不同语言版本冲突；因此 C++ 把标准库功能全部移入名为 `std`（standard 的缩写）的命名空间。
- **`std::cout` 的解读**：真正的名字是 `cout`，`std` 是它所在的命名空间，所以不会与你别处定义的 `cout` 冲突。
- **显式命名空间限定**：最安全的引用方式是加 `std::` 前缀，明确指出用的是哪个 `cout`。
- **作用域解析运算符（scope resolution operator）`::`**：`::` 左边的标识符指明右边名字所在的命名空间；左边为空时默认为全局命名空间。带命名空间前缀的标识符称为**限定名（qualified name）**。
- **using 指令（using directive）**：如 `using namespace std;`，允许不加前缀就访问该命名空间里的名字。
- **为何不推荐 `using namespace std;`**：写在程序顶部时，你定义的名字可能和 `std` 里任意同名标识符（包括未来版本新增的名字）冲突。
- **花括号与缩进**：花括号常用来划定嵌套作用域区域，区域内的代码约定缩进一级以便阅读；写在大括号外的函数参数仍可能属于该括号作用域。

## 最佳实践

- 使用显式命名空间前缀来访问命名空间中的标识符（例如 `std::cout`）。
- **Warning**：避免在程序顶部或头文件中使用 using 指令（如 `using namespace std;`）——这会违背当初引入命名空间的初衷。
