## 核心概念

本章（C++ Basics: Functions and Files）小结要点，按原文顺序：

- **函数（function）**：可复用的语句序列，完成特定工作；自己写的称为"用户定义"函数。
- **函数调用（function call）**：让 CPU 运行某函数的表达式；发起方叫**调用者（caller）**，被调方叫**被调用者（callee）**；圆括号必需。
- **函数体（function body）**：函数定义中的花括号及其语句。
- **有返回值函数**：返回一个值；**返回类型**指明类型，**return 语句**给出具体的**返回值**。把返回值复制回调用者的过程称为"按值返回（return by value）"；非 void 函数缺省 return 属于未定义行为。
- **状态码（status code）**：`main` 的返回值，交给操作系统及调用它的程序；约定 **0 表示成功，非 0 表示失败**。
- **DRY**："don't repeat yourself"，用变量和函数消除重复代码。
- **void 函数**：不向调用者返回值，不能用在需要值的地方。
- **提前返回（early return）**：位于函数最后一条语句之前的 return，会立即返回调用者。
- **形参 vs 实参**：形参（parameter）是函数里的变量，实参（argument）是调用者传入的值；把实参复制进形参称为**按值传递（pass by value）**。
- **局部变量**：形参和函数体内声明的变量。**生命周期（lifetime）**是变量存在的时间（创建/销毁发生在**运行时**）；**作用域（scope）**是变量可见/可用的范围（"在作用域内/外"），是**编译期**属性。
- **空白符（whitespace）**：格式化字符，C++ 中即空格、制表符和换行。
- **前置声明（forward declaration）**：在定义之前告诉编译器某标识符存在；对函数而言即**函数原型（function prototype）**（返回类型、名字、参数、无函数体、以分号结尾）。
- **定义 vs 声明**：定义实现/实例化标识符，声明只是宣布它存在。所有定义都是声明；**纯声明**（如原型）不是定义。
- **多文件**：大多数非平凡程序由多个文件组成。
- **命名冲突 / 命名空间**：标识符歧义会导致编译或链接错误；命名空间让其中标识符保持唯一，如 `std`。
- **预处理器 / 指令 / 宏**：预处理器在编译之前运行；指令以 `#` 开头、以换行结束；宏把输入文本映射为替换文本。
- **头文件**：把声明传播到各代码文件；`#include` 被替换为被包含文件的内容。系统头用尖括号，自己的头用双引号；有可用版本时优先用不带 `.h` 的标准库头。
- **header guard**：阻止头文件在同一代码文件中被多次包含，但不阻止它在不同文件中各被包含一次。

## 最佳实践

- 即便 `io.cpp` 技术上不需要 `io.h`，配对的代码文件也应包含它对应的头文件（详见 2.11）。
- 保持代码格式一致、可读——可用编辑器的自动格式化。

## 本章知识速览

Chapter 2 全章要点清单（2.1–2.13）：

1. **函数基础（2.1）**：函数是完成特定任务的语句序列；调用、定义、函数体、语义。
2. **有返回值函数（2.2）**：返回类型、return 语句、按值返回、缺省 return 未定义行为、`main` 的状态码约定。
3. **void 函数（2.3）**：不返回值，不能在需要值处使用。
4. **函数参数与实参（2.4）**：形参/实参、按值传递、多个参数、如何传入数据。
5. **局部变量（2.5）**：生命周期（运行时）与作用域（编译期）的概念区分。
6. **为什么用函数 + 声明/定义（2.6–2.7）**：DRY、可复用性；定义与声明之别、纯声明、函数原型、前置声明解决"先使用后定义"。
7. **多代码文件（2.8）**：`.cpp` 独立编译、前置声明 + 链接、每文件独立 `#include`、不要 `#include` `.cpp`。
8. **命名冲突与命名空间（2.9）**：冲突的编译/链接表现、作用域区域、命名空间、`std`、`::`、限定名、`using` 指令的风险。
9. **预处理器（2.10）**：预处理先于编译、翻译单元、以 `#` 开头的指令、宏（对象式/函数式）、条件编译 `#ifdef/#ifndef/#endif`、`#if 0`、宏的作用范围。
10. **头文件（2.11）**：用头文件集中声明、双引号 vs 尖括号、头文件里放定义会违反 ODR、源文件包含配对头、避免包含 `.cpp`、包含顺序与最佳实践。
11. **header guard（2.12）**：`#ifndef/#define/#endif` 防止同一文件重复包含、命名约定、`#pragma once`、guard 不能阻止跨文件重复定义。
12. **设计程序（2.13）**：先设计后编码、五步设计、三步实现、Words of Advice（简单起步、渐进加功能、一次专注一处、边写边测、不过早打磨、优先可维护性）。

## 测验

- **第 1 题**：在单个文件 `main.cpp` 中，让用户输入两个整数、求和并打印结果。要求用三个函数组织：`readNumber()`（读取并返回一个整数）、`writeAnswer()`（接收一个参数、无返回值，负责打印结果）、`main()`（把两者串起来）。提示：不需要单独的加法函数，直接用 `operator+`；`readNumber()` 要用两次。
  - 解答见 [2-14-quiz1.cpp](2-14-quiz1.cpp)。
- **第 2 题**：改写第 1 题，把 `readNumber()` 与 `writeAnswer()` 放进单独的 `io.cpp`，`main()` 通过前置声明调用它们。排错提示：确保 `io.cpp` 已加入项目并被编译。
  - 解答见 [2-14-quiz2/main.cpp](2-14-quiz2/main.cpp) 与 [2-14-quiz2/io.cpp](2-14-quiz2/io.cpp)。
- **第 3 题**：改写第 2 题，用一个头文件 `io.h` 提供函数声明（替代内联前置声明），并要求该头文件带 header guard。
  - 解答见 [2-14-quiz3/main.cpp](2-14-quiz3/main.cpp)、[2-14-quiz3/io.h](2-14-quiz3/io.h) 与 [2-14-quiz3/io.cpp](2-14-quiz3/io.cpp)。

### 排错提示（原文）

- `unresolved external symbol "int __cdecl readNumber(void)" (?readNumber@@YAHXZ)`
- `` undefined reference to `readNumber()' ``

出现上述链接错误，通常说明 `io.cpp` 没被加入项目，导致其中的函数定义从未被编译。
