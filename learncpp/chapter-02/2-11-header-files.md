# 2.11 Header files

> 原文：https://www.learncpp.com/cpp-tutorial/header-files/

## 核心概念

- **头文件为何存在**：在每个文件里手抄前置声明无法扩展，头文件把声明集中到一处，需要时再引入。
- **头文件（header file）**：通常以 `.h` 结尾（也有 `.hpp` 或无扩展名），用于把相关的前置声明传播到各个代码文件。它让我们"把声明放在一个地方，然后在需要处导入"，省去重复输入。
- **`#include` 如何工作**：预处理器在被包含处把整个文件内容复制进来，从而引入别处的声明。标准库同理——`<iostream>` 前置声明了 `std::cout`，否则你得手抄每一个相关声明，且原型一变就要同步更新。
- **头文件的构成**：两部分——header guard（下一节讲）和实际内容（供其它文件使用的前置声明）。
- **把头文件加入项目**：步骤与源文件相同，类型选 "Header"；命令行下只要建文件即可，注意头文件**不应**出现在编译命令里。
- **包含自己的头文件用双引号**：`#include "add.h"`，不用尖括号。
- **在头文件里放定义会违反 ODR**：把函数或变量**定义**写进头文件，一旦该头文件被多个源文件包含，通常违反单一定义规则（ODR）；因为每个 `.cpp` 单独都能编过，但链接器会看到重复定义。ODR 第二部分要求：同一程序里，变量或普通函数只能有一个定义。
- **源文件应包含与它配对的头文件**：这样声明与定义不一致时，编译器能在编译期就报错，而不是拖到链接期。例如函数定义的返回类型与头文件声明冲突时，编译器立即报错；若源文件没包含该头文件，则这种不匹配不可见，只在链接期才暴露。（旁注：此技巧对**参数类型**不匹配无效，因为 C++ 重载会让编译器把它当作另一个重载。）
- **不要 `#include` `.cpp` 文件**：理由是——源文件之间的命名冲突、大型项目里难以避免的 ODR 问题、被包含文件变动导致不必要的重编译，以及这不符合惯例。若你的项目只有这样做才能编译，说明那些 `.cpp` 根本没被编译，请把它们加入项目或编译命令。
- **尖括号 vs 双引号**：尖括号表示"不是你写的头文件"，预处理器只在配置的**包含目录（include directories）**里查找，不搜你当前源码目录；双引号表示"你自己的头文件"，先搜当前目录，再搜包含目录。
- **`<iostream>` 为什么没有 `.h`**：`iostream.h` 其实是另一个头文件。最初所有标准头都以 `.h` 结尾、名字位于全局命名空间；标准化时名字移入 `std`，于是新增了无扩展名的新式头，旧头为兼容而保留。
- **四类标准头**：新式 C++ 专属 `<xxx>`、新式 C 兼容 `<cxxx>`、旧式 C++ `<xxx.h>`、旧式 C 兼容 `<xxx.h>`。新式头把名字放进 `std`（C 兼容的可能也放进全局命名空间）；旧式头用全局命名空间（C 兼容的可选地也放进 `std`）。
- **其它目录下的头文件**：在 `#include` 里写相对路径是"坏"做法，会把目录结构写死进代码。更好的是在 IDE 项目设置里配置**包含路径/搜索目录**（VS：属性 → VC++ Directories → Include Directories；Code::Blocks：Build Options → Search directories；g++：`-I./source/includes`，`-I` 后不要空格；VS Code：在 `tasks.json` 里加 `"-I./source/includes",`）。
- **头文件可以包含其它头文件**：若某头文件用到了别处声明或定义的东西，它应自己包含相应头文件（例如 `std::string_view` 需要 `<string_view>`）。
- **传递包含（transitive include）**：被包含的头文件间接带入的头文件。其内容可用，但不应依赖，因为头文件实现会随时间和系统变化。
- **包含顺序**：在头文件都写正确的前提下，顺序不影响结果；但若某头文件漏了它需要的包含，把它**放在最前面**包含能尽早暴露错误，这是可取的。
- **头文件最佳实践清单**：始终加 header guard；不要在头文件里定义变量/函数（目前）；头文件名与对应源文件匹配；每个头文件职责单一且尽量独立；注意自己真正需要哪些头文件；一个头文件应能自给自足、被单独包含时也能编译；只包含所需内容；不要包含 `.cpp`；把"用法"文档放在头文件里、"实现"文档放在源文件里。

## 最佳实践

- 头文件除非项目已有其它约定，否则优先用 `.h` 后缀。
- 配对的头文件与代码文件应使用相同的基名（如 `add.h` 配 `add.cpp`）。
- 不要在头文件里放函数和变量定义（目前）。
- 源文件应 `#include` 与它配对的头文件（若存在）。
- 避免 `#include` `.cpp` 文件。
- 每个文件应显式 `#include` 它编译所需的全部头文件，不要依赖其它头文件传递进来的包含。
- 包含顺序：先配对头文件，再其它项目头文件，再第三方库头文件，最后标准库头文件；每组内按字母排序。
- 标准库头文件用不带 `.h` 的新式写法；用户自定义头文件仍用 `.h`。
- **Rule**：用双引号包含你写的、或位于当前目录的头文件；用尖括号包含编译器、操作系统或第三方库的头文件。
- **Warning**：C 兼容头（`<cxxx>`）可能额外把名字放进全局命名空间、旧式 `<xxx.h>` 可能额外放进 `std`，这些名字应避免使用，因为其它实现未必把它们声明在那里。
