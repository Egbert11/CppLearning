# 12.8 Null pointers

> 原文：https://www.learncpp.com/cpp-tutorial/null-pointers/

## 核心概念

- **指针回顾**：指针是保存另一个对象地址的对象；可用解引用运算符 `*` 访问那个地址。
- **空值（null value）**：一个表示"没有值"的特殊值。持有它的指针"什么都不指"，称为**空指针（null pointer）**。
- **创建空指针**：最简单的办法是值初始化，如 `int* ptr {};`。当不用有效对象地址初始化指针时，就应这样做。
- **指针可重定向**：因为赋值可改变指针的目标，空指针稍后可被指向有效对象。
- **nullptr 关键字**：正如 `true`/`false` 是布尔字面量，`nullptr` 是空指针字面量，可用于初始化、赋值，或把空指针传给函数。
- **解引用 null 是未定义行为**：与解引用悬垂指针、野指针一样，会导致 UB，多数情况下使程序崩溃。概念上：若指针什么都不指，就没有值可访问。
- **这是常见 bug**：误解引用空指针或悬垂指针是最常见的 C++ 错误之一，也是现实崩溃的主要来源。
- **显式空检查**：可用条件语句把指针与 `nullptr` 比较以检测是否相等。
- **隐式布尔转换**：空指针转为布尔 `false`，非空指针转为 `true`。因此 `if (ptr)` 就足够，不必显式比较。
- **条件判断的局限**：它只能区分"空"与"非空"，无法方便地判断某个非空指针是否有效或悬垂。
- **避免悬垂指针**：解引用前先做非空检查；并确保任何不指向有效对象的指针都被设为 `nullptr`，这样就能假定非空指针有效。
- **不会自动置空**：对象被销毁时，指向它的指针仍悬垂，且**不会**被自动置空；程序员必须自己发现并把这些指针设为 `nullptr`。
- **旧式字面量 0**：在指针语境中，字面量 `0` 被特别定义为空值，这是唯一允许把整型字面量赋给指针的情形。
- **关于地址 0 的旁注**：现代架构通常用地址 `0` 表示 null，但标准不保证如此；字面量 `0` 会被翻译成该架构所用的地址。
- **旧式宏 NULL**：来自 `<cstddef>` 的预处理器宏，继承自 C，也表示空指针。现代 C++ 中 `0` 与 `NULL` 都应避免。
- **优先用引用而非指针**：两者都能间接访问对象，但指针还能重定向、还能为空——两者都更危险（空解引用、更易悬垂）。引用不能为空、不能重设，所以除非需要指针的额外能力，优先用引用。

## 最佳实践

- **Best practice**：**如果不用有效对象的地址初始化指针，就把它值初始化为空指针。**
- **Best practice**：**需要空指针字面量用于初始化、赋值或把空指针传给函数时，使用 `nullptr`。**
- **Best practice**：**指针要么持有有效对象的地址，要么设为 nullptr。这样只需检测指针是否为空，并可假定任何非空指针都有效。**
- **Best practice**：**除非需要指针提供的额外能力，否则优先用引用而非指针。**
- **Warning**：**使用指针时要格外小心，别解引用空指针或悬垂指针，否则会导致未定义行为（多半是程序崩溃）。**
- **Warning**：**条件语句只能区分空指针与非空指针；没有方便的办法判断一个非空指针是指向有效对象还是悬垂（指向无效对象）。**
- **Warning**：**对象销毁时，指向它的指针会保持悬垂（不会被自动设为 `nullptr`）。发现这些情况并把它们设为 `nullptr` 是你的责任。**
- **As an aside**：现代架构中地址 `0` 通常表示 null，但标准不保证；某些架构用别的值。字面量 `0` 会被翻译成该架构所用的地址。
