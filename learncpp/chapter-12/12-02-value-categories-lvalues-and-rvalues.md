# 12.2 Value categories (lvalues and rvalues)

> 原文：https://www.learncpp.com/cpp-tutorial/value-categories-lvalues-and-rvalues/

## 核心概念

- **表达式（expression）**：由字面量、变量、运算符、函数调用组合而成，求值后产生单个值的一段代码。
- **副作用（side effect）**：表达式求值过程中造成的、在表达式结束后仍然持续的改变（如自增变量）。
- **表达式的两个属性**：C++ 中每个表达式都有**类型（type）**和**值类别（value category）**。
- **表达式的类型**：等于其产生的值/对象/函数的类型，编译期由编译器确定。
- **类型检查**：类型让编译器判断表达式在特定上下文中是否合法（如把字符串字面量传给期望 `int` 的地方会失败）。
- **编译期 vs 运行期**：类型必须在编译期可确定，但值可能在编译期已知（constexpr）或只能运行期求得。
- **值类别**：表示表达式"求值为一个值、一个函数，还是某个对象"，决定它能否出现在赋值号某一边。
- **C++11 之前只有两类**：`lvalue` 与 `rvalue`。
- **C++11 新增**：`glvalue`、`prvalue`、`xvalue`，用于支持移动语义。
- **左值（lvalue）**：全称 "left value" 或 "locator value"，求值为一个**可识别的对象、函数或位域**。
- **身份（identity）**：有身份的对象可与同类对象区分（通常靠地址），能通过标识符、引用、指针访问，且通常比表达式活得更久。
- **可修改左值 / 不可修改左值**：前者的值可被改变；后者（const 或 constexpr）不能。
- **右值（rvalue）**：非左值的一切；求值为一个值，不可识别，必须立即使用，只在其所在表达式内存活。例如字面量（C 风格字符串字面量除外）、函数/运算符的按值返回结果。
- **运算符与操作数**：除非另有说明，运算符期望其操作数是右值（如二元 `operator+`）。
- **赋值规则**：左操作数必须是**可修改左值**，右操作数必须是**右值**——这就是 `5 = x` 非法的原因。
- **左值到右值转换（lvalue-to-rvalue conversion）**：需要右值却给了左值时，左值被隐式转换——对其求值以产生它的值。
- **一条语句中的双重身份**：`x = x + 1` 中左侧 `x` 是左值，右侧 `x` 经历左值到右值转换。
- **经验法则**：左值表达式求值为函数或可识别对象（含变量），它们比表达式活得久；右值表达式求值为值、字面量或临时对象，不持续存在。
- **C++11 细分**：本文讨论的"右值"是 `prvalue` 与 `xvalue` 的合称。
- **检测手法**：在 `T&`（左值引用）与 `T&&`（右值引用）上重载函数，可让编译器报告实参的类别。
- **前缀 vs 后缀**：`++x` 求值为左值；`x++` 求值为右值。
- **高级旁注**：C 风格字符串字面量是左值，因为 C 风格数组会退化为指针，而退化需要左值；C++ 为向后兼容沿用了这一行为。

## 最佳实践

本节无 Best practice / Rule / Warning 条目。相关 callout：

- **Key insight**：**左值表达式求值为一个可识别的对象；右值表达式求值为一个值。**
- **Key insight**：**左值会隐式转换为右值**，因此可出现在任何需要右值的地方；但右值不会隐式转换为左值。
- **Tip（经验法则）**：左值求值为函数或持续存在的可识别对象；右值求值为字面量等值或不持续存在的临时对象。
- **Tip**：更完整的类别列表见 cppreference；C++11 中右值拆成 `prvalue` 与 `xvalue`，本文的"右值"涵盖两者。
- **For advanced readers**：C 风格字符串字面量是左值，因为 C 风格数组退化为指针需要带地址的左值；C++ 为向后兼容保留此行为。
- **Author's note**：本节有意采用 C++11 之前的两类别视角，作为"对值类别更温和的入门"，眼下够用；移动语义与三个新类别留到后面章节。
