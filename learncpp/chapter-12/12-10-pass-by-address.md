# 12.10 Pass by address

> 原文：https://www.learncpp.com/cpp-tutorial/pass-by-address/

## 核心概念

- **三种传参方式回顾**：按值（形参是副本，改动不影响原对象）、按引用（形参绑定到原对象、不复制，非 const 引用可修改原对象）、以及本节新讲的按地址。
- **按地址传递的定义**：调用方传入对象的**地址**而不是对象本身，用指针承载。该指针被复制进函数的指针形参，形参随后持有对象的地址。
- **访问对象**：函数解引用其指针形参，从而访问被传入地址的那个对象。
- **形参声明**：把形参声明为指针；若只需读取，应声明为“指向 const 的指针”，如 `const std::string* ptr`。
- **调用方式**：不能传对象本身，要传它的地址，最方便的是用取地址运算符：`printByAddress(&str);`。
- **传入已有指针**：如果某个指针变量已经保存了该地址，也可以直接传这个指针，而不必用 `&`。
- **命名**：用 `operator&` 传地址意味着变量“按地址传递”。把一个持有对象地址的指针变量传给同类型形参时，是对象按地址传递、指针按值传递。
- **不复制被指对象**：只复制指针本身（通常 4 或 8 字节），因此按地址与按引用一样快、避免复制实参；复制 `std::string` 的代价很高。
- **可以修改实参**：函数拿到的是真实对象的地址，所以“指向非 const 的指针”形参允许函数修改实参，改动在返回后依然存在。
- **防止修改**：把形参改成“指向 const 的指针”（`const int* ptr`），函数若试图赋值就会编译报错。
- **关于 const 指针形参的判断**：让指针形参本身成为 const 价值不大（对调用方无影响，主要只是表明指针不会被改）。而“指向 const”与“指向非 const”的区分很重要，因为调用方需要知道实参是否可能被修改。
- **可读性论点**：只用非 const 指针形参时，每个 `const` 都有意义；加入 const 指针形参后，重要的 `const` 更难被发现，还可能掩盖“指向非 const 的指针”形参（以两个 `foo()` 声明为例）。
- **空指针检查**：把空指针按地址传入后再解引用是未定义行为（示例先打印 `5`，随后多半崩溃）。解引用前需要小心。
- **处理空指针：条件判断**：解引用前用 `if (ptr)` 判断可以工作，但在复杂函数中可能造成重复检查或很深的嵌套。
- **处理空指针：前置条件/提前返回**：通常更好的是把“是否为空”当作前置条件、对否定情形立即处理（`if (!ptr) return;`），此后函数其余部分即可假定指针有效。
- **处理空指针：assert**：如果空指针本就不该被传入，用 `assert(ptr)` 把它记录为前置条件（生产环境可选地配合错误处理）。
- **优先用（const）引用传递**：示例函数在空指针时实际上中止了；既然这样，为什么还允许传空？按引用传递能获得同样的好处，又没有空指针解引用的风险。
- **优势：可接受右值**：按地址传递的对象必须有地址，因此只接受左值；按 const 引用传递则左右值都能接受。
- **优势：语法**：按引用传递的语法自然，而按地址的代码“到处都是 & 和 *”。
- **现代建议**：多数过去用按地址做的事，如今有更好的做法；本节引用格言“**Pass by reference when you can, pass by address when you must**”（能按引用就按引用，必须时才按地址）。

## 最佳实践

- **Best practice**：优先使用“指向 const 的函数形参”，除非函数需要修改传入的对象。
- **Best practice**：除非有特别的理由，不要把函数形参做成 const 指针。
- **Best practice**：除非有特别的理由要使用按地址传递，否则优先按引用传递。
- **格言**：Pass by reference when you can, pass by address when you must.
