# 12.3 Lvalue references

> 原文：https://www.learncpp.com/cpp-tutorial/lvalue-references/

## 核心概念

- **引用（reference）**：一个作为既有对象别名的名字。对引用的任何操作都作用于被引用对象，因此可用引用读取或修改它。
- **引用本质**：**引用与被引用对象本质上是同一个东西**。
- **对函数的引用**：也可以建立对函数的引用，只是不常用。
- **现代 C++ 的两种引用**：左值引用与右值引用。本章讲左值引用；右值引用在移动语义一章（第 22 章）。
- **左值引用（lvalue reference）**：作为既有左值（如变量）的别名。对象的类型限制它能存什么值，引用的类型则限制它能引用什么类型的对象。
- **语法标记**：左值引用类型用类型说明符里的单个 `&` 标识。
- **引用类型 vs 被引用类型**：指定引用的类型（如 `int&`）称**引用类型**；能被引用的底层类型（如 `int`）称**被引用类型**。
- **命名约定**：左值引用分两种——
  - 非 const 左值引用，可称 "左值引用"、"对非 const 的左值引用" 或 "非 const 左值引用"（因为没用 `const`）；
  - 对 const 的左值引用，称 "const 左值引用" 或 "对 const 的左值引用"。
  本节聚焦非 const 左值引用，const 左值引用在 12.4。
- **左值引用变量**：作为对某左值（通常是另一个变量）的引用的变量，通过定义带引用类型的变量创建。
- **& 的位置**：`int& ref` 还是 `int &ref` 对编译器没有区别，纯属风格；现代程序员把 `&` 贴在类型上，以表明引用是类型信息而非标识符的一部分。
- **通过非 const 左值引用修改**：非 const 引用可以修改被引用对象的值。
- **引用初始化**：如同常量，所有引用都必须初始化，这种初始化形式叫**引用初始化（reference initialization）**。未初始化的引用是错误。
- **绑定术语**：用对象（或函数）初始化引用称为把它**绑定（bind）**到该对象，过程叫**引用绑定（reference binding）**，被引用对象/函数叫**被引用对象（referent）**。
- **绑定限制规则**：非 const 左值引用只能绑定到**可修改左值**。
- **为何如此**：若非 const 左值引用能绑定不可修改（const）左值或右值，就能通过引用改掉这些值，违背其 const 性质。
- **void 引用**：对 `void` 的左值引用不被允许。
- **绑定不发生转换**：即使引用类型（`int&`）与被绑定对象类型（`int`）不完全一致，也不会做转换；类型差异作为引用初始化的一部分处理。
- **类型匹配规则**：通常引用只绑定到与其被引用类型匹配的对象（继承场景有例外）。类型不符时，编译器会尝试隐式转换，再绑定到转换结果。
- **为何类型不符会报错**：转换结果是右值，而非 const 左值引用不能绑定右值，所以会编译失败。
- **不能重绑定（no reseating）**：引用一旦初始化就不能**重绑定（reseat）**去引用别的对象。给引用赋另一个变量能编译运行，但实际是给被引用对象赋值。
- **作用域与生存期**：引用变量与普通变量遵循同样的作用域和生存期规则。
- **生存期彼此独立**：除下一节的例外外，引用的生存期与被引用对象的生存期相互独立，任一可先销毁。引用先销毁时，被引用对象不受影响。
- **悬垂引用（dangling reference）**：若被引用对象先于引用被销毁，引用指向已不存在的对象，这就是悬垂引用，访问它导致未定义行为。这类情况容易避免，实例见 12.12。
- **引用不是对象**：引用不是对象，不被要求存在或占用存储；编译器若有可能就把它优化掉，用被引用对象替换引用的每次出现，但有时仍需存储。所以"引用变量"是轻微用词不当——变量是有名字的对象，而引用不是对象。
- **不是对象的后果**：引用不能用在需要对象的地方（例如"引用的引用"不成立，因为左值引用必须引用可识别对象）。若需要一个"可重绑定、且是对象"的引用，`std::reference_wrapper`（见 23.3）提供解决方案。
- **旁注——引用的引用**：若用 `ref1` 初始化 `ref2`，有人会以为 `ref2` 是"引用的引用"，其实不是：`ref1` 求值为 `var`，所以 `ref2` 只是绑定到 `var` 的普通左值引用。"引用的引用"需要 `int&&` 语法，但 C++ 不支持，该语法在 C++11 被改用作右值引用。

## 最佳实践

- **Best practice**：**定义引用时，把 & 紧贴类型放（而不是放在引用变量名旁边）。**
- **Key insight**：引用与被引用对象本质上是同一个东西。
- **For advanced readers**：对指针熟悉者而言，这里的 `&` 不是"取地址"，而是"对……的左值引用"。
- **Key insight（绑定限制）**：允许非 const 左值引用绑定 const 左值或右值，就会通过引用改掉这些值，从而破坏其 const 性质。
- **Key insight（类型不符）**：转换产生右值，而非 const 左值引用不能绑定右值，因此把非 const 左值引用绑定到类型不符的对象会编译失败。
- **Related content**：值类别复习见 12.2；右值引用见移动语义章（第 22 章）。
- **Author's note**：若此刻觉得引用没用，别担心——引用被大量使用，主要理由会在 12.5 和 12.6 讲。
