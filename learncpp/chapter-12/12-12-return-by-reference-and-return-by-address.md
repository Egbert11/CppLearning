# 12.12 Return by reference and return by address

> 原文：https://www.learncpp.com/cpp-tutorial/return-by-reference-and-return-by-address/

## 核心概念

- **按值返回会复制**：正像按值传递把实参复制进形参，按值返回把结果复制回调用方。对基本类型代价小，对 `std::string` 这类类类型可能很贵。
- **按引用返回避免复制**：函数返回绑定到某个已存在对象的引用，而不是复制。把函数返回类型声明为引用即可。
- **被引用的对象必须比函数活得久**：如果对象在函数结束时被销毁，返回的引用就会悬垂，使用它是未定义行为。
- **静态存储期对象是安全的**：`static` 局部或其它长寿对象在函数返回后依然存在，因此返回对它的引用是合法的。
- **自动存储期的局部变量不安全**：返回对非 static 局部（或临时值）的引用，函数一返回就产生悬垂引用。编译器常能对简单情形给出警告或错误，但可能漏掉复杂情形。
- **警告**：按引用返回的对象必须活得比返回该引用的函数更久，否则会产生悬垂引用。
- **生命周期延长不能跨函数边界**：按引用返回一个临时值，会在调用方得到一个绑定到“已销毁对象”的临时引用；之后的绑定不会带来延长。
- **直接绑定 vs 间接绑定**：把 const 引用直接绑定到临时值（`const int& ref1 { 5 };`）会延长临时的生命周期；而引用经由函数“绕一圈”则不会，得到悬垂引用。
- **不要按引用返回非 const 的 static 局部**：这样多个调用方/多个引用会共享同一个可变对象，后一次调用会改变先前引用“看到”的值；也没有标准办法重置该状态。
- **返回引用的复制**：用返回的引用去初始化或赋值一个非引用变量时，会像按值返回那样复制值。
- **复制前就已悬垂仍是 UB**：如果返回的引用已经悬垂，那么复制是自一个悬垂引用进行的——未定义行为。
- **按引用返回引用形参是安全的**：调用方的实参必然存在于调用方作用域，在被调方返回后仍存活。
- **按 const 引用传入的右值，可以按 const 引用返回**：右值要到创建它的那条完整表达式结束时才销毁，因此在该表达式内返回的引用仍然有效。
- **非 const 引用让调用方可修改**：函数返回非 const 引用时，调用方可以通过它赋值（例如把 `max(a, b)` 的结果当左值用）。
- **按地址返回**：与按引用返回类似，只是返回指针，且对象同样必须活得比函数久。优点是可以用 `nullptr` 表示“没有对象”；缺点是调用方必须记得解引用前先做空检查。
- **相关**：`std::optional`（12.15 节）适合“返回没有对象或一个值”；5.9 节讲如何在 `std::string_view` 与 `const std::string&` 之间选择。

## 最佳实践

- **Warning（对象生命周期）**：按引用返回的对象必须活得比返回该引用的函数更久，否则会产生悬垂引用。**永远不要**按引用返回（非 static 的）局部变量或临时值。
- **Warning（生命周期延长）**：引用生命周期延长不能跨越函数边界。
- **Best practice（static）**：避免按引用返回非 const 的局部 static 变量。（返回对 **const** 局部 static 的 const 引用偶尔用于创建代价高昂的值，但很少见；返回对 const 全局变量的 const 引用是有时可以接受的封装手法。）
- **Best practice（地址 vs 引用）**：优先按引用返回，除非需要“返回没有对象”（用 `nullptr`）这一能力。
