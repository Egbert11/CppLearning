# 12.13 In and out parameters

> 原文：https://www.learncpp.com/cpp-tutorial/in-and-out-parameters/

## 核心概念

- **两种通信机制**：函数与调用方通过参数和返回值交换数据；实参可以按值、按引用或按地址传入。
- **in 参数**：唯一职责是接收调用方输入的形参。这类形参通常按值或按 const 引用传递。
- **out 参数**：按非 const 引用（或指向非 const 的指针）传递的形参，使函数能修改调用方的对象。当返回值不足以送回数据时，它让函数把数据送回。
- **命名与位置约定**：out 参数常加 “out” 后缀，以表明其传入值无关紧要、将被覆盖；通常放在最右侧的位置。
- **工作机制**：调用方的局部变量被按引用绑定，函数写的是真实对象而非副本，改动在调用结束后依然存在。若按值传递，改动会被丢弃。
- **缺点：调用语法别扭**：调用方必须先创建并初始化可赋值的（非 const）对象再传入；结果不能当临时值使用，也不能放在单个表达式里。
- **缺点：修改被隐藏**：像 `getSinCos(degrees, sin, cos)` 这样的调用，看不出哪些是输入、哪些会被覆盖，不像从返回值赋值那样一目了然。
- **按地址是部分补救**：调用处必须写 `&i`，让修改更明显，但并不保险——直接传一个指针变量又会把它隐藏起来。
- **按地址的代价**：调用方可能误以为可以传 `nullptr`，函数也不得不加空检查，往往比按引用传递带来更多麻烦。
- **in-out 参数**：少数情况下函数会先读取形参的既有值，再覆盖它。这类参数的行为与 out 参数相同，缺点也一样。
- **何时用非 const 引用才合理**：两种主要情形——(a) 参数是 in-out 参数（对象本来就要传进来）；(b) 函数否则要按值返回对象且复制**极其**昂贵，尤其在性能关键代码中。
- **默认原则**：如果只是为了避免复制才用引用，几乎总是应选 const 引用。

## 最佳实践

- **Best practice**：避免 out 参数（除非在极少数没有更好选择的情况下）。
- **Best practice**：对非可选的 out 参数，优先使用按引用传递。
- **Author's note**：以下示例中的 `Foo` 代表你选择的某个类型，例如 `std::string`。
- **For advanced readers**：昂贵复制的例外情形通常是填充大型 C 风格数组或 `std::array`（其元素类型复制代价高）；这类对象极少昂贵到需要用非常规的返回方式。
- **As an aside**：原链接了一则 StackOverflow 讨论，解释为何非 const 左值引用不能绑定到右值或临时对象（隐式转换与 out 参数相互作用会产生坏结果）。
